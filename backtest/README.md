# 決算・業績修正イベント バックテスト

決算・業績予想修正の開示 → 翌営業日の始値で信用買い → N営業日後の始値で返済。
このエッジが取引コストを超えるかを検証する。**ロングのみ。空売りしない。**

設計と根拠は [DESIGN.md](DESIGN.md)。

---

## 前提

- データは J-Quants API V2 の **Light プラン**（月1,650円・過去5年）
- V2 は **APIキー方式**。ダッシュボードで発行して `.env` に置く
- 実行は **ローカル PC の Docker コンテナ内**
- J-Quants のデータは再配布できないため `data/` は git 管理外

---

## 手順

### 1. APIキーを置く

```bash
cp .env.example .env
# .env を開いて JQUANTS_API_KEY を書く
```

### 2. イメージを作る

```bash
docker compose build
```

### 3. probe（最初に必ずこれ）

実データの列名と `config.yaml` の対応表を突き合わせる。
V2 の列名は V1 と別物で、公式ドキュメントだけでは確定しない項目があるため、
**推測のまま本番を回さない**。

```bash
docker compose run --rm erb probe
```

`results/probe.md` に出る。食い違いが報告されたら `config.yaml` の
`columns:` を実データに合わせて直す。特に次を確認する。

```
[ ] DocType の実際の値（業績予想修正 / 配当予想修正 / 決算短信の区別）
[ ] MktCap に値が入っているか（空なら発行済株式数x終値で代替される）
[ ] 上場廃止銘柄の過去データが残るか  ← 残らなければ生存バイアスが不可避
```

### 4. データを置く

`data/` に以下を置く（CSV または Parquet）。

```
data/summary.csv     財務サマリー（fins summary）
data/daily.csv       株価日足（eq daily）
data/calendar.csv    取引カレンダー（mkt calendar）
data/master.csv      銘柄マスタ（任意。信用区分フィルタに使う）
data/topix.csv       TOPIX 日足（任意。超過リターンの算出に使う。無いと判定できない）
```

公式 CLI の一括ダウンロードを使う場合:

```bash
jquants login
jquants bulk get --endpoint /equities/bars/daily --date 2025-06 --download
```

### 5. 修正率の分布を見る

閾値を決める前に必ず見る。東証の適時開示基準では営業利益の修正は原則
**±30%** を超えないと開示義務が生じないため、5%/10%/20% では
母集団がほぼ同じになりうる。

```bash
docker compose run --rm erb histogram
```

`results/histogram.md` を見て `config.yaml` の
`grid.revision_thresholds` と `judgement.primary_cell.revision_threshold`
を決める。**決めたら以後動かさない。**

### 6. グリッドを回す

```bash
docker compose run --rm erb run
```

`results/results.md` と `results/grid.csv` に出る。

## 結果の読み方

判定は**主条件（事前登録した1セル）**で行う。グリッドの中から一番良い
組み合わせを選ぶ行為そのものが過剰最適化なので、他のセルは頑健性の確認にのみ使う。

```
純エッジ = TOPIX超過の粗エッジ − 往復スリッページ − 買方金利

  < 0.05%        打ち切り
  0.05 〜 0.35%  ペーパートレード3か月
  > 0.35%        少額実弾
```

粗エッジ単独では判定できない。損益分岐が N とスリッページで変わるため。

```
N     暦日   金利(建玉%)   損益分岐（滑り0.4%）
1     1.4     0.011%       0.411%
3     4.2     0.032%       0.432%
5     7.0     0.054%       0.454%
10   14.0     0.107%       0.507%
```

採用は次を**すべて**満たしたときだけ。

- 主条件の純エッジが基準を超える
- 対照群を除く全セルで純エッジがプラス
- クラスター・ブートストラップの信頼区間の下限が 0 を上回る
- 件数が必要サンプル数に達している（`verdict` が「判定可」）
- 前半 / 後半のどちらもプラス
- 対照群（フィルタなし・下方修正）で符号が期待どおり

### 数字を鵜呑みにしてはいけない点

- **単純な t 値は当てにならない。** 決算発表は 2月/5月/8月/11月 に集中し、
  同じ週のトレードは市場全体の動きを共有する。クラスター・ブートストラップの
  信頼区間で見ること。
- **増担保規制は再現できない。** 好材料で急騰した小型株はまさに規制対象になり、
  実際には建玉が組めないことがある。ペーパートレードで実測する。
- **上場廃止銘柄がデータに残っているか。** 残っていなければ結果は押し上げられている。
- **`margin_call_days` が 0 でない元金は使えない。** 期待値がプラスでも破産する。

```bash
docker compose run --rm --entrypoint python erb -m pytest -q
```
