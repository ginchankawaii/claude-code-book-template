# 2晩目システム 運用規程 v0.2

作成 2026-09-03 / 改訂 2026-09-07 / 状態 **Stage 0 不通過。終了（Stage 1 に進まない）→ §12**

このシステムは、既存の個別株の取引ルール（運用規程・トレード日誌）とは**別の資金・別の帳簿・別のルール**で動かす。
両者を混ぜない。既存ルールの裁量はこのシステムには一切入れない。

---

## 0. 一言でいうと

```
引け後に業績予想の開示があった銘柄を、翌営業日(E+1)の引けでニュースの方向に建て、
翌々営業日(E+2)の寄付で返す。1泊。ロングもショートもやる。裁量はゼロ。
```

なぜこの形か。5年の日足で、引け後開示のあとに次の構造が見えた（フェーズ1の分解）。

```
引け後開示・売買代金F・常習除外    E+1 の日中（始値→引け）   E+1 引け → E+2 始値
  上方 ≥ +18%   1,156件              −0.153%                   +0.354%
  上方 ≥ +36%     530件              −0.390%                   +0.557%
  下方 ≤ −30%     765件              +0.183%                   −0.567%
  フィルタなし 22,989件              +0.007%                   +0.054%   ← 基準線

  翌朝の寄付で大きく動く（取れない）→ 翌日の日中は逆に戻す → その夜、ニュース方向へもう一度動く
  修正率に対して単調で、下方修正で鏡像になり、基準線はほぼ0。
```

**ただしこれは分解表（70セル）から事後に見つけた構造で、事前登録した仮説ではない。**
だから Stage 0 で執行可能な日だけに絞って再集計し、Stage 1 で未使用の5年で追試するまで、
このシステムは「仮説」でしかない。この文書の数字を根拠に実弾を入れてはならない。

## 1. ギャンブルにしないための原則

```
1. 期待値を先に証明する      Stage 0〜2 の門を全部通るまで実弾ゼロ
2. サイズで守る              停止注文は夜間に効かない。1泊の損失はサイズでしか制御できない
3. レバレッジを使わない      信用取引は「売りができる」ためだけ。グロス建玉 ≤ 専用資金 × 1.0
4. 両方向を持つ              ロングとショートで市場全体の動きを相殺する
5. 裁量ゼロ                  建てる／建てない／サイズ／出口は全部ルールで決まる。迷ったら見送り
6. 停止条件を先に決める      損失の上限・連敗・実測コストの上限を数字で固定。踏んだら止める
7. 同じデータで探し直さない  閾値・フィルタ・時刻を結果を見て変えない。変えるなら新しい仮説として登録
```

## 2. シグナル（固定。変更禁止）

```
対象        J-Quants 財務サマリー（fins summary）の開示のうち
              DocType = EarnForecastRevision（業績予想修正）
                      = 1Q/2Q/3Q FinancialStatements（決算短信内の予想変更）
            引け後開示のみ: DiscTime ≥ 大引け（〜2024-11-01 は 15:00、以降 15:30）または休業日
            REIT を除く。配当予想修正のみを除く

修正率      当期営業利益の会社予想 FOP を、直前に開示済みの予想で割って −1
            本決算での新年度初回予想は「修正」ではないので対象外
            分母が 0 以下（赤字予想）は対象外

ロング      修正率 ≥ +18%（主）。+36% は副セルとして併記
ショート    修正率 ≤ −30%（主）

共通フィルタ（フェーズ1と同一。動かさない）
  ・常習除外: 過去3年の予想変更が4回以上の銘柄を除く
  ・売買代金: 1本の建玉 ≤ 直近20営業日平均売買代金 × 1%
  ・除外銘柄: 8053 / 9719 / 7518（既存ルールの制約を引き継ぐ）
  ・単元: 生の株価 × 100株 ≤ 1本の建玉

執行可能フィルタ（Stage 0 で主セルに適用）
  ・ロング: E+1 の引けがストップ高張り付き（UL）なら見送り（買えない）
  ・ショート: E+1 の引けがストップ安張り付き（LL）なら見送り（売れない）
  ・ショート: 貸借銘柄のみ（銘柄マスタ Mrgn=2）。一般信用売りの在庫があれば貸借外でも可
```

## 3. 執行（固定手順）

```
E 日  15:30 以降   引け後開示を抽出し、修正率を計算し、候補を確定する（候補表を記録）
E+1   日中         候補の 値幅制限張り付き／貸借／在庫 を確認。張り付きは見送り
E+1   15:20 まで   引け成行を発注
                     ロング   制度信用買い（1泊。金利 年2.80% × 2/365 ≈ 0.015%）
                     ショート 一般信用売り（無期限）を優先（逆日歩なし・貸株料 年1.10%）
                              在庫が無ければ制度信用売り（貸株料 年1.15%・逆日歩あり）
                              どちらも無理なら見送り
                   注文は 50単元（5,000株）以下に収める → 空売り価格規制の適用除外
E+2   寄付         寄成で返済。例外なし。持ち越し禁止
毎日               全注文・約定値・日足の C/O との差・見送り理由 を記録
```

指値・時間指定・分割・ナンピン・利確の前倒し・損切りの前倒し、いずれも禁止。
「引け成行で建て、寄成で返す」以外の執行は、このシステムの取引ではない。

## 4. 資金・サイズ・レバレッジ

```
専用資金（バケット）   このシステム専用。他の資金から補填しない。利益も外に出さない
                       Stage 3 の初期値: 50万〜100万（§9 Q1）
1本の建玉             バケット ÷ 3 以下、かつ Stage 0 で検証したサイズ（30万）以下
同時保有              3本まで
グロス建玉            バケット × 1.0 以下。信用の3.3倍は使わない
ネット建玉            制限しない（ロング3本の日もショート3本の日もある。両建ては結果として）

1泊のギャップの目安    σ ≈ 3〜4%、3σ ≈ 10〜12%
                       30万の建玉で 3σ = 3〜4万 = バケット100万の 3〜4%
                       バケット50万なら1本は15万に落とす（Stage 0 を15万で再実行してから）
```

## 5. 停止条件（数字。踏んだら止める。再開は Stage 1 から）

```
日次    その日の実現＋含み損 ≥ バケットの 3%      → 当日以降の新規建て停止（返済は予定どおり）
累積    バケットのピークからの下落 ≥ 10%          → 全停止。Stage 1（OOS）からやり直し
統計    直近60本の 純リターン平均 < 0             → 全停止
コスト  直近30約定の実測往復コスト > 0.40%        → 全停止（前提が崩れた）
執行    直近20営業日で見送り率 > 50%              → 停止して原因を記録（在庫・張り付き・規制）
乖離    実現損益 と「建てた本の平均×本数×建玉」の差 > バケットの 5%
                                                  → 記録ミスかバグ。止めて突き合わせ
```

## 6. 執行制約（制度面。裏取り済み）

```
空売り価格規制    前日比 −10% で発動。ただし 50単元以下の注文は適用除外 → 個人サイズは規制外
貸株料            制度信用売り 年1.15%（SBI）、一般信用売り無期限 年1.10%。1泊なら 0.006%

金利（買い）      制度信用 年2.80%。1泊 0.015%
手数料            SBI/楽天は信用0円（ゼロ革命）
```

滑り 0 にしても long_up18 は超過 −0.155%、short_dn30 は超過 +0.017% − 貸株料 0.008% ≈ 0。滑りの問題ではない。

### 超過リターンはどこに載っていたか

```
               全日              執行できた日        執行できない日（差分）
long_up18      1,139件 +0.345%   985件 −0.155%     154件（13.5%） 1件あたり +3.54%  全日の超過合計の 139%
long_up36        544件 +0.548%   437件 −0.252%     107件（19.7%） 1件あたり +3.81%  同 137%
short_dn30       882件 +0.504%   583件 +0.017%     299件（33.9%） 1件あたり +1.45%  同  98%
```

§0 で見えた「E+1 引け → E+2 寄付の +0.35〜+0.56%」は、ロングでは **E+1 にストップ高で張り付いた日**（買えない日）に、
ショートでは **ストップ安張り付き または 貸借外**（売れない日）に、全部載っていた。
執行できる日の粗リターンは中央値 0・平均 ≈ 0 で、滑りを払えば確実にマイナス。
これは §6「値幅制限: 張り付きの日は執行不能」で事前に懸念していたとおりの結果。

両建てポートフォリオ（long_up18 + short_dn30、執行できた日のみ）は 6 ケース全部で破産（期待値がマイナスの帰結。追加情報ではない）。

### 判定

```
Stage 0   不通過（3セルとも、通過条件5つのうち4つを落とす）
Stage 1   進まない。3,300円は払わない
この仮説   終了。§11 により閾値・時刻・フィルタは変えない
実弾       ゼロのまま。バケットは作らない
```

### 残っている診断（費用 0・判定は変えない）

short_dn30 の執行不能 299 件が「ストップ安張り付き」と「貸借外」のどちらに載っているかは、今回の集計では分けていない。
`erb night2` を再実行すると §3b に内訳が出る（2026-09-07 のコード変更）。

もう一つ。J-Quants の UL/LL フラグが「その日にストップ高（安）に触れた」を意味するのか「引けで張り付いた」を意味するのかは、
この環境からは仕様書を確認できていない（未確認）。主セルの執行可能フィルタは UL/LL をそのまま使っているので、
「日中に触れたが引けは下だった日（本来は買えた日）」まで除いている可能性がある。
再実行後の §3b は、UL=1 の日を「終値 == 高値（引けで張り付き）」と「触れただけ」に分けて出す。
ただし、除いた 154 件の平均 +3.54% を丸ごと執行可能側に足し戻しても long_up18 の超過は +0.11%、純は −0.29% で、
どちらの意味であっても Stage 0 の判定は変わらない。
貸借外に載っている場合、「一般信用売りの在庫があれば売れる」が論点になるが、
一般信用の在庫は J-Quants に無く、事後のデータでは検証できない。やるなら §11 のとおり別仮説として登録し、
在庫の有無を Stage 2 相当の記録（毎日、候補銘柄の在庫を目視）で先に数えてからになる。
この診断の結果によって Stage 0 の判定が変わることはない。
