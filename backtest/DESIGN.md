## 0. 仮説と判定

```
イベント   : 決算・業績予想修正の開示
エントリー : 開示日の翌取引日 t0 の始値
イグジット : t0 から取引カレンダー上 N 営業日後 tN の始値
ロングのみ。空売りしない。
```

### 判定指標（v0.1 から変更）

粗エッジは N とスリッページに依存しないため、単独では採否を決められない。
コストを引いた **純エッジ** で判定する。

```
純エッジ = TOPIX超過の粗エッジ − 往復スリッページ − 買方金利

  < 0.05%       → 打ち切り
  0.05 〜 0.35% → ペーパートレード 3か月
  > 0.35%       → 少額実弾
```

これは元の基準「粗エッジ 0.5% / 0.8%」から、主条件(N=5・滑り0.4%)の損益分岐
0.454% を引いた等価変換であり、基準を厳しくしたものではない。
粗エッジ・絶対リターンも全セルで併記する。

### 損益分岐（買方金利 年2.80%、制度信用の実勢）

```
N     暦日   金利(建玉%)   滑り0.3%   滑り0.4%   滑り0.5%
1     1.4     0.011%      0.311%    0.411%    0.511%
3     4.2     0.032%      0.332%    0.432%    0.532%
5     7.0     0.054%      0.354%    0.454%    0.554%
10   14.0     0.107%      0.407%    0.507%    0.607%
```

N=10・滑り0.5% では粗エッジ 0.6% でも赤字。単一の閾値で判定してはならない。

### TOPIX超過で判定する理由

年率10%上昇する市場で7暦日持つだけで 0.19% が自動的に乗る。
粗エッジ 0.5% のうち 0.19% が市場ドリフトなら実質 0.31% で、損益分岐 0.454% を下回る。
市場ベータは金利2.8%を払わずTOPIXを買えば得られるので、エッジの判定からは外す。
絶対リターンは実損益の計算に使う。

### Q5 の訂正（事実関係）

「信用区分の非対象銘柄」と「確定申告不要」は別の軸。

- 確定申告不要 = 口座の話。特定口座（源泉徴収あり）なら信用取引も証券会社が
  売買のつど源泉徴収するので原則申告不要。銘柄フィルタにはならない。
  ※損失繰越や他口座との損益通算をするなら申告が必要。
- 信用区分 = 銘柄の話。非対象銘柄は制度信用で買えないので除外は必須。

→ 口座は特定口座(源泉徴収あり)。銘柄フィルタは銘柄マスタの Mrgn で制度信用可に限定。

### 元金別のリスク（維持率20%基準。証券会社により25%）

```
元金    建玉    当初維持率   追証が出る下落率
50万   150万     33.3%        13.3%     ← 維持率25%の会社なら 8.3%
100万  150万     66.7%        46.7%
150万  150万    100.0%        80.0%
```

2024-08-05 の日経平均は −12.4%（終値4,451円安、史上最大の下げ幅）。
小型株はこれより深い。**元金50万・3倍はこの1日で追証**。同時3本は同じ日に
同じ方向へ動くため分散にならない。シミュレーションで **追証発生回数を数える**。

## 3. 監査で見つかった欠陥と対処

### 3.1 調整済み価格と生値の使い分け（先読みバイアス）

`AdjO/AdjC` は **データ取得時点までの分割・併合を遡及反映した価格**である。

```
リターンの計算   → AdjO を使う（分割を跨ぐリターンが正しくなる）
価格水準の判断   → 生の O/C を使う
                    ・単元100株が1本の建玉に収まるか
                    ・値がさ株の除外
                    ・時価総額の計算（生の株価 x 当時の株数）
```

v0.1 はここを混同していた。生値で判定しないと「当時5万円だった株が
10分割で調整後5千円に見え、買えるはずのない銘柄を買う」ことになる。

### 3.2 売買代金フィルタ（約定可能性）

時価総額300億以下の小型株で寄付に成行50万円を入れると、往復0.4%では済まない。
目安として **1本の建玉が直近20営業日平均売買代金の1%以内** を条件に加える。
50万円なら日次売買代金5,000万円が下限。これを満たさない銘柄は主条件から外し、
「フィルタなし」の結果と件数差を併記する。

### 3.3 ストップ高で寄らない銘柄（選択バイアス）

最も上昇する銘柄ほど買えない。3通りを出す。

```
(a) 寄らずをスキップ（デフォルト）
(b) 寄らずを翌日以降の最初に寄った始値で買う
(c) t0 が UL=1（ストップ高）の取引を全て除外
```

(a) と (c) の差が大きければ、リターンの大半がストップ高銘柄に依存している。

### 3.4 トレードの独立性（統計）

決算発表は 2月・5月・8月・11月 に集中する。同じ週のトレードは市場全体の
動きを共有し独立でない。単純な t 検定は有意性を過大評価する。

→ **日付クラスター・ブートストラップ**（同一週のトレードをまとめて再抽出、5000回）で
信頼区間を出す。単純 t 値も併記し、両者の乖離を示す。

### 3.5 必要サンプル数の再計算

v0.1 は「1トレードの標準偏差5%なら平均0.5%を t≈2 で言うには400トレード」と
書いたが、小型株の N=5 保有では σ=8% も珍しくない。

```
必要件数 = (2σ/目標平均)^2
  σ=5%,  平均0.5% →   400 件
  σ=8%,  平均0.5% → 1,024 件
  σ=8%,  平均0.3% → 2,844 件
```

5年で集まらない可能性が高い。各セルで必要件数を計算し、
**件数が不足するセルは数値を出したうえで「判定不能」と明示**する。

### 3.6 修正率の閾値は実データの分布で決める

東証の適時開示基準では、営業利益の業績予想修正は **130%超 または 70%未満**
（±30%）を超えないと開示義務が生じない（売上高は±10%）。

→ 「5% / 10% / 20%」という閾値は、業績予想修正だけを見ると3つとも
ほぼ同じ母集団（全部30%超）になり区別がつかない可能性が高い。
決算短信内の予想変更には小さい修正率も含まれるので、混在具合は実データ次第。

**グリッドを回す前に修正率のヒストグラムを出し、分位点で閾値を決める**
（例: 中央値 / 上位25% / 上位10%）。これは過剰最適化ではなく、開示制度に
合わせた区分けである。閾値の決定は `results/histogram.md` に記録し、
決めた後は動かさない。

### 3.7 除外銘柄の扱い

8053 / 9719 / 7518 の除外は、後から見て問題があった銘柄を落とす行為であり
それ自体が軽度の先読みである。ユーザーの明示的な制約として実装するが、
**「除外なし」の結果を必ず併記**し、除外が結果をどれだけ動かすかを示す。

- J-Quants の Code は5桁（"80530"）。4桁・5桁どちらでも一致させる。
- 7518 は 2025-03-18 に上場廃止（SCSK による TOB）。除外は上場中の期間に効く。

### 3.8 増担保規制

好材料で急騰した小型株は日々公表銘柄・増担保規制の対象になりやすく、
保証金率が50%等に引き上げられて建玉が組めなくなる。
バックテストでは検出できないため、**結果の但し書きとして明記**し、
ペーパートレード段階で実測する。

### 3.12 レート制限（実行して発覚）

1営業日ずつ叩くと 429 が返る。対策:

```
・Retry-After ヘッダがあればその秒数だけ待つ
・無ければ 5秒から倍々（上限300秒）で最大8回
・429 を食らうたびにリクエスト間隔そのものを 1.5倍に広げる（上限10秒）
・成功が200回続いたら少しだけ戻す
```

再試行するのは通信起因の例外（接続断・タイムアウト）と 429 / 5xx のみ。
こちらのバグまで再試行すると、原因が見えないまま何分も止まる。

### 3.13 取得のやり直し判定

月ごとに `<month>.meta.json` を置き、次を記録する。

```
version        保存形式の版。上げると既存の月を取り直す
expected_days  その月の営業日数
rows           取得できた行数
failed_days    取れなかった日
```

次のいずれかなら取り直す。

```
・版が古い
・営業日数が合わない
・失敗した日がある
・日足なのに0行（全銘柄が返るはずなので0行は異常）
```

HolDiv を取り違えた最初の実行は全月0行のファイルを作ってしまった。
版を上げることで、利用者が手でファイルを消さなくても自動的に無効化される。

### 3.10 MktCap の単位（probe で発覚）

`/equities/bars/daily` の `MktCap` は **百万円単位**で返る。

```
極洋(13010)              MktCap 54050    -> 540.5億円（株価4475円・発行済1208万株）
ネットワンシステムズ(75180) MktCap 359783   -> 3598億円（TOB総額と整合）
```

円と誤読すると 54,050円 になり、「時価総額500億円以下」（5e10）の条件を
**全銘柄が通過する**。時価総額フィルタが存在しないのと同じになり、
グリッドの3列（全体 / 500億以下 / 300億以下）が全部同じ結果になる。

読み込み時に `units.mkt_cap_multiplier`（= 1,000,000）を掛けて円に揃える。
代替計算の `(ShOutFY - TrShFY) x 終値` は円建てなので、これで単位が一致する。

### 3.11 REIT の除外

`FYFinancialStatements_Consolidated_REIT` が存在する。REIT（投資法人）は
事業会社と決算・予想の性質が異なる（分配金予想が主）ため、既定で除外する。
`filters.exclude_reit` で切り替え可能。

### 3.9 配当落ち

保有期間が権利落ちを跨ぐと株価は配当分下がるが、信用買いは配当落調整金を
受け取るのでほぼ中立。ただし J-Quants の調整済み価格が配当を含むかは未確認。
権利落ちを跨いだトレードにフラグを立て、件数と平均リターンを別掲する。

## 4. イベント定義

### 4.1 対象開示

| 種別 | 扱い |
|---|---|
| 決算短信 1Q/2Q/3Q | 当期通期予想 `FOP` の前回開示比を修正率とする |
| 決算短信 FY（本決算） | `NxFOP` は新年度の初回予想であり修正ではない。修正率は算出せず、フィルタなしの集計にのみ含める |
| 業績予想修正 | `FOP` の前回開示比 |
| 配当予想修正のみ | 対象外 |

### 4.2 修正率

```
同一 Code・同一 CurFYEn の開示を DiscDate, DiscTime, DiscNo 順に並べ
  prev_FOP = 直前の開示の FOP（本決算行の NxFOP を新年度の初回予想として引き継ぐ）
  rev_rate = FOP / prev_FOP - 1
除外: prev_FOP <= 0 / 欠損 / 窓の外（赤字転換は率が定義できないため件数のみ別掲）
```

対照群を必ず出す。

```
・修正率フィルタなし（全開示）
・下方修正 <= -30%       ← 仮説が本物なら符号が逆になる。ならなければ市場ベータを拾っているだけ
```

### 4.3 タイミング分類

```
after_close : DiscTime >= 大引け（〜2024-11-01 は 15:00、2024-11-05〜 は 15:30）
              または DiscDate が休業日
intraday    : それ以外
```

場中開示も翌取引日始値で統一するが、内訳を必ず別掲する。

### 4.4 修正常習フラグ

```
habitual = イベント日より前 1095 暦日の同一 Code の予想変更件数 >= 4
           （業績予想修正の開示 + 決算短信内での予想変更。上方・下方の両方）
```

5年分しかないため 3年窓が欠けるイベントがある。
「窓が完全なイベントのみ」と「欠けたまま」の両方を出す。

### 4.5 時価総額

イベント開示日の終値時点で評価（現在値で分類すると先読み）。
`MktCap` が使えなければ `(ShOutFY - TrShFY) x C`（生値）。

## 6. ポートフォリオ

```
建玉150万・同時3本・1本50万
日次ループ:
  1) 返済日到来の建玉を tN 始値で返済
  2) 当日 t0 のシグナルを修正率降順（同順位は時価総額昇順）に並べ、空き枠だけ建てる
  3) 枠がなく見送った件数を記録
  4) 元金 50/100/150万 それぞれで維持率を計算し、20%割れ（追証）の日を数える
出力: 日次エクイティ、最大DD、年別純益、枠稼働率、追証発生回数
```

## 7. グリッドと出力

```
N            : 1 / 3 / 5 / 10
時価総額     : 全体 / 500億以下 / 300億以下
修正率       : なし(対照) / 分位点3段階 / <=-30%(対照)
常習除外     : あり / なし
売買代金     : フィルタあり / なし
タイミング   : 全体 / 引け後 / 場中（内訳）
スリッページ : 0.3 / 0.4 / 0.5%（純エッジ・純益表）
除外銘柄     : あり / なし（併記）
```

各セルの出力列:

```
trades, gross_%, excess_topix_%, net_edge_%, median_%, stdev_%,
t_stat, cluster_boot_ci_low, cluster_boot_ci_high,
required_n（必要件数）, verdict（判定可 / 判定不能）,
win_rate, year別平均, max_dd_%,
annual_net_jpy（元金50/100/150万別）, margin_call_count,
skipped_no_open, skipped_lot_size, skipped_turnover, skipped_no_slot
```

### 過剰最適化への対策

1. 主条件を1セル事前登録し、判定はそのセルで行う。
2. 前半（〜2024-03）/ 後半（2024-04〜）で別集計し、両方プラスでなければ不採用。
3. 対照群（フィルタなし / 下方修正）の符号を確認。上方修正だけが優位でなければ不採用。
4. 件数不足のセルは「判定不能」と表示し、判定に使わない。
5. 採用条件: 対照群を除く全セルで `net_edge > 0` かつ 主条件で `net_edge > 0.05%`
   かつ クラスターブートストラップの信頼区間下限が 0 を上回る。
