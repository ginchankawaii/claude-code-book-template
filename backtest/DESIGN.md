## 0. 検証したい仮説（仕様の再掲と精密化）

> 決算・業績予想修正の開示があった **翌営業日の始値** で信用買い →
> **N営業日後の始値** で返済。往復スリッページ控除前の粗エッジが 0.5% を超えるか。

精密化した定義:

```
イベント   : 財務サマリー(fins summary) の1開示行 = 1イベント
エントリー : 開示日の翌取引日 t0 の始値 (調整済み AdjO)
イグジット : t0 から取引カレンダー上 N 営業日後 tN の始値 (AdjO)
粗リターン : AdjO[tN] / AdjO[t0] - 1
粗エッジ   : 条件に合致するトレードの粗リターンの単純平均
```

- 「翌営業日」は **銘柄の取引日ではなく取引カレンダー(mkt calendar, HolDiv=0)** で数える。
- 場中開示（DiscTime が大引け前）も **翌取引日始値** で統一する（仕様どおり）。ただし
  「引け後」「場中」のラベルを全イベントに付与し、内訳を必ず別掲する。
- 大引け時刻は **2024-11-05 から 15:30**（それ以前は 15:00）。引け後判定の閾値は日付で切り替える。

### 1.2 使用するテーブルと項目（V2 名称。V1 とは別名なので注意）

```
fins summary（財務サマリー）
  DiscDate, DiscTime, Code, DiscNo, DocType
  CurPerType (1Q/2Q/3Q/FY), CurFYSt, CurFYEn        … 対象事業年度の特定に使う
  OP        : 営業利益 実績
  FOP       : 営業利益 通期予想（当期）
  NxFOP     : 営業利益 翌期予想（本決算行で新年度予想が入る）
  FOP2Q     : 営業利益 第2四半期累計予想
  ShOutFY   : 期末発行済株式数（自己株含む）      … 時価総額の代替計算用
  TrShFY    : 期末自己株式数
  ChgByASRev / ChgNoASRev / ChgAcEst / RetroRst     … 会計方針変更フラグ（要注意行の識別）

eq daily（株価日足）
  Date, Code, O, H, L, C, Vo, Va
  UL, LL      : ストップ高/安フラグ
  AdjFactor, AdjO, AdjH, AdjL, AdjC, AdjVo
  MktCap      : 時価総額（CLI のスキーマには存在。Light で値が入るかは要確認 → 1.4）

eq master（銘柄マスタ、日付指定で過去時点も取れる）
  Date, Code, CoName, Mkt, MktNm, ScaleCat
  Mrgn, MrgnNm : 信用区分（制度信用/貸借/非対象）  … 信用買い可否フィルタに使う

mkt calendar : Date, HolDiv (0=営業日)
idx daily-topix : TOPIX 日足  … 市場ベータの控除（超過リターン算出）用
```

- 決算発表予定日（`fins earnings-date`）は **将来の予定のみ** を返す想定。バックテストでは
  不要（DiscDate/DiscTime で足りる）。実運用の前日スクリーニングで使う。

## 2. イベント定義（events.py）

### 2.1 対象開示

| 種別 | DocType（想定） | 扱い |
|---|---|---|
| 決算短信 1Q/2Q/3Q | `*FinancialStatements*` かつ CurPerType≠FY | 当期通期予想 `FOP` の **前回開示比** を修正率とする |
| 決算短信 FY（本決算） | 同上 かつ CurPerType=FY | `NxFOP` は「新年度の初回予想」であり修正ではない → **修正率は算出しない**（修正率フィルタなしの集計にのみ含める） |
| 業績予想修正 | `EarnForecastRevision` 相当 | `FOP` の前回開示比 |
| 配当予想修正のみ | `DividendForecastRevision` 相当 | **対象外** |

### 2.2 修正率

```
同一 Code・同一 CurFYEn の開示を DiscDate, DiscTime, DiscNo 順に並べ、
  prev_FOP = 直前の開示の FOP（本決算行なら NxFOP を初回予想として引き継ぐ）
  rev_rate = FOP / prev_FOP - 1
除外: prev_FOP <= 0、FOP または prev_FOP が欠損、prev_FOP が 5年窓の外で取れない
      （赤字→黒字転換は率が定義できないので v0.1 では対象外。件数だけ別掲）
```

- 「修正率 5%/10%/20% 以上」に加えて **対照群** を必ず出す:
  - `修正率フィルタなし`（全開示）
  - `下方修正 −5% 以下`（仮説が本物なら符号が逆になるはず。ならなければ市場ベータを拾っているだけ）

### 2.3 タイミング分類

```
after_close : DiscTime >= 大引け（〜2024-11-01 は 15:00、2024-11-05〜 は 15:30）
             または DiscDate が休業日
intraday    : それ以外
```

### 2.4 修正常習フラグ

```
habitual = イベント日より前 3年間（暦日 1095日）の同一 Code の
           EarnForecastRevision 相当の件数 >= 4
```

- 5年分しかないため、**データ開始から 3年未満のイベントは窓が欠ける**。
  → 「窓が完全なイベントのみ（後半約2年）」と「欠けた窓のまま」の両方を出す。
  上方・下方の両方を数えるか、上方のみかは確認事項。

### 2.5 時価総額

- イベント開示日の終値時点で評価（**その時点の値**。現在値で分類すると先読みになる）。
- `MktCap` が使えなければ `(ShOutFY − TrShFY) × C`。ShOutFY は直近の本決算行から取る。

### 2.6 ハードコード除外・制約

```python
EXCLUDED_CODES = {"8053", "9719", "7518"}   # 住友商事 / SCSK / ネットワンシステムズ
# J-Quants の Code は 5桁（"80530" 等）。4桁・5桁どちらでも一致させる。
# ロングのみ。ショート側のロジックは存在させない（パラメータでも切り替え不可）。
```

- ネットワンシステムズ(7518) は SCSK による TOB 後、**2025-03-18 に上場廃止**。
  除外は「上場中の期間のイベントを落とす」意味で必要。

## 3. 約定・コストモデル（simulate.py）

| 要素 | 扱い |
|---|---|
| エントリー価格 | t0 の AdjO。t0 の Vo=0 または O 欠損（寄らず）なら **その取引はスキップ**して件数を記録 |
| ストップ高で寄った日 | 通常どおり成立扱いとし、感度分析で「t0 が UL=1 の取引を除く」版も出す |
| イグジット価格 | tN の AdjO。tN 前に上場廃止 → 最終取引日の AdjC で手仕舞い（フラグ付与、除外しない） |
| スリッページ | 往復 0.3 / 0.4 / 0.5% を粗リターンから減算（グリッド） |
| 信用買方金利 | 年 2.8%（制度信用の一般的水準、パラメータ）× 保有暦日/365 |
| 手数料 | 0 円を既定（主要ネット証券の制度信用）、パラメータで変更可 |
| 税金 | 控除しない（税引前で判定） |
| 単元 | 100株。1本あたりの資金で 100株買えない銘柄は **スキップ**して件数を記録 |

- スリッページは粗エッジに対する **定数の引き算** なので、粗エッジの表はスリッページに依存しない。
  グリッド次元として回すのは「純益・DD」の表のみ。

## 4. ポートフォリオ・シミュレーション（年間純益・最大DD用）

```
資金 150万円、同時保有 3本、1本 = 50万円（既定。→ 確認事項 Q2）
日次ループ:
  1) 返済日到来の建玉を tN 始値で返済
  2) 当日 t0 のシグナルを rev_rate 降順に並べ、空き枠がある分だけ建てる
     （同順位は時価総額の小さい順）
  3) 枠がなく見送った件数を記録
出力: 日次エクイティ、最大DD、年別純益、稼働率
```

- 「同時3本」の制約で **年間純益は取引候補数に強く依存**する。粗エッジと純益は別物として読む。

## 5. グリッドと出力（grid.py）

### 5.1 次元

```
N            : 1 / 3 / 5 / 10
時価総額     : 全体 / 500億以下 / 300億以下
修正率       : なし(対照) / ≥5% / ≥10% / ≥20% / ≤−5%(対照)
常習除外     : あり / なし
タイミング   : 全体 / 引け後のみ / 場中のみ   （内訳として出す）
スリッページ : 0.3 / 0.4 / 0.5%             （純益・DD 表のみ）
```

粗エッジ表 = 4 × 3 × 5 × 2 = **120 セル**（タイミング内訳を含めると 360）。

### 5.2 各セルの出力列

```
trades, mean_gross_%, median_%, stdev_%, se_%, t_stat,
win_rate, excess_vs_topix_%（同一区間の TOPIX 始値→始値を控除）,
year別 mean（2021…2026）, 
max_dd_%（ポートフォリオ）, annual_net_jpy（スリッページ別）,
skipped_no_open, skipped_lot_size, skipped_no_slot
```

### 5.3 過剰最適化への対策（仕様の「注意点」に対する具体策）

1. **主条件の事前登録**: 実行前に 1 セルを主条件として固定し、判定はそのセルで行う。
   提案: `N=5 / 全体 / ≥10% / 常習除外あり / スリッページ 0.4%`（→ 確認事項 Q9）
2. **時間分割**: 前半（〜2024-03）と後半（2024-04〜）で別々に集計し、両方プラスでなければ不採用。
3. **対照群**: 「フィルタなし」「下方修正」の符号を確認。上方修正だけが優位でなければ不採用。
4. **統計的有意性**: t_stat と se を必ず併記。1トレードの標準偏差が 5% なら、
   平均 0.5% を t≈2 で言うには **約 400 トレード必要**。件数が足りないセルは「判定不能」と表示する。
5. 「全条件で安定してプラス」の機械的定義: 対照群を除く全セルで `mean_gross > 0` かつ
   主条件で `mean_gross > 0.5%`。

## 6. 判定基準（仕様どおり、コードで自動判定して md に書く）

```
主条件の粗エッジ  < 0.5%        → 打ち切り
                 0.5 〜 0.8%    → ペーパートレード 3か月
                 > 0.8%         → 少額実弾
ただし 5.3 の 2〜4 のいずれかに該当すれば、数値に関係なく「不採用」と併記する
```

## 8. 確認事項（回答で設計が変わる順）

```
Q1  実行場所: 実データの取得・実行はローカル PC で行う前提でよいか
    （この環境は J-Quants に到達できない）。CLI は brew で入れられる環境か。
```
