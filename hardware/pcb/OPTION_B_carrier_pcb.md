## 1. 何が本当に解決するのか（案Bの勝ち筋）

v1 で「設計書には書いてあるが実装できていない」2機能は、いずれも
**XIAO の castellation ピンだけで閉じられる**ので、キャリア基板が最も素直に解ける。

| 機能 | v1 で不可能な理由 | 案B での解 |
|---|---|---|
| VBUS(USB挿入)検出<br>（README §9.5 / 全体設計の「充電開始で同期」トリガ） | 5Vピンから分圧してGPIOに入れる配線が無い | **5V → R2 220k / R3 330k → D0(GPIO1)**。<br>Seeed公式: 「5Vピンは USB からの 5V 出力。外部給電に使うならダイオードを入れよ」＝**5Vピンは VBUS 直結**なので検出点として使える（Web検証済み） |
| 電池電圧監視 / 残量警告<br>（README §9.5、ELECTRICAL.md §2.1 のv2申し送り） | BAT+ ノードを引ける場所が無い | **BAT+（保護FET後）→ R4 220k / R5 220k → D4(GPIO5, ADC1_CH4)**。常時 9.5 µA（ELECTRICAL.md の申し送り値と同じ） |
| 電池の極性事故（README 冒頭の最大警告） | パッド直はんだ・やり直し不能 | **JST-PH コネクタ + AO3401A ×2 背中合わせ** で、セルを逆挿ししても**放電も充電も流れない** |
| LED抵抗の空中配線・GND 3本のより合わせ（ELECTRICAL.md §3 の #7/#9） | 空中スプライスが振動で最も壊れる | **銅箔になる**（0805 抵抗 + GNDベタ） |

**再現性**: 本リポジトリは「本のテンプレート」なので、複数人が同じ物を組む前提なら
基板化の価値は1台きりの場合より高い（誰が組んでも同じ配線になる）。

## 2. 決定的な制約 —— XIAO の BAT パッドは裏面にある

Seeed フォーラム/コミュニティで繰り返し指摘されている既知の問題:

> The BAT pads are on the back of the XIAO ESP32-C3, which makes surface mount soldering
> to a motherboard problematic.

MECHANICAL.md §2 も「BAT+/− パッドのある面が裏面（背面側）」と書いており、
ELECTRICAL.md §5.2 は「−が USB-C 側、+が遠い側」とだけ規定していて **正確な座標は未確定（assumption）**。

したがって案Bでは:

- キャリア基板の **XIAO 直下に 12 × 10 mm の窓** を開け、BAT+ ジャンパ線をそこへ落とす。
  窓の左端は XIAO 外形より 0.4 mm 左に出し、線を**横方向に引き出せる**ようにする
  （線を XIAO と基板の間に挟むと XIAO が浮いてキャステレーションのはんだが割れる）。
- **BAT− 側のジャンパは不要にできる**（点数削減の要）:
  XIAO の BAT− は内部で GND と同電位のはずなので、**GND キャステレーション経由で返す**。
  → **ジャンパは BAT+ の1本だけ**になり、「2本を入れ替える」事故そのものが消える。
  - ★**この前提は必ずテスターで確認すること**（XIAO の BAT− パッド ↔ GND ピン間の導通）。
    導通しなければ BAT− ジャンパをもう1本足す＝はんだ+2点、入れ替え事故のリスク復活。

**結論: 「BATパッドへの手はんだ」は案Bでも1点残る。** ただし v1 と違い、
**電池を繋ぐ前に（無通電で）はんだ付けし、テスターで検証してからコネクタを挿す**順序になるので、
「一瞬で ¥2,660 が死ぬ不可逆ステップ」ではなくなる。

## 3. 回路（詳細は [`netlist.txt`](netlist.txt)）

```
                       ┌── R2 220k ──┬── R3 330k ── GND
  XIAO 5V (=VBUS) ─────┘             ├── C2 100n ── GND
                                     └────────────── XIAO D0 (GPIO1)  VBUS_SENSE

                Q1        Q2                       ┌── R4 220k ──┬── R5 220k ── GND
  J1.1 ──D  ┤├  S ── S  ┤├  D ──┬── TP1 ──(ジャンパ)─┤             ├── C1 100n ── GND
  (セル+)     G      G          └── R4 へ            └─────────────── XIAO D4 (GPIO5)  VBAT_SENSE
              │      │                         XIAO 裏面 BAT+ パッド
             GND    GND

  J1.2 (セル−) ── GND ── XIAO GND (castellation)   ※XIAO の BAT− は内部でGNDと同電位という前提
  XIAO D1 (GPIO2) ── J2.1 …スライドスイッチ…  J2.2 ── GND
  XIAO D3 (GPIO4) ── R1 220R ── J3.1 …LED…      J3.2 ── GND
```

### 3.1 逆接続保護は「2個」でなければ意味がない（重要）

- P-ch MOSFET **1個**では、**逆挿しセルへの充電を止められない**。
  ボディダイオードが充電方向に導通するため、XIAO の内蔵充電IC が
  **逆極性のセルを 50 mA で充電し続ける**（LiPo の逆充電は発熱・膨張・破裂の経路）。
- **AO3401A を 2個、ソース同士を突き合わせ（back-to-back）**、両ゲートを GND に落とす。
  - 正常時: 両方 Vgs = −Vbat で ON。オン抵抗 2 × 約50 mΩ = 0.1 Ω
    → WiFi 送信バースト 300 mA でも 30 mV 降下（無視できる）。
  - 逆挿し時: 両方 OFF + ボディダイオードが逆直列 → **双方向とも阻止**。
- 充電電流 50 mA での降下は 5 mV なので、内蔵充電IC の CV 判定に実害なし。

### 3.2 分圧値の根拠

| 項目 | 値 | 根拠 |
|---|---|---|
| VBUS 分圧 | 220k / 330k → **3.00 V** | VIH = 0.75 × 3.3 = 2.48 V に対し +0.52 V。USB 5.25 V でも 3.15 V < 3.3 V。**デジタル入力として使う**（ADCの精度確保域 150〜2450 mV を超えるため電圧測定には使わない）。消費 9.1 µA（USB挿入時のみ） |
| VBAT 分圧 | 220k / 220k → **Vbat/2 = 1.50〜2.10 V** | ESP32-S3 ADC1・12 dB の精度確保域内。常時 9.5 µA = 680 mAh に対し約340日で1%。ELECTRICAL.md §2.1 の申し送り「220k×2・約9µA」と同値 |
| C1/C2 100 nF | 必須 | 分圧のテブナン抵抗 110 k は SAR ADC のサンプリング容量に対して高すぎる。コンデンサで電荷を供給する（省くと読み値が沈む） |
| LED R1 | 220 Ω | ELECTRICAL.md §1.2 と同一（5.9 mA、PWMで微灯化） |

### 3.3 ピン割当（v1 から変更なし + 2本追加）

| 信号 | ピン | GPIO | 備考 |
|---|---|---|---|
| SW_IN | D1 | 2 | v1 と同じ。RTC GPIO / EXT0 ウェイク |
| LED_DRV | D3 | 4 | v1 と同じ |
| **VBUS_SENSE** | **D0** | **1** | RTC GPIO → EXT1 で「USB挿入でウェイク」が可能 |
| **VBAT_SENSE** | **D4** | **5** | ADC1_CH4（ADC2 は WiFi と排他なので不可） |
| 使用禁止 | D8/D9/D10 | 7/8/9 | Sense 拡張ボードの microSD SPI。**基板上でも一切引き回さない** |
| 回避 | D2 | 3 | ストラッピングピン |

## 4. 機構 —— 筐体CADで実測した高さ予算

### 4.1 奥行き(Z): allday はタダで入る / slim は基板厚がそのまま効く

`python3 hardware/pcb/height_budget.py` の出力（筐体CADを再計算した実数）:

内寸奥行き `ID = max(XIAO側, 電池側)`、
XIAO側 = 基板下逃げ 0.8 + **PCB厚** + スタック 7.5 + リッド余裕 0.6、
電池側 = ボス 1.4 + 電池厚 + 押さえリブ 1.8。

| 構成 | XIAO側 | 電池側 | ID | **allday 外形奥行** | **slim 外形奥行** |
|---|---|---|---|---|---|
| v1（基板なし） | 9.5 | 11.2 / 8.2 | 11.2 / 9.5 | **14.6** | **12.9** |
| 案B / PCB **0.8 mm** | 9.7 | 同上 | 11.2 / 9.7 | **14.6**（±0） | 13.1（**+0.2**） |
| 案B / PCB **1.0 mm**（推奨） | 9.9 | 同上 | 11.2 / 9.9 | **14.6**（±0） | 13.3（**+0.4**） |
| 案B / PCB **1.6 mm**（JLC既定） | 10.5 | 同上 | 11.2 / 10.5 | **14.6**（±0） | 13.9（**+1.0**） |

- **allday は奥行きが一切増えない。** 奥行きを支配しているのは電池側（11.2 mm）で、
  XIAO 側には元々 **1.7 mm の遊び**がある。1.6 mm 基板でも 10.5 < 11.2 で収まる。
- **slim は基板厚が丸ごと外形に出る**（XIAO 側が支配的なため）。
  0.8 mm 板なら +0.2 mm で済むので、slim を残すなら **0.8 mm 一択**。
- **推奨は 1.0 mm**: JLCPCB は 2層 0.8〜1.6 mm が同一価格帯。XIAO の基板厚（実測要）
  に近く、キャステレーションのランドとの段差が小さい。allday 主体なら 1.6 mm でも構わない。
- 図: [`stackup.svg`](stackup.svg)

**「基板の厚み分そのまま筐体が厚くなる」は allday では成立しない。** これは案Bの数少ない明確な勝ち点。

### 4.2 高さ(Y): ここが案Bの本当のコスト —— +1.7 mm

キャステレーションを手はんだするには、ランドが XIAO 外形から外へ **1.0 mm** 出ている必要がある
（+ 基板端まで銅箔 0.3 mm）。現行筐体の余裕は:

| | 現行 | 必要 | 判定 |
|---|---|---|---|
| XIAO 上端 〜 上壁内面 (`M_TOP`) | **0.6 mm** | 1.3 mm | ★不足 0.7 mm |
| 電池上端 〜 XIAO 下端 (`GAP_BX`) | **1.2 mm** | 1.3 mm | ★不足 0.1 mm |

XIAO の 14 ピンは**長辺2列**（列間 17.78 mm・2.54 ピッチ×7）に並ぶので、
**両方の長辺にランドが要る**。片側だけで済ませられない理由:

- 必要な信号は **5V/GND（電源列＝下辺）** と **D0/D1/D3/D4（信号列＝上辺）** に分かれている。
- 電源列にある空きピン D7〜D10 は GPIO44/9/8/7 で、GPIO44 は ADC 不可・RTC 不可、
  GPIO7/8/9 は microSD 占有。**VBUS/VBAT の入口は信号列にしか無い。**

→ `GAP_BX 1.2 → 1.8` / `M_TOP 0.6 → 1.7` に拡大。
**内寸高さ IH 46.2 → 47.9 / 外形高さ H 49.4 → 51.1 mm（+1.7 mm）**。

`carrier_board.py` の判定は allday/slim とも **PASS（NG 0）**。

### 4.3 キャリア基板が置ける場所は「XIAO の帯」だけ

- 電池は allday で上面 z = 11.0（リッド内面 12.8）まで来るため、**基板を電池の上に重ねられない**。
- 基板外形 = **34.2 × 20.6 mm（面積 705 mm²）**、z 2.4〜3.4。
- 基板上面〜リッド内面の実装可能高さ: **allday 9.4 mm / slim 8.1 mm**
  → JST-PH（H6.0 + 嵌合代 assumption 1.0 = 7.0）は allday +2.4 / slim +1.1 mm で**入る**。
    slim は電線の曲げ代がかなり苦しい。
- 図: [`carrier_layout_allday.svg`](carrier_layout_allday.svg)

### 4.4 スイッチと LED は基板に載せられない（正直な限界）

基板上面は z = 3.4、スイッチのレバーが出る上壁とLED窓（リッド）は **4.7〜9.4 mm 上**にある。
基板実装の SS-12D00（H3.5+レバー2.0）や 3 mm LED（H約5.3）では**届かない**。
SMD サイドスライドスイッチ（MSK-12C02, H2.8, JLCPCB C431540）も同様に届かない。

→ **スイッチと LED は v1 と同じく空中配線のまま**、基板側は 2P スルーホール（J2/J3）で受ける。
「基板にすれば配線が全部消える」わけではない。

### 5.1 筐体CADに見つかった潜在バグ（案B以前の問題として要修正）

`GAP_BX` / `M_TOP` を変えると **`INTERFERENCE: seat0 <-> xnub_b0` で assert が落ちる**。
原因は `xiao_seats` の y 座標が **絶対値の直書き**（29.5 / 32.0 / 44.6 / 47.1）で、
`xiao[1]` / `xiao[3]` に追従しないため。`sw_rib` の y0 = 44.6、`bat_stops_*`、
`LED_POS` も同様に直書き。

> **これは案Bを採らなくても直すべき。** 現状「`IH` を構成する `M_TOP`/`GAP_BX` を触ると
> 静かに壊れる」パラメトリックCADになっている。`height_budget.py` はこの再現手順を含む。

| XIAO 裏 BAT+ パッド ← ジャンパ | 2（BAT+/BAT−） | **1** | 1 |
| ジャンパ ← 基板 TP1 | 0 | **1** | 1 |
| スライドスイッチ（本体2 + 基板2） | 2 | **4** | 4 |
| LED（本体2 + 基板2） | 1 | **4** | 4 |
| 220 Ω 抵抗（空中配線） | 2 | 0 | — |
| GND 3本のより合わせ | 1 | 0 | — |
| XIAO D1/D3/GND 直はんだ | 3 | 0 | — |
| SMD（R×5, C×2, Q×2, J1） | — | 0 | 22 |
| **合計** | **11** | **20** | **42** |

**点数は増える。減るのは難易度と不可逆性:**

- キャステレーション 10 点は「半円の穴にはんだを流す」だけで、
  XIAO のスルーホールに細線を通す作業より**易しい**（ESP-12 等と同じ）。
- 最難関だった **BATパッドは 2点 → 1点**、しかも**無通電で施工 → テスターで確認 → 最後に電池を挿す**。
- 空中スプライス（GND 3本より合わせ・抵抗の宙吊り）が **0 になる**。
  これは装着デバイスで最も壊れる接合形態（案A側の指摘とも一致）。

## 8. リスク（自案に不利なものを先に書く）

1. **BATパッド直はんだは消えない。** XIAO の電池パッドは裏面（Web検証済み）。
   キャリアに載せると隠れるので、窓+ジャンパ線が必須。案Bの売り文句として
   「BATパッド直はんだが不要になる」と書いてはいけない。
2. **XIAO裏面 BAT パッドの正確な位置が未実測**（MECHANICAL.md §8 / README §9.1）。
   窓 12 × 10 mm はあくまで当て推量。外せば基板ごと作り直し（+2週間・+¥2,000〜4,700）。
3. **「BAT− = GND」が未確認の前提。** 成立しなければジャンパが2本になり、
   入れ替え事故のリスクが復活する（＝案Bの安全上の主張が半分崩れる）。
   実機で導通確認するまでは仮説。
4. **手はんだ点が 11 → 20 に増える。** 「基板にすれば楽になる」は総量では偽。
5. **筐体が高さ +1.7 mm（49.4 → 51.1 mm）になる。** 奥行きは allday なら±0だが、
   高さは両バリアントで確実に増える。ここは案Aに完敗する点。
6. **XIAO を基板にはんだ付けした瞬間、取り外しが実質不可能になる。**
   ヒートガン無しで 14 箇所のキャステレーションを外すのは初心者には無理。
   配線ミス＝¥2,660 の XIAO ごと廃棄。**基板より先に XIAO の動作確認を済ませること。**
7. **逆接続保護 FET を 1個で済ませると危険**（§3.1）。2個必須。
   さらに FET はメインの電池経路に直列に入るので、**はんだ不良＝間欠断＝ウェアラブルで最悪の故障**。
8. **本環境に KiCad が無いため、Gerber を出せない。** 本書とネットリストは
   「回路図を手で起こすための一次資料」であって製造データではない。
   人手のアートワーク工程が入る＝レイアウトミスの余地が残る。
9. **JST-PH の嵌合高さ（+1.0 mm）は assumption。** slim では基板上の余裕が
   8.1 mm しかなく、電線の曲げ代込みで実測確認が要る。
10. **スイッチ・LED の空中配線は残る**（§4.4）。案Bでも配線作業はゼロにならない。
11. **最小ロット 5 枚。** 1台しか作らない人には全額が乗る（+30〜70%）。
12. **基板下の逃げ 0.8 mm は薄い。** スルーホール部品の足を切り残すと基板が浮き、
    XIAO が傾いてキャステレーションのはんだにモーメントが掛かる。足はニッパで面一に切る。
13. **XIAO スタック総厚 7.5 mm 自体が assumption。** 実測がこれより厚ければ
    slim は基板の +0.4 mm 以前に破綻する（README §9.1）。

## 9. 判定と、採るなら守る条件

**判定: 条件付き推奨。ただし「今」ではない。**

- 案Bが本当に効くのは **VBUS検出・電池監視・逆接続保護の3点**で、
  これらは v1 の設計書が「やる」と書いて実装できていない項目そのもの。
  空中配線で足すと 3端子スプライスが増えて信頼性が落ちるので、**最終形は基板が正しい**。
- しかし **BATパッド位置・スタック厚・電池実寸・USB-C嵌合のどれもまだ実測されていない**。
  この状態で焼くと、失敗コストが「2週間 + ¥2,000〜4,700 + XIAO ¥2,660」になる。

**採るなら以下を順に満たすこと（ゲート）:**

1. v1 を 1台組み、README §8.6 の**消費電流ゲート（平均 ≤28 mA）を通す**。
2. ノギスで **XIAO スタック総厚**を実測 → `XIAO_STACK_T` を更新。
3. **XIAO 裏面 BAT+/− パッドの座標を実測**（基板端からの X/Y）→ 窓位置を確定。
4. テスターで **BAT− ↔ GND の導通**を確認 → ジャンパ本数を確定。
5. 電池（802530）の**実寸・リード出射・JST-PH プラグの極性**を確認。
6. 上記を `carrier_board.py` のパラメータに反映して再実行し、PASS を確認してから
   回路図・アートワークに着手。

**それまでの間は、案A（空中配線の改良）で v1.5 を回すのが順当。**
案Bは v2 の設計であって、v1 の代替ではない。
