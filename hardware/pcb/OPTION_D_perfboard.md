# 案D — ユニバーサル基板(蛇の目基板)での手組み

**担当範囲**: 基板製造を発注せず、秋月電子のユニバーサル基板を筐体内寸に合わせて切り、
部品を載せて手配線する案。納期ゼロ・作り直し自由という利点と、精度・再現性・高さの
問題を評価する。**「初心者がまず1台試す」段階での現実解になり得るか**を主題にする。

検証スクリプト: [`option_d_perfboard.py`](option_d_perfboard.py)
（`python3 hardware/pcb/option_d_perfboard.py` で本書の数値をすべて再生成する）

## 1. なぜ「左デッドスペース」しか使えないのか（実空間の実測）

`option_d_perfboard.py` は筐体CADの内部部品・リブの AABB をそのまま読み込み、
キャビティ断面を 0.1mm グリッドに離散化して「板厚1.0mmの基板を床から0.8mm浮かせて置いた
とき、部品高さ H mm を確保できる最大の空き長方形」を求める（ヒストグラム法）。

**allday の結果**（基板 z 2.4..3.4 / リッド内面 z 12.8）:

| 必要部品高さ | 最大の空き長方形 | 2.54グリッド | 位置 |
|---|---|---|---|
| 1.5 mm | 10.2 × 15.9 mm (162mm²) | **4×6 = 24穴** | x 1.9..12.1, y 28.4..44.3 |
| 5.0 mm | 10.2 × 15.9 mm (162mm²) | 4×6 = 24穴 | 同上 |
| 6.0 mm | 10.2 × 6.5 mm (66mm²) | 4×2 = 8穴 | y 37.8..44.3 |
| 8.0 mm | 9.1 × 6.5 mm (59mm²) | 3×2 = 6穴 | x 3.0..12.1, y 37.8..44.3 |
| 9.5 mm | **なし** | — | — |

（slim は LED がリッドから同じ4mm侵入する一方でリッド内面が z11.1 と1.7mm低いため、
5.0mm 以上を要求すると 4×2=8穴 に落ちる。）

**なぜここしか無いのか**（すべてCADから読んだ値）:

- 電池 (x4.0..34.0, y3.2..28.2) は **z 3.0..11.0** を占める。基板を床に置くと z2.4..3.4 で
  電池と z が重なるので、**基板は電池の下にも上にも敷けない**。
- XIAO の下 (x15.4..36.4, y29.4..47.2) は面積は広いが、**外形を変えずに置ける部品高さは
  1.3mm しかない**（§4）。
- 残るのが x1.9..12.1 / y28.4..44.3 の左ゾーン。ここは `xiao_stops`(x12.4〜)、`sw_rib`(x2.9..3.7,
  y44.6〜)、LED(リッドから4mm侵入)、`lip_left` に三方を囲まれている。
- 切り欠き(L字カット)を許せば左ゾーンの空き面積は最大 235mm²（≈36穴相当）まで伸びるが、
  リブを避ける切り欠きを手作業で出すのは現実的でないので、**矩形24穴を上限として設計する**。

> **これは v1 筐体の設計が悪いのではなく、狙い通り詰まっている**ことの裏返しである。
> MECHANICAL.md は内寸奥行きを「XIAO側」と「電池側」の厚い方から自動計算しており、
> 余剰体積を持たない。案Dはその「詰まった箱」の隙間に入る唯一の形に自然と収束する。

## 2. 採用構成

### 2.1 何を載せるか（載せないか）

| 載せる | 理由 |
|---|---|
| **J1: JST PH 2P コネクタ**（電池） | BATパッドへの通電状態はんだ付けを無くす |
| **R1/R2: 220kΩ 分圧** → D5(GPIO6) | **VBUS検出**（README §9.5 / ELECTRICAL §2.1 の v2 方針そのまま） |
| **R3/R4: 220kΩ 分圧** → D0/A0(GPIO1) | **電池電圧監視**（同上） |
| **C1: 0.1µF** | 分圧の等価出力抵抗 110kΩ は ESP32-S3 の SAR ADC には高すぎるため必須 |
| **GNDスター点** | v1 の「黒線3本をより合わせる1点」(ELECTRICAL §3 #9) を基板ランドに置換 |

| 載せない | 理由 |
|---|---|
| **スライドスイッチ** | v1ではレバーが **+y（上面スロット）** を向く姿勢で固定されており、端子は −y に出る。<br>床に寝かせた基板には**原理的に載らない**（載せるならレバーをリッド側に向ける = 筐体全面改設計） |
| **LED + 220Ω** | LED はリッドに接着され、開閉のたびに配線が引かれる（余長60mm必須）。<br>基板側に引き込むと配線ランドが増えるだけで利得がない → v1 の空中配線を維持 |
| **XIAO 本体** | §4 参照。載せると高さ・BATパッド窓・ピン列ピッチの3つの問題が同時に出る |

### 2.2 部品配置（24穴中19穴使用・スクリプトが天井高さを assert）

r5  .    [ J1本体で潰れる ]     W:BAT-     y39.86

### 2.3 高さ予算（本タスクの主題）

CAD を実行して確認した実数:

```
$ python3 hardware/cad/mindclip_case.py
[layout] all interference checks passed
[layout] outer: 38.0 x 49.4 x 14.6 mm (W x H x D, lid込み)
```

- 内寸奥行 `ID = max(XIAO_LIFT 1.4 + XIAO_STACK_T 7.5 + 0.6, BOSS_H 1.4 + BAT_T + 1.8)`
  - allday: `max(9.5, 11.2) = 11.2` → **電池側が支配。XIAO側には 1.7mm の余裕がある**

- 案Dの基板は **XIAO の z に一切かからない**（左ゾーンの床に置く）ので、
  この式の値は変わらない → **外形 38.0 × 49.4 × 14.6 mm のまま。追加高さ 0.0 mm。**

## 3. 回路（v1配線への差分）

```
XIAO 5Vピン(=VBUS直結) ─── R1 220k ──┬── R2 220k ── GND        → 分圧 2.50V (max 2.62V)
                                     └── D5 (GPIO6, RTC GPIO)   = USB挿入検出

電池+ (J1 pin1) ────────── R3 220k ──┬── R4 220k ── GND        → 分圧 1.85V (max 2.12V)
                                     ├── C1 0.1uF ── GND
                                     └── D0 / A0 (GPIO1, ADC1_CH0) = 電池電圧監視

J1 pin1 ── 赤線 ── XIAO 裏面 BAT+ パッド
J1 pin2 ── 黒線 ── XIAO 裏面 BAT− パッド（= 基板GND）
```

スクリプトが計算する成立性:

| 項目 | 値 | 判定 |
|---|---|---|
| VBUS分圧の最大出力 | 5.25V × 1/2 = **2.62V** | ADC 12dB フルスケール ~3.1V / GPIO 絶対最大 3.6V に対し OK |
| 電池分圧の最大出力 | 4.25V × 1/2 = **2.12V** | OK（3.0V放電端で 1.50V。ADCの直線域） |
| 電池分圧の常時消費 | **8.4 µA** | deep sleep 3mA(公式typ) の **0.28%** → 無視できる |
| VBUS分圧の消費 | 11.4 µA（USB接続時のみ） | 充電中なので影響なし |
| 分圧の等価出力抵抗 | 220k∥220k = **110kΩ** | **ESP32-S3 の SAR には高すぎる → C1 必須** |

**ピン選定の根拠**（ELECTRICAL.md §1 の検証済みマップに従う）:

- `D0 = GPIO1 = ADC1_CH0`、`D5 = GPIO6 = ADC1_CH5`。どちらも **GPIO0〜21 = RTC GPIO** なので
  deep sleep からの EXT1 ウェイクに使える → **「USBを挿したら起きて同期する」が実装可能になる**
  （全体設計書§5のトリガが v1 で不可能だった問題が、これで閉じる）。
- `D2 = GPIO3` は**ストラッピングピン**なので使わない（ELECTRICAL §1）。
- `D8/D9/D10 = GPIO7/8/9` は microSD SPI で使用済み。`D6/D7 = GPIO43/44` は RTC GPIO ではない。
- 空きは `D4 = GPIO5` のみ（予備）。

**ファーム側の注意（申し送り）**:

1. **USB接続中の A0 は「電池電圧」ではなく「充電器の出力電圧」を読む**（BQ25101 の BAT 端子が
   4.2Vへ向かうため）。SOC推定は VBUS=LOW のときだけ有効にすること。
2. ADC は個体差が大きい。`esp_adc_cal`（eFuse校正）を使い、さらに多重サンプリング平均を取る。
3. 分圧を切り離すスイッチ（FET）は入れていない。8.4µA の常時消費を許容する設計。

## 4. 検討したが採らなかった配置

### 4.1 XIAO の下に敷く（案B/Cに近い形）

スクリプトが `XIAO_LIFT` を差し替えて評価した結果:

| variant | XIAO側の奥行き余裕 | 外形を変えずに XIAO下に置ける部品高さ |
|---|---|---|
| allday | 1.7 mm | **1.3 mm**（板1.0mm + 裏面逃げ0.8mm の後） |
| slim | 0.0 mm | **−0.4 mm（そもそも入らない）** |

- allday でも **1.3mm** では 0805 チップ部品しか載らない。手組みの利点（スルーホール部品を
  自由に挿せる）が消える。
- さらに **XIAO 裏面の BAT+/− パッドのはんだ盛り（1.0〜1.5mm突出）**を逃がす窓を、
  ガラスコンポジット基板に手で開ける必要がある（12×8mm程度）。カッターとピンバイスでは
  現実的でない。
- **XIAO のピン列2列の中心間距離が 2.54mm グリッドに乗るかは未検証**。基板外形 21.0×17.5〜17.8mm
  からの推定では 17.78mm = 7×2.54 の可能性が高い（キャステレーション穴の中心が基板端に来る）が、
  Seeed の推奨ランドパターンPDFは本環境から取得できなかった（**assumption**）。
  0.3mm ずれると 14 本のピンを全部曲げて挿すことになる。
- 加えて XIAO を基板に直はんだすると **¥2,660 のボードが取り外せなくなる**。
  「失敗しても作り直せる」という案Dの最大の利点を自ら捨てることになる。

→ **不採用。** XIAO を基板に載せたいなら、それは案B/Cの土俵であって、
ユニバーサル基板でやる話ではない。

### 4.2 サイド型コネクタ (S2B-PH-K-S, 高さ約4.8mm)

トップ型より 2.7mm 低く魅力的だが、**嵌合したプラグが水平に約7mm張り出す**方向が、
筐体内のどこにも取れない:

| プラグの向き | 干渉相手 |
|---|---|
| −y（電池側） | 電池 z3.0..11.0 に直撃 |
| +y（スイッチ側） | スイッチ z4.5..8.2 / 筐体上壁 |
| +x（XIAO側） | `xiao_stops` z1.6..8.1 → 抜けても XIAO スタック z3.0..10.5 |
| −x（左壁側） | 壁まで 1.9mm しかない |

**allday に限り**、基板の下段に置いてプラグを +y に出すと、プラグ天面 z8.2 < LED下端 z8.8 で
0.6mm 逃げられる（ケーブルは一度上に回してから電池側へ戻す）。slim は LED 下端が z7.1 まで
降りるので不可。→ **標準構成はトップ型 (B2B-PH-K-S) を採る。**

### 4.3 逆接保護回路を載せる

案Dの基板なら P-ch MOSFET やクロウバーダイオードを載せる余地はあるが、**採らない**:

- XIAO の BAT パッドは**充電と放電が同じ経路を双方向に流れる**。直列に素子を入れると
  BQ25101 の充電終止判定・電池検出に影響し得る（副作用が読み切れない）。
- 「逆接時に PCM を短絡保護で落とす」クロウバー（BAT+↔GND に整流ダイオード1本）は
  部品¥10・はんだ2点で実装できるが、**故障時に意図的にLiPoを短絡させる回路**であり、
  初心者向けドキュメントに載せる設計としては不適切と判断した。
- したがって案Dは「極性ミスを**検査可能・やり直し可能**にする」ところまでで止める（§6）。

## 6. 電池極性リスクは「消えない」— 正直な評価

案Dで **変わること**:

1. XIAO 裏面 BAT+/− へのはんだ付けが、**電池を繋ぐ前（＝無通電）**にできる。
   v1 は「充電済みの LiPo のリード線を、1mm角の SMD パッドに、こてを当てながら付ける」
   という**通電状態の作業**だった。これが消えるのは大きい。
2. はんだ付け後、**テスターの導通レンジで J1 の pin2 ↔ XIAO の GND ピンが導通することを
   確認できる**（無通電・非破壊の決定的な検査）。v1 には同等の事前検査が無い。
3. 間違えても**やり直せる**（線を付け替えるだけ、基板は無傷）。

案Dでも **変わらないこと**:

4. **ハウジングの結線が逆な電池を挿せば、その瞬間に XIAO は壊れる。**
   キー付きコネクタは「上下逆に挿せない」ことは保証するが、
   「中の配線が正しい」ことは保証しない。ELECTRICAL §5.2 が警告する
   「赤黒が逆の中華製セル」は、**プラグ付きセルでも同じ確率で存在する**。
5. したがって「テスターで電池プラグ側の極性を確認してから初めて挿す」という
   **運用ルールへの依存は残る**。逆だった場合はハウジングから端子を抜いて入れ替える
   （細いピンが要る・初心者には難しい）か、リード線を切って継ぎ直す（はんだ+2点）。

→ 本書は `removes_battery_polarity_risk = false` と評価する。
**リスクは大きく下がるが、構造的には排除されていない。**
排除したいなら、逆接保護を含むキャリア基板（案B/C）か、そもそもコネクタ付きの
充電回路を別に持つ設計が要る。

| XIAO: 5V / D0 / D5 ピン | 3 | 易 | **新規** |
| XIAO: D1 / D3 / GND ピン | 3 | 易 | 据置 |
| スイッチ 2端子 | 2 | 易 | 据置 |
| LED + 220Ω 空中配線 | 3 | 易 | 据置 |
| GND より合わせ分岐 | 1 | 易 | 据置 |
| **合計** | **約36点** | | **11 → 36（3.3倍）** |

**評価**: 1点あたりの難易度は下がる（グリッド穴に挿してランドに付けるのは、
空中配線より圧倒的に易しい）。しかし**総数が3.3倍**になり、
かつ **XIAO側が5点→8点**に増える。「はんだ付けを最小化する」という v1 の設計思想
（ELECTRICAL §3）とは正面から矛盾する。ここは案Dの明確なコストである。

## 8. リスク（致命的なものを先に）

1. **【再現性がない】** 手配線は毎回配線経路が変わる。ショート・イモはんだ・断線が
   筐体に入れた後は目視できない。**「READMEに書いて他人に組ませる」用途には不適**。
   本プロジェクトの成果物は組立ガイド（README）であり、案Dはその要件と衝突する。
2. **【slim の余裕が +0.2mm】** J1 の実装高さを 7.5mm と仮定した値（assumption）。
   実物が 7.7mm あれば slim は不成立。**allday を選ぶこと**を強く推奨。
3. **【24穴中19穴使用】** 設計余地がほぼ無い。配置を1つ間違えると穴が足りない。
   （ただし基板が¥50なので作り直しは安い＝これは案Dの利点でもある）
4. **【基板の切断】** ガラスコンポジット(CEM-3)は紙フェノールより硬い。1.0mm厚なら
   カッターで両面にスジを入れて折れるが、割れ・欠けが出やすい。金ノコ or 基板カッターが
   実質必要（「特殊工具を持たない」という前提と摩擦がある）。
5. **【基板裏面 0.8mm】** リードを面一に切り、はんだ盛りを抑える必要がある。
   初心者ははんだを盛りがちで、ここが v1 の BAT パッドと同じ「腕前依存」箇所になる。
   0.8mm を超えると基板が浮き、部品高さの余裕（slim +0.2mm）を食い潰す。
6. **【アンテナフィルムの居場所を奪う】** MECHANICAL §2 は「アンテナフィルムは XIAO 左の
   空間（スイッチ下・LED周辺）に貼る」としている。**そこが案Dの基板の位置そのもの**。
   基板上面か左壁内面へ移すか、オンボードアンテナ運用にする必要がある（要判断）。
7. **【LED配線余長60mm と J1 ケーブルの経路が競合】** どちらも左ゾーンを通る。
   MECHANICAL §7 の「リードは電池上面より下に収める」制約と合わせて、実機で要確認。
8. **【基板の固定方法が未定義】** 両面テープ想定。USB挿入力は受けないので軽荷重だが、
   ラトルとリード疲労の評価は未実施。
9. **【assumption が多い】** J1 の実装高さ・footprint、基板の実厚、裏面リードの残り、
   1/6W抵抗の寸法はすべて実測していない。**0.5mm狂うと slim は不成立**。
   allday は 1.7mm の余裕があるため、これらの誤差を吸収できる。
10. **【極性リスクは残る】** §6 の通り。

## 9. 「まず1台試す」段階での位置づけ（本タスクの主題への回答）

**現実解になり得る。ただし目的を限定した上で。**

案Dが強いのはこの4点:

- **高さ予算を1mmも消費しない。** 案の中で唯一、`mindclip_case.py` を触らずに済む
  （allday）。筐体を刷り直さなくてよいのは、3Dプリンタを持っていても実は大きい
  （body 7.9g / 数時間 + スナップ嵌合の再調整が発生する）。
- **納期が実質ゼロ。** 秋月の既存注文に4点足すだけ。海外PCBの2週間 × 試行回数が消える。
- **失敗の単価が¥50。** 配線を間違えたら新しく切って作り直せる。
  これは「ファームがまだ存在しない」（README §9.12）現状で決定的に効く。
  **VBUS検出のGPIO選定・分圧比・ADC校正・充電検出→同期のトリガ実装**は、
  どれもファームを書きながら回路を触りたくなる部分である。
- **v1で閉じられなかった2つの穴（VBUS検出・電池電圧監視）を両方閉じられる。**
  しかも ELECTRICAL §2.1 が v2 方針として書いた「220kΩ×2」をそのまま実装するので、
  設計判断の追加が要らない。

案Dが弱いのはこの2点:

- **再現性・ドキュメント化。** 36点の手はんだと24穴中19穴の詰め込みは、
  README §7 のような「この手順どおりにやれば組める」ガイドに落とせない。
- **極性リスクを構造的には消せない。** これは案Dの主目的にしない方がよい。
  むしろ v1 筐体で最も収まりが悪い部品がコネクタ（§4.2）である以上、
  「コネクタ化」は筐体側に余裕がある案B/Cで解くべき課題である。

### 推奨する進め方

```
案D で1台組む  →  ファームを書いて VBUS検出・電池電圧監視・充電トリガ同期を実機検証
                  （分圧比・ADC校正・ウェイク動作を実測で確定させる）
       ↓
確定した回路で 案B/C のキャリア基板を起こす（JLCPCB等）
       ↓
案B/C を README の正規手順にする（再現性・はんだ点数削減・逆接保護はここで解決）
```

案Dを**最終形**にするのは勧めない。**案B/Cの前段の実験台**として使うのが、
費用・納期・リスクのバランスが最もよい。
