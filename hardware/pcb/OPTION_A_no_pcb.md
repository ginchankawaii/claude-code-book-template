## 1. なぜ「今」基板を起こすべきでないか（案Aの主張）

### 1.1 寸法がまだ確定していない

[`../README.md`](../README.md) §9.1 の未検証寸法が **1つも実測されていない**:

| 未検証項目 | 現在値 | 基板設計に与える影響 |
|---|---|---|
| XIAO スタック総厚 | 7.5 mm（assumption） | **キャリア基板が入るかどうかを直接決める唯一の値** |
| PDMマイクの基板上位置 | assumption | 基板が音導経路を塞ぐか否か |
| XIAO 裏面 BATパッド位置 | assumption | 基板側の電池配線の出口 |
| 802530 の実寸・PCM位置・リード出射 | 公称値のみ | 基板の外形と電池室の取り合い |
| USB-C 座ぐりの実嵌合 | 未検証 | 基板が XIAO を +x に押すと即 NG |

**基板は「寸法が固まった後」の最適化であって、寸法を固める手段ではない。**
スタック厚 7.5mm が実測 8.3mm だった瞬間、slim の内寸 9.5mm は
リフト1.4 + 8.3 = 9.7 で**すでに破綻**する。この状態で $5 と 2週間を投じて基板を焼くのは順序が逆。

### 1.2 基板を作ると「XIAO をどう載せるか」の三択が必ず発生する

| 載せ方 | 追加高さ | 初心者可否 | 備考 |
|---|---|---|---|
| ピンヘッダ+ソケット | +8〜11 mm | ○ | **即死**（allday の空き 2.30mm）。MECHANICAL.md §7 が既に禁止 |
| XIAO を基板に直はんだ（14点） | +1.6〜2.5 mm | △ | slim 不可。しかも**はんだ点が 14点増える**ので目的と矛盾 |
| カステレーションSMD リフロー | +1.6 mm | ✗ | 特殊工具前提。前提ユーザー条件を外れる |

案Aはこの三択そのものを回避する。

### 1.3 反復コストがゼロ

分圧比を間違えた・LED が暗すぎた・スイッチ位置を変えたい——案Aなら**その晩に直せる**。
基板は 1反復 = 2週間 + $5。未検証項目が10件以上残っている段階では反復回数が読めない。

**lead time: 案A = 秋月/Amazon の着荷 3日 / 基板案 = 14日 + 手戻り時 +14日/回。**

## 2. 高さ予算の実測（CAD 実行結果）

`python3 hardware/cad/mindclip_case.py` および `MINDCLIP_VARIANT=slim` で実行し、
`check_layout()` の全 assert 通過・STL watertight を確認したうえでパラメータを読み出した値。

```
[allday]  外形 38.0 x 49.4 x 14.6 / 内寸 34.8 x 46.2 x 11.20 / body開口面 z=12.80
  XIAOスタック z 3.00 .. 10.50      ★ XIAO上の空き z = 2.30 mm
  XIAO下の逃げ空間 = 1.40 mm        電池上面 z=11.00 / lip帯 z 10.60..12.80
[slim]    外形 38.0 x 49.4 x 12.9 / 内寸 34.8 x 46.2 x  9.50 / body開口面 z=11.10
  XIAOスタック z 3.00 .. 10.50      ★ XIAO上の空き z = 0.60 mm
  XIAO下の逃げ空間 = 1.40 mm        電池上面 z= 8.00 / lip帯 z  8.90..11.10
```

**読み方（重要）**

- slim の内寸奥行き 9.50 は `XIAO_LIFT(1.4) + XIAO_STACK_T(7.5) + 0.6` で決まっており、
  **余裕 0.6mm のうち大半は「スタック厚 7.5mm が assumption であることへの保険」**。
  ここにキャリア基板を挟む余地は物理的にない。
- allday の 2.30mm も、FR4 0.8mm + 部品面のはんだフィレット 0.3 + 2階建てのための
  スペーサ/両面テープ 0.3 を積むと実質 1.4mm 相当が消える。残り 0.9mm では
  スタック厚の実測ブレ（±0.8mm 級）を吸収できない。
- **案Aの追加高さは 0.00mm**。受動部品は既存の空隙に入れる（§4.3）。

### 2.1 空きポケットの実容積

| 領域 | 座標 | 体積（粗） |
|---|---|---|
| 左ポケット（電池上端〜スイッチ下端、XIAO ストップリブより左） | x1.6–12.4 × y28.2–45.0 × z1.6–12.8 | **allday 2.03 cm³ / slim 1.72 cm³** |
| XIAO 裏面の逃げ空間 | 21.0 × 17.8 × **1.40** | 0.52 cm³（高さ1.4mm の制約が厳しい） |
| 電池左のリード曲げチャネル | 2.4 mm 幅 | AWG28 φ1.2 が2本並ぶだけで満杯 |

A-2 の追加部品（1/6W抵抗4本 + 熱収縮 = 0.15 cm³、JST嵌合体 ≈0.29 cm³）は
**体積上は左ポケットに収まる**。ただし同ポケットには既に LED 本体・LED余長60mm×2本・
スイッチ配線50mm×2本が入る。実占有は約 0.9 cm³ / 2.03 cm³ で、
**配線の詰め物としては実質満杯**（詰め物の充填率は 50–60% 程度が限界）。

### 3.3 JST化は「不可逆ミス」を消せるか — 正直な評価

**結論: 消せない。ただし「検出不能・修復不能」から「検出可能・修復可能」に落とせる。**

- v1: **充電済みのLiPoを持ったまま**小さなパッドにはんだ付けする。逆だと通電した瞬間に XIAO 死亡。
  作業中に確認する手段がない（すでにエネルギーが繋がっている）。
- A-1: ピグテールの**無通電のワイヤ**をパッドにはんだ付け →
  テスタ導通レンジで「コネクタの＋側 ↔ BAT+ パッド」を当てて確認 → 合っていたら電池を嵌合。
  **間違っていればはんだを外してやり直せる。壊れる前に気づける。**
- ただし**ピグテールを逆に付けたまま検査を省略すれば、初回嵌合で XIAO は死ぬ**。
  「フットプリント + シルク + 極性キーで物理的に不可能にする」ことは基板でないとできない。
  → 本評価では `removes_battery_polarity_risk = false` とする（過大主張を避ける）。
- 副次効果としてこちらの方が実務的に効く: **電池を抜き差しできるようになる**。
  筐体の嵌合調整で再印刷（README §9.3 は初回再印刷を前提としている）するたびに
  電池をはんだ付けし直す必要がなくなる。SD交換・分解・保管もコネクタを抜くだけ。

### 3.4 JST嵌合体の置き場所（筐体変更なしで成立することの確認）

- PH-2.0 2P 嵌合体 ≈ 11 × 5.8 × 4.5 mm。
- **電池上（z方向）には置けない**: allday の電池上空きは 1.80mm、slim でも 3.10mm（うち lip帯 2.2mm 使用不可）。
- **リード曲げチャネル（2.4mm幅）にも置けない**。
- → **左ポケットに Y方向に寝かせ、左内壁にホットボンドで点付け固定**する。
  **座標は採用後に更新された: x1.60–7.40 / y28.60–39.60 / z1.60–6.10**
  （左内壁に密着させる。本書執筆時の x3–12, y29–43 は、スイッチ端子（y40.5–45.0）と
  LED の曲げリードを CAD がモデル化していなかった時点の値で、**slim では実干渉する**）。

## 4. A-2: VBUS検出 と 電池監視 を空中配線で足す（**禁止。実装してはならない**）

> **この節は「なぜ空中配線で足してはいけないか」の根拠として残しています。**
> ここに書かれた組立手順・部品は**発注も実装もしないでください**（SCHEMATIC.md §0.1）。
> VBUS検出と電池電圧監視は、同じ回路をサテライト基板 `MC-SENSE-A` に載せて実現します
> （SCHEMATIC.md §9、MECHANICAL.md §11.2。allday なら筐体外形は 38.0×49.4×14.6mm のまま）。

### 4.1 VBUS検出は「外付け回路なし」では不可能（確認済み）

Espressif 公式（ESP-IoT-Solution / Self-Powered USB Device）の記載:

> The internal USB PHY of ESP32-S3 **does not support hardware detection logic**, so VBUS
> detection needs to be implemented by software with the help of ADC/GPIO …
> use a simple resistor voltage divider that outputs (0.75 × Vdd) if VBUS is 4.4V.

- `tud_mounted()` 等の USBスタック側の検出は「**ホストが列挙した**」ことしか分からず、
  ダム充電器（D+/D− に抵抗を置くだけ）では成立しない。本機の運用（USB充電器に挿す）では使えない。
- BQ25101 の /CHG ステータスは XIAO の基板上LEDに配線されており、外部ピンに出ていない。
  チップLED端をタップする改造は前提ユーザー条件（特殊工具なし・SMD 0805まで）を外れる。
- **したがって VBUS検出は、案A・案B のどちらでも「2本の抵抗」が必ず要る。**
  案Aの不利は「その抵抗をどこにどう留めるか」だけ。

### 4.2 回路（計算で裏取り済み）

XIAO の **5V ピンは USB VBUS 直結**（Seeed フォーラム: "The 5V pin is 5V out from the USB port"、
だから外部5V入力にはショットキーが要る、という文脈で確認）。

```
  5V(VBUS) ──[R1 220k]──┬──[R2 330k]── GND        → D0 (GPIO1) : VBUS検出
                        └─→ D0
  BAT+ ─────[R3 220k]──┬──[R4 220k]── GND         → D4 (GPIO5) : 電池電圧監視 (ADC1)
                       └─→ D4
```

| 分圧 | VBUS/BAT | 出力 | 判定 |
|---|---|---|---|
| R1 220k / R2 330k | 4.40 V | **2.640 V** | ok（VIH=0.75×3.3=2.475V をクリア） |
| 〃 | 5.00 V | 3.000 V | ok |
| 〃 | 5.25 V | **3.150 V** | ok（3.3V を超えない） |
| 〃 | 消費 | 8.0–9.5 µA | deep sleep 3mA(typ) の 0.3% |
| R3/R4 220k/220k | 3.0–4.2 V | 1.500–2.100 V | ADC1 12dB減衰のレンジ内 |
| 〃 | 消費 | 9.5 µA（1週間 1.60 mAh） | 同上、無視可 |

- **220k/220k（1:1）は不可**: VBUS 4.4V で 2.200V となり VIH を割る。実測して回避済み。
- **180k/220k も不可**（4.4V→2.420V）。E24 標準値では **220k/330k が実質唯一の解**。
- 電池分圧の Thevenin 抵抗は **110kΩ** で ESP32 ADC の推奨源インピーダンスを超える。
  **0.1µF のバイパスコンデンサが実質必須**（+2点）。省く場合は多重サンプリング＋
  初回読み捨てで運用し、精度は残量「警告」レベル（±100mV 程度）に割り切る。

### 4.3 ウェイクアップ設計（追加部品ゼロで解決できる）

ESP32-S3 の EXT1 は `ANY_LOW` / `ANY_HIGH` のいずれかで、**ピンごとに極性を混在できない**（ESP-IDF公式）。
スイッチON = LOW、VBUS有 = HIGH なので EXT1 単独では両立しない。

- **採用案**: スイッチは従来どおり **EXT0（GPIO2, LOW）**、VBUSは **タイマウェイク 30秒ポーリング**。
  Sense装着時の deep sleep は 3mA(typ) と元々大きいため、30秒ポーリングの増分は無視できる。
  設計書の「充電開始をトリガに同期」は**最大30秒遅延**で成立する（実害なし）。
- EXT0 と EXT1 の同時有効化（極性違い）が S3 で成立するかは**未検証**。成立すれば即時ウェイク可。
- **どちらもハードウェアの追加を伴わないため、案A/案B の優劣に影響しない。**

### 4.4 A-2 のはんだ点（17点）

A-1 の 9点 に加えて:

| # | 箇所 | 導体数 | 難易度 |
|---|---|---|---|
| 10 | XIAO **5V** ピン ← 紫 | 1 | 易 |
| 11 | XIAO **D0** (GPIO1) ← 緑 | 1 | 易 |
| 12 | XIAO **D4** (GPIO5) ← 白 | 1 | 易 |
| 13 | R1 自由端 ← 紫（5V線） | 2 | 中 |
| 14 | **node V**: R1 + R2 + 緑（D0線） | **3** | **難（空中3端子）** |
| 15 | R3 自由端 ← BAT+ タップ（ピグテール赤の中間被覆剥き） | 2 | 中 |
| 16 | **node B**: R3 + R4 + 白（D4線） | **3** | **難（空中3端子）** |
| 17 | **GNDスプライス**: R2 + R4 + GND戻し線 | **3** | **難（空中3端子）** |

- ADC バイパス 0.1µF を入れると **19点**。
- **v1 では空中3端子スプライスは1箇所（GND分岐）だった。A-2 では 3箇所になる。**
- XIAO に付くリード線は **3本 → 8本**（BAT+/BAT−/D0/D1/D3/D4/GND/5V）。
  AWG28 φ1.2 が 8本、並べ幅 9.6mm。**裏面の逃げ空間は 1.40mm しかないので、
  1本でも重なった瞬間（2本重ね = 2.4mm）に基板が浮き、USB-C が開口とずれる。**
  MECHANICAL.md §2 の「両面テープ固定は必須」要求と正面衝突する故障モード。

## 6. 組立手順への影響（README §7 との差分）

> **この差分は [`../README.md`](../README.md) §7 に反映済み**（手順4・手順5・手順8 を改訂）。

1. 手順8「電池を XIAO にはんだ付けする（最重要）」が
   **「ピグテールをはんだ付け → テスタで極性導通確認 → 電池を嵌合」**に分割される。

5. （A-2のみ）XIAO に付く線が 8本になるため、「裏面の線を重ねずに1層で敷く」という

## 8. 判断基準 — いつ案Aを捨てるべきか

案Aを推す立場からでも、以下のいずれかに該当したら**基板案に移るべき**:

1. **実測でスタック厚が 7.5mm を下回った**（例 6.8mm）→ slim にも基板を挟む余地が生まれ、
   案Aの最大の勝ち筋（高さゼロ）が消える。
2. **同じものを3台以上作る／他人に作らせる／書籍の作例にする** → R8（再現性）が支配的になる。
3. **VBUS検出と電池監視が「あったら嬉しい」ではなく必須要件に昇格した** →
   A-2 の 17点・3スプライスを飲むより、基板の方が安全側。
4. **極性ミスによる XIAO 破損を設計で排除することが要件になった** → R3 は案Aでは原理的に残る。
