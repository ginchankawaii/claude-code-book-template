## 0. この文書の位置づけ（最初に読む）

### 0.1 採用構成と不採用構成

| 構成 | 内容 | はんだ点 | VBUS検出 | 電池監視 | 判定 |
|---|---|---|---|---|---|
| v1（現行） | 電池をBATパッドへ直はんだ・GNDより合わせ分岐 | 11 | ✗ | ✗ | 置換される |
| **A-1（本書の採用回路）** | 電池をJST-PH2.0化・GNDデイジーチェーン化 | **10**（※） | **✗** | **✗** | **採用** |
| ~~A-2~~ | A-1 + VBUS検出・電池監視を**空中配線**で追加 | 17〜19 | ✓ | ✓ | **不採用（禁止）** |
| v2-SENSE | 同機能を**案Dのサテライト基板**に載せる | +約20（基板ランド） | ✓ | ✓ | 将来（§9のゲート通過後） |

> ※ **はんだ点は 9 ではなく 10。** 案A-1 の当初案は「抵抗内蔵LEDで 220Ω を廃止して 9点」だったが、
> 内蔵抵抗値が非公開（assumption）のため **1台目のデフォルトを v1 と同じ 220Ω＋OSR5JA3Z74A に戻した**（§4.2）。
> その結果 A-1 の削減は **11 → 10 の −1点**になる。**減るのは「空中3端子スプライス（GNDより合わせ分岐）」であり、
> これが A-1 の本質的な利得**（点数ではなく接合形態が良くなる）。抵抗内蔵LEDを選べば 9点になる。

> **A-2（空中配線での分圧追加）は本プロジェクトでは実装しない。**
> 理由: 3端子の空中スプライスが1→3箇所に増え、常時振動＋リッド開閉の引張を受ける
> 装着デバイスで最も壊れやすい接合形態になる。しかも断線時の症状が「機能が効かない」ではなく
> 「GNDが浮く」等の不定故障になり得る。さらに左ポケットの自由体積（MECHANICAL §7 の
> 「リード・余長は電池上面より下」制約下で **allday 1.84cm³ / slim 1.24cm³**）に対し
> A-2 の所要は 1.28〜1.62cm³ で、**slim では 103〜131% = 物理的に入らない**。
> **VBUS検出・電池監視が必要になった時点で、§9 のサテライト基板に載せ替える。**

### 0.2 したがって、本書の「機能フラグ」は次のとおり

```
v1.5 (A-1) として出荷する回路:   closes_vbus_detect = false
                                 closes_battery_monitor = false
                                 removes_battery_polarity_risk = false （§5.4 の手順で低減するのみ）
```

§6〜§7 に VBUS検出回路と電池監視回路の**完全な設計値**を載せるが、これは
**「v1.5 では実装しない、v2 でサテライト基板に載せる回路」**の設計であり、
v1.5 の組立手順には現れない。1つの文書に「組める道」と「組めない道」を同居させないため、
**§6・§7 は見出しに `[v2 / 非実装]` を付けて明確に隔離している。**

### 0.3 案Aは v1 を確定させるための構成であって、最終形ではない

本リポジトリは書籍テンプレートであり、「他人に作らせる」性質を既に半分持っている。
**手配線は再現性で基板に原理的に劣る**（同じ人が2台作っても配線長と引き回しが変わる）。
案Aを採る理由は「基板より良いから」ではなく、
**README §9.1 の未検証寸法（XIAOスタック総厚7.5mm・BATパッド位置・802530実寸・USB-C嵌合）が
1つも実測されておらず、基板は寸法が固まった後の最適化だから**である。離脱条件は §9.4。

## 2. XIAO ESP32S3 Sense のピン割当と衝突検証

### 2.1 一次資料で確認した「使えないGPIO」

| 機能 | GPIO | 確認方法（一次資料） |
|---|---|---|
| PDMマイク CLK | **GPIO42** | Seeed公式wikiリポジトリ `Seeed-Studio/wiki-documents` の `XIAO_ESP32S3_Sense_mic.md` に `I2S.setPinsPdmRx(42, 41); // setup 42 PDM clock and 41 PDM data pins` を実確認 |
| PDMマイク DATA | **GPIO41** | 同上 |
| microSD SCK | **GPIO7** | `espressif/arduino-esp32` の `variants/XIAO_ESP32S3/pins_arduino.h` を実取得: `SCK=7 / MISO=8 / MOSI=9`（拡張ボードのSDは既定SPIに接続） |
| microSD MISO | **GPIO8** | 同上 |
| microSD MOSI | **GPIO9** | 同上 |
| microSD CS | **GPIO21** | 同wikiのSD例が `SD.begin(21)`。`pins_arduino.h` で `LED_BUILTIN=21` も確認 → **内蔵ユーザーLEDとCSが共用** = 外付けLEDを使う電気的根拠（ELECTRICAL §1.1 の記述を一次資料で裏取り） |
| カメラ | GPIO10–18, 38–40, 47, 48 ほか | カメラモジュールは取り外して未使用（コネクタから抜くだけ） |
| ストラッピング | GPIO0 / **GPIO3** / GPIO45 / GPIO46 | ESP32-S3 の仕様。外部14ピンに出ているのは **GPIO3 = D2** のみ |

> GPIO41/42 は外部14ピンに出ていない（拡張ボード内部のB2B経由）ため、**外部配線と物理的に衝突しない**。
> GPIO7/8/9 は D8/D9/D10 として外部にも出ているので、**ここに何も繋がないことが衝突回避の条件**になる。

ADC1 のチャネル対応（GPIO1→ADC1_CH0 … GPIO10→ADC1_CH9）は ESP-IDF の
`ADC1_GPIOn_CHANNEL` マクロ定義で確認。**ADC2 は WiFi 使用中に使えないため一切使わない。**

### 2.3 選定理由

1. **`SW_IN`=D1(GPIO2)、`LED_DRV`=D3(GPIO4)** … v1 から変更しない。両方 RTC GPIO（≤21）なので
   deep sleep からの EXT0/EXT1 ウェイクに使える。配線図で同じ列に並び、初心者が数え間違えにくい。
2. **`VBUS_SENSE`=D0(GPIO1)** … RTC GPIO かつ **ADC1_CH0**。デジタル閾値（VIH）に頼らず
   ADC で判定できるため、抵抗公差のマージン不足という失敗モードを設計から消せる（§6.3）。
3. **`VBAT_SENSE`=D4(GPIO5)** … **ADC1_CH4**。ADC2 を避けつつ、唯一の予備 `D5` を残せる。
4. **D2(GPIO3) を空けたままにする** … ストラッピングピンに分圧を付けると起動時に中間電位が
   かかる。ADCが1本足りなくなっても、ここだけは使わない。

### 2.4 既知の排他条件（申し送り）

- `D4`(SDA) と `D5`(SCL) は I2C の既定ピン。**電池監視に D4 を使うと I2C は使えなくなる。**
  現設計に I2C デバイスは無く（ELECTRICAL §1.1）、増設予定も無いためこれを受け入れる。
- ADC が使える空きピンは D0 / D4 / D5 の **3本しかない**（D2は禁止、D8–D10はSD、D6/D7はADC非対応）。
  VBUS＋電池監視で2本使うと残りは D5 の1本。3つ目のアナログ入力が必要になったら
  外部 ADC（I2C）ではなく**設計の見直し**が必要になる。

## 3. スイッチ入力回路（v1.5 実装）

```
                    ESP32-S3 内部
                  ┌─────────────┐
   SW1 中央端子 ───┼──○ D1 (GPIO2) │
        │          │   ├─[R_pu 約45k]── 3V3   ← 内部プルアップ（外付け部品ゼロ）
        │          └─────────────┘
   SW1 片端端子 ─── GND     ← ON でここに短絡 = LOW = 録音
   SW1 反対端子 ─── 未接続（切り落とし）
```

| 項目 | 値 | 根拠 |
|---|---|---|
| プルアップ方式 | **内部プルアップ（外付け抵抗なし）** | 外付けにすると +2はんだ点。DCレベルのスライドスイッチであり、配線長 50mm・筐体内・低インピーダンス源のため内部45kΩで十分 |
| ON時のプルアップ電流 | 3.3V / 45kΩ = **73µA** | 録音時平均28mA目標に対し **0.26%** |
| OFF時 | **0µA** | スイッチ開放なのでプルアップに電流が流れない（deep sleep 中の増分ゼロ） |
| 論理 | ON = LOW = 録音 / OFF = HIGH = 同期→deep sleep | ELECTRICAL §2.3 |
| ウェイク | **EXT0（GPIO2, LOW検出）** | RTC GPIO。sleep 移行前に `rtc_gpio_pullup_en(GPIO_NUM_2)` が**必須**（通常GPIOのプルアップは deep sleep で無効化される） |
| チャタリング | **ソフト側で 20–50ms のデバウンス** | スライドスイッチは頻繁に操作されない。ハードのRC（0.1µF併用で τ=4.5ms）は不要 |
| 電源断にしない理由 | 電池ラインを切ると USB を挿しても充電できなくなる | ELECTRICAL §2.3（確定済み設計判断） |

**外部プルアップに切り替える条件**: 実機でチャタリング/誤ウェイクが観測された場合のみ、
サテライト基板側に 10kΩ プルアップ + 0.1µF を追加する（v1.5 のハーネスには追加しない）。

## 4. LED駆動回路（v1.5 実装）

```
   D3 (GPIO4) ──[R1 220Ω 1/4W]──▷|── GND
                 LED_DRV   LED_A  D1 (OSR5JA3Z74A 赤・3mm)
```

### 4.1 電流計算

| Vf | 電流 I=(3.3−Vf)/220 | 抵抗の消費 I²R | LEDの消費 |
|---|---|---|---|
| 1.9V | 6.36 mA | 8.9 mW | 12.1 mW |
| **2.0V（採用値）** | **5.91 mA** | **7.7 mW** | 11.8 mW |
| 2.1V（データシートtyp） | 5.45 mA | 6.5 mW | 11.5 mW |

- GPIO の吐き出し定格 40mA に対し **15%**。ESP32-S3 の推奨駆動範囲内。
  - **この表は VOH = 3.3V を仮定している（条件付き）**。データシートの規定は
    **VOH ≥ 0.8×VDD = 2.64V**、また 40mA は `PAD_DRIVER=3` 条件の値である
    （Arduino の既定ドライブ強度は 3 ではない）。規格最悪 VOH=2.64V なら Vf=2.0V で
    **2.9mA** まで落ち、PWM デューティ 10% だと平均 **0.29mA** になり
    「点いているのか分からない」水準になり得る。
  - したがって **デューティを机上で決めない**。README §8.2 テスト1 で実際の明るさと
    （可能なら R1 両端電圧から換算した）実電流を確定させてから決めること。
- 抵抗の定格は **1/4W**（消費 7.7mW → 余裕 32倍）。1/2W品は空中配線で大きすぎるため不可（ELECTRICAL §1.2）。
- 「微灯」要件は**ハードを変えずファームの LEDC(PWM) デューティ 10–20%** で実現（平均 0.59–1.18mA）。

### 4.2 抵抗内蔵LED を 1台目のデフォルトにしない（判定の変更点）

案A-1 の当初案は「抵抗内蔵LED（秋月 116692 OSR5JA3134A-5V）に置換してはんだ −1点」だったが、
**1台目のデフォルトからは外す**。

- 理由: **内蔵抵抗値が非公開（assumption）**。5V用を 3.3V で駆動したときの実電流は
  **4〜9mA と推定するしかなく**、暗すぎた場合に 220Ω 版へ戻す手戻りが発生する。
  1台目の完成率を未検証部品の一発勝負に賭けない。
- 位置づけ: **「2台目以降で試す、はんだ −1点の任意置換」**に格下げ（BOM の任意欄）。
- **代償を正直に書く**: この判断により A-1 のはんだ点は 9 → **10点**に戻る（§1.4）。
  それでも採る理由は、1台目の完成率を「内蔵抵抗値が非公開の部品」に賭けないため。
- 電気的には `LED_DRV` と `LED_A` が1ネットに縮退し、`R1` が消えるだけ。ネットリストの
  `netlist.json` では `R1` を `populate: true`（採用）、抵抗内蔵LED版を
  `alternates` に記載している。

## 5. 電池・充電系（v1.5 実装）

### 5.1 系統

```
  [LiPo セル + PCM]--(赤)--[PH2.0 プラグ]==[PH2.0 ピグテール J1]--(赤)--> XIAO 裏面 BAT+ パッド
   BT1 802530/502530  (黒)                                        (黒)--> XIAO 裏面 BAT− パッド
                                                                          └ 内蔵 BQ25101 が充電/給電
```

- 充電IC: **TI BQ25101 内蔵**、充電電流 **50mA(Fast) / 3.8mA(Trickle) 固定**（ELECTRICAL §2.1）。
  外付け部品は不要で、本回路は充電経路に一切介入しない。
- `/CHG` ステータスは XIAO 基板上の赤LEDに配線済みで**外部ピンに出ていない**。
  よって「充電中かどうか」をファームが知る唯一の手段は §6 の VBUS 検出になる。

### 5.2 電池コネクタの選定理由

| 候補 | 嵌合体サイズ | 定格 | 圧着工具 | 判定 |
|---|---|---|---|---|
| **JST PH 2.0mm 2P（採用）** | 約 11.0 × 5.8 × 4.5mm | 2A | **不要**（プリクリンプのピグテール品が流通） | **採用**。LiPoセル側の既定コネクタで、そのまま嵌合できる個体が多い。極性キー付きで上下逆に挿せない |
| JST SH 1.0mm 2P | 約 6 × 4 × 3mm | 1A | 必要（極細） | 不可。初心者が扱うには接点が小さすぎ、リード径も AWG28 が通らない |
| Molex PicoBlade | 同程度 | 1A | 必要 | 不可（専用工具） |
| JST XH 2.5mm 2P | 約 14 × 7 × 8mm | 3A | 必要 | 不可。**高さ8mm** は左ポケット（床から天井まで allday 11.2mm）に対し大きすぎ、電池上には置けない |
| 直はんだ（v1） | 0mm | — | 不要 | **置換対象**。充電済みLiPoを持ったままパッドにこてを当てる不可逆作業 |

- 電流的な裏取り: WiFi送信の瞬時ピーク 300mA超（ELECTRICAL §2.2）に対し PH の 2A は **6倍以上の余裕**。
- **キーは「上下逆挿し」しか防げない。** 中華セルの赤黒逆結線はプラグ付きでも同確率で存在するため、
  §5.4 のテスタ確認が必須ゲートになる。

#### 5.2.1 【購入条件】セル側に PH2.0 プラグが付いていること（必須）

A-1 は「セル側の PH2.0 プラグと嵌合する」ことに全面的に依存している。したがって
**BT1 の購入条件に「JST-PH 2.0mm ピッチ 2P プラグ付き」を必須で入れる**こと
（`bom.md` #2 / README §5.2）。「リード線が付いていればよい／コネクタは切り落として使う」は
**この構成では成立しない**。

**バラ線セル／XH・SH プラグ付きセルが届いた場合のフォールバック**:

| 届いた物 | 対処 | 代償 |
|---|---|---|
| **PH2.0 プラグ付き** | そのまま嵌合（本線） | — |
| **XH(2.5mm) / SH(1.0mm) プラグ付き** | プラグを根元で切り落とし、PH2.0 ピグテールの反対側と**セル側で継ぐ**。継ぐ前に §5.4④ を先に実施して＋側を確定する | はんだ **+2点（充電済みセルを持ったままの通電作業）**。両端に熱収縮を先通しし、1本ずつ、短時間で |
| **バラ線（コネクタ無し）** | 同上 | 同上 |
| **上記を避けたい場合** | **セルを買い直す（¥1,000前後）。これが最も安全で推奨** | 納期のみ |

> フォールバックに入った時点で A-1 の目的（不可逆・通電はんだの排除）は部分的に失われる。
> **セルは必ず「PH2.0 プラグ付き」と明記された商品を買うこと。**

#### 5.2.2 コネクタの性別（どちらを XIAO 側にするか）

- **XIAO 側（ピグテール）= コンタクトが奥まった受け側**、**セル側 = 相手側**にする。
- 理由: 嵌合前に**常時 4.2V で帯電しているのは電池側**である。電池側の露出コンタクトを
  減らす向きに選ばないと、電池を外した状態で工具や電池パウチのタブが触れて短絡する経路ができる。
- 市販の「オス・メス組」は **2本入り**なので、**セルが届いてから嵌合する側を選び、余りは予備**にする。
- `netlist.json` の `components[].J1` に `gender` フィールドとして記録した。

#### 5.2.3 コネクタ化の代償（v1 には無かった故障モード）

主電池経路に**嵌合部を1つ新設する**以上、装着デバイス特有の
**「振動での瞬断 → リセット／録音ファイル破損」**という故障モードが新しく生まれる。
§5.2 の比較表は PH の利点しか並べていないので、ここに明記する。

- 対策1: 嵌合体そのものを左内壁へホットボンドで点付けする（§5.5）。
- 対策2: **ケーブル側も別途固定して、嵌合部に引張が伝わらないようにする**。
  ピグテールを左内壁に沿わせ、嵌合体から 5–10mm の位置でホットボンドを1点。
  ハウジングだけ固定してケーブルが自由だと、引張はそのままコンタクトに集中する。

### 5.3 `BATN` と `GND` の関係（未確認の前提）

- 本設計は「XIAO の **BAT− は内部で GND と同電位**」を前提にしている。成立すれば
  `BATN` と `GND` は同一ネットで、電池側の配線は実質「＋を間違えないこと」だけになる。
- **これは未検証（assumption）。** §5.4 の手順②で必ずテスタ確認すること。
  導通しなかった場合は `BATN` を独立ネットとして扱い、ネットリスト（`netlist.json` の
  `expected_shorted_to` フィールド）を実測結果で更新する。

### 5.4 【必須手順】電池を嵌合する前のテスタゲート（省略禁止）

> **A-1 の不可逆リスク低減は、この1手順に全面的に依存している。**
> 省略すれば v1 と同じ確率で XIAO（¥2,660）が復旧不能に壊れる。
> README §7 手順8 に「推奨」ではなく**必須手順**として組み込むこと。

ピグテール（J1）を BAT+/BAT− パッドにはんだ付けした**直後、電池を嵌合する前**に、
テスタで次の4点を確認する。**1つでも不一致なら嵌合しない。**

| # | 測定 | 期待値 |
|---|---|---|
| ① | J1 コネクタの **＋側** ↔ XIAO 裏面 **BAT+ パッド** | 導通（ブザー鳴る） |
| ② | J1 コネクタの **−側** ↔ XIAO の **GNDピン** | 導通（＝BAT−とGNDが内部で同電位であることの確認も兼ねる） |
| ③ | J1 の ＋側 ↔ −側 | **短絡していないこと**（ブザーが鳴らない。数十kΩ以上） |
| ④ | **電池プラグの「コンタクト位置」の極性**（下記の手順。DCVレンジ） | 電池側で **＋を示したコンタクト位置**が、嵌合したときに **J1 の pin1（`netlist.json` で `BATP` に割当）と向かい合う**こと |

**④の測り方（①②③では検出できない故障モードを潰すための手順）**:

1. 電池プラグを**キー（ラッチのある面）を上にして固定**する。
2. DCV レンジで、プラグの**2つのコンタクト位置**（ハウジングの穴）にプローブ先端を当て、
   **どちらの「位置」が ＋か**を読む（+3.5〜4.2V 側が＋）。
3. 同じ向き（キー上）で、ピグテール側の **pin1 = `BATP`（①で BAT+ パッドと導通した線）**が
   どのコンタクト位置にいるかを確認し、**2 と 3 が嵌合時に向かい合う**ことを確かめる。

> **なぜ「線の色」でも「どちらのリードが＋か」でもいけないのか。**
> ①②③はピグテール↔XIAO 側しか見ておらず、**セル側ハウジングの中でコンタクトが
> 左右逆に入っている個体**（§5.2 の「プラグ付きでも同確率で存在する」個体）は
> **①②③④'（＝どちらかのリードが＋であること）を全部通過したうえで逆給電になる。**
> 見るべきは「色」でも「リードの＋／−」でもなく、**キーを基準にしたコンタクト位置**である。
>
> なお **README §7 手順5-4（配線前に、セルを嵌合した状態でピグテール自由端の電圧を測り
> ＋に印を付ける）を正しく行っていれば ④ は必ず一致する**（同じ電流経路を別経路で測って
> いるだけ）。**一致しないなら、どちらかの測定が誤っている**ので両方やり直す。
> プラグの穴にテスタ棒が入らない場合は、細い単線をコンタクト穴に差してそこを測る。

**④が不一致だったときの処置（電池側は触らない）**:

- **セル側のコンタクトは抜かない**（充電済みセルの端子を扱うのは危険）。直すのは**ピグテール側**。
  1. **ピグテール側ハウジングのコンタクトを抜いて左右入れ替える**（ランスを細ピンで押しながら
     電線を引く → カチッと鳴るまで差し直す）。**入れ替えたら ①〜④を全部やり直す。**
  2. できない／自信がない場合は、**ピグテールを根元で切って ＋と− を入れ替えてはんだ付けし直す**
     （無通電なので安全。J01/J02 のやり直し）。
- **中止条件**: ②が鳴らない（BAT− と GND が同電位でない個体）／プラグのコンタクトに
  テスタ棒が届かず ④ が測れない／上記の処置ができない —— このいずれかなら**嵌合しない**。
  ここで止まるコストは数百円、進むコストは XIAO ¥2,660 と発火リスクである。

- XIAO 裏面のBATパッドの向き（**−がUSB-Cコネクタに近い側、＋が遠い側**）は Seeed公式wiki記載。
  `wiring.svg` にも反映済み（ELECTRICAL §5.2）。
- ①②が通れば、以後は**コネクタを抜き差ししても極性事故は起きない**。
  筐体の嵌合調整で再印刷するたびに電池をはんだ付けし直す必要もなくなる。

**⑤⑥ スイッチ側の検査（J07 の2導体接合を作った直後・同じく省略禁止）**

A-1 は `SW1.1` に黒線を2本盛る（§5.7）。SS-12D00 系の端子ピッチは **2.54mm** で、
隣は `SW_IN` が付く `SW1.2` である。はんだ量が増える分**ブリッジ確率は v1 より上がる**。

| # | 測定 | 期待値 | ブリッジしていると何が起きるか |
|---|---|---|---|
| ⑤ | スイッチ **OFF 位置**で `SW1.2` ↔ `SW1.1` | **非導通**（ブザーが鳴らないこと） | 導通していると `D1`(GPIO2) が恒久 LOW＝**常時録音・deep sleep に入らない**。破壊はしないが半日で電池が空になり、v1 唯一の同期トリガ「スイッチOFF」も死ぬ |
| ⑥ | `SW1.1` ↔ `SW1.2` を**ルーペで目視** | はんだが端子間を橋渡ししていないこと | 同上。⑤だけだと接触抵抗の高いブリッジを見落とす |

- ON 位置で `SW1.2` ↔ GND が導通することの確認（従来の `TP_SW`）も併せて行う。
- ⑤⑥は「壊れないが完成に見えて動かない」故障を潰す検査であり、④とは目的が違う。

### 5.5 【必須】JST 嵌合体の向きと置き場所（筐体無改造で成立させる条件）

CAD の AABB 検算で確定した唯一の成立配置。**「左ポケットに寝かせる」だけでは 1.5mm の失敗を招く。**

```
   嵌合体の占有: X 5.8mm × Y 11.0mm × Z 4.5mm   ← 必ず Y方向に長辺を向ける
   配置座標    : x 1.60..7.40 / y 28.60..39.60 / z 1.60..6.10（床置き・左内壁に密着）
   固定        : 左内壁（x=1.6 の面）へホットボンド点付け ＋ ケーブル側も別途固定
   ロール      : 断面 5.8 × 4.5 のうち **4.5 を高さ(z)**、5.8 を幅(x) にして寝かせる
```

> **座標は rev2 で変更した（旧: x3.0..8.8 / y31.0..42.0）。** 旧値は CAD が
> **スイッチの端子3本（y40.5..45.0）と LED の曲げリードをモデル化していなかった**
> 時点のもので、slim では端子との分離が 0.00mm（熱収縮込みで −1.35mm の実干渉）だった。
> 現在の CAD (`cad/mindclip_case.py`) は `sw_terms` / `led_leads` を持ち、
> 旧座標に戻すと `INTERFERENCE: sw_terms <-> harness_jst` で落ちる（MECHANICAL.md §11.4）。

- **X方向に寝かせてはならない**: x1.6..12.6 となり、利用可能幅 10.8mm（x1.6..12.4）を
  超過して `xiao_stops[0]`（x12.4..15.25, z1.6..8.1）と LED の曲げリード帯に干渉する。
- **LED 窓も rev2 で x6.9 → 9.8 へ移動した**（lid の再印刷が必要）。
  嵌合体の真上に LED があると、90°に曲げた LED リード（本体下面から 3mm 下がる＝
  allday z5.8 / slim z4.1）が嵌合体上端 z6.10 と **slim で 1.0〜2.0mm 干渉**する。
  左ポケットの y 方向には LED 帯の上下どちらにも 11.0mm の嵌合体が入らないため、
  **逃げられるのは x 方向だけ**（JST を左壁密着 + LED を右へ = 隙間 0.80mm）。
- **嵌合体の寸法上限**（CAD 実測。超えると assert が落ちる）:
  **高さ allday 8.7mm / slim 7.0mm、長さ(y) 11.6mm、幅(x) 5.8mm**。
- 電池上（z方向）には置けない（allday の電池上空き 1.80mm / slim 3.10mm、うち lip帯 2.2mm は使用不可）。
- リード曲げチャネル（幅2.4mm）にも入らない。
- 左 lip（x1.75–2.75, z>10.6 / slim z>8.9）を避ければ干渉ゼロ。
  **body と backplate の STL は v1.4 とバイト一致（変更なし）。lid だけ LED 窓が動くので再印刷する。**
- **部品到着後・配線前に「嵌合体を仮置きしてリッドを1回閉める」確認を行うこと。**
  ここは CAD の assert では守れず、実機でしか判定できない。

### 5.6 配線長・配色の指定

| ネット | 色 | 長さ | 備考 |
|---|---|---|---|
| `BATP` | 赤 | **40mm**（市販品の 100–150mm を必ず切り詰める） | XIAO 裏 BAT パッド → 左端チャネル → J1 |
| `BATN` | 黒 | **40mm** | 同上 |
| `SW_IN` | 青 | **50mm** | |
| `GND`（XIAO→SW） | 黒 | **50mm** | |
| `GND`（SW→LED） | 黒 | **allday 60mm / slim 45mm** | リッド開閉で引かれる |
| `LED_A` | 橙 | **allday 60mm / slim 45mm** | 同上 |

- **ピグテールを切り詰めるのは必須。** 100mm のままだと所要体積が枠を超え、
  150mm では allday でも成立しない。**40mm** は「XIAO 裏面 → 左端チャネル → 嵌合体」の
  経路長（実測 約28mm）に曲げ代を足した値。
- **slim の余長短縮も必須。** 左ポケットの自由体積は（JST 嵌合体・LED リード帯・
  スイッチ端子帯をすべて差し引いた 0.1mm ボクセル実測で）**allday 1.45cm³ / slim 1.15cm³**。
  ここに入る AWG28（φ1.2）は allday 300mm / slim 270mm で、充填率 50% 換算の占有は
  **allday 47% / slim 53%**（実用上限 50〜60%）。**slim で LED 側を 60mm のままにすると 59%**
  に上がって上限に張り付くため、**slim は 45mm に詰める**（＝リッドの開き角を制限する）。
- 電線は **AWG28（外径約1.2mm）**。**ピグテールも被覆込み外径 1.3mm 以下の品を買うこと**
  （市販の PH2.0 コード付き品は AWG26〜22 が混在する。太い場合は AWG28 に載せ替える）。XIAO 裏面の逃げ空間は **1.40mm しかない**ため、
  **裏面で線を重ねない（1層で敷く）**こと。1本でも重なると 2.4mm となり基板が浮き、
  USB-C が開口とずれて**充電不能**になる（MECHANICAL §2 の両面テープ固定要求と衝突する）。

### 5.7 【必須】GND デイジーチェーンのはんだ手順（J07・線同士の2導体接合）

スライドスイッチの片端端子には黒線が2本入る（XIAO GND から来る線 + LED カソードへ出る線）。

> **2本を先に撚る → 予備はんだ → 端子へ一度で流す。**
> 1本ずつ後付けすると、先に付けた線が溶けて外れる。初心者が最も繰り返しやすいループ。

中継点を **LEDカソード側ではなくスイッチ端子側**に置くのが要点（スイッチ端子は太く剛性があり、
LEDリードは細く 60mm 余長経由の引張を受けるため中継点に向かない）。

## 6. [v2 / 非実装] VBUS（USB挿入）検出回路

> **v1.5 では実装しない。** 実装する場合は §9 のサテライト基板に載せること。**空中配線は禁止。**

### 6.1 なぜ外付け分圧が必須か

- Espressif 公式（ESP-IoT-Solution / Self-Powered USB Device）: ESP32-S3 の内蔵USB PHY には
  **VBUS検出のハードウェアロジックが無い**。ADC/GPIO + 抵抗分圧で実装せよ、と明記されている。
- `tud_mounted()` 等の USBスタック側の検出は「ホストが列挙した」ことしか分からず、
  **ダム充電器（D+/D−に抵抗を置くだけの充電器）では成立しない**。本機の運用（USB充電器に挿す）で使えない。
- BQ25101 の `/CHG` は基板上LEDに配線され外部ピンに出ていない（§5.1）。
- → **VBUS検出は、基板を作っても作らなくても「抵抗2本」が必ず要る。**

### 6.2 分圧比の決定（E24 全探索の結果）

制約:
- **下限**: USB VBUS の規格下限 **4.40V** で、抵抗公差の最悪合わせ込みでも `VIH = 0.75 × 3.3 = 2.475V` を上回ること
- **上限**: USB の上限 **5.25V** で、最悪でも **3.30V（=VDD）を超えない**こと（絶対最大は VDD+0.3=3.6V だが VDD を設計上限とする）
- **電流**: 5.0V で 12µA 以下

E24 標準値（10k–910k）を全探索した結果、**±5% 品で成立する組合せは10通り**。
そのうち **最悪値が最良なのは比 0.600（2:3）のグループ**で、比を変えると余裕が単調に減る。
（下表は代表7組。全10組は `calc_circuit.py` の出力を参照。**案A-1 の当初文書が書いていた
「E24 では 220k/330k が実質唯一解」は誤りで、正しくは「比 0.600 のグループが最良」である。**）

| R2(上側) / R3(下側) | 比 | 最悪低 @4.40V | 最悪高 @5.25V | Rth | I @5.0V |
|---|---|---|---|---|---|
| 180k / 270k | 0.600 | 2.533V | 3.275V | 108k | 11.1µA |
| 200k / 300k | 0.600 | 2.533V | 3.275V | 120k | 10.0µA |
| **220k / 330k（採用）** | **0.600** | **2.533V** | **3.275V** | **132k** | **9.1µA** |
| 240k / 360k | 0.600 | 2.533V | 3.275V | 144k | 8.3µA |
| 270k / 390k | 0.591 | 2.493V | 3.228V | 160k | 7.6µA |
| 330k / 470k | 0.588 | 2.477V | 3.211V | 194k | 6.2µA |
| 470k / 680k | 0.591 | 2.494V | 3.230V | 278k | 4.3µA |

- **採用は 220k / 330k**。比 0.600 グループの中で、電流（9.1µA）と Rth（132kΩ）のバランスが最良。
  240k/360k は E24 だが 220k/330k より流通が薄い。
- **不可の例（重要）**:
  - **220k/220k（1:1）は不可** … 4.40V で最悪 **2.090V**、5.00V ですら最悪 **2.375V** で VIH を割る。
    案C・案Dが採用していた比であり、**この比では EXT1 のデジタルウェイクが成立しない**。
  - 180k/220k も不可（4.40V で最悪 2.311V）。

### 6.3 公差と判定方式（must_fix 反映）

| 抵抗公差 | 4.40V での最悪 | VIH 余裕 | 5.25V での最悪 |
|---|---|---|---|
| ±5%（カーボン） | 2.533V | **+58mV しかない** | 3.275V（< 3.3V OK） |
| **±1%（金属皮膜・推奨）** | **2.619V** | **+144mV** | 3.175V |

**判定方式は二段構えにする:**

1. **主系: ADC で読む（推奨）** — `D0` は **ADC1_CH0** なので、デジタル VIH に依存しない。
   閾値を **2.00V（VBUS換算 3.33V）**に置けば、±5% 抵抗でも判定は揺るがない。
   これで「公差58mV」という失敗モードが設計から消える。
2. **従系: EXT1 ANY_HIGH ウェイク** — こちらはデジタル VIH に依存するので、
   **±1% 抵抗を使う場合に限り有効**とする（§6.5）。

### 6.4 耐圧・レンジ・消費

| 項目 | 値 | 判定 |
|---|---|---|
| GPIO 絶対最大入力 | VDD+0.3 = **3.6V** | 最悪 3.275V < 3.6V。**ESDクランプは導通しない** |
| 設計上限 | VDD = 3.3V | 最悪 3.275V < 3.3V。OK |
| ADC1 12dB の推奨入力範囲 | 0–**3100mV** | 5.25V 時の 3.275V は**フルスケールを僅かに超えて飽和**するが、判定は「USB有り」なので実害なし（電圧値としては読まない） |
| 常時消費 | **9.09µA @5.0V / 9.55µA @5.25V** | **USB挿入中のみ流れる。電池からは1µAも流れない** |
| Thevenin 抵抗 | **132kΩ** | C2 = 0.1µF で τ = **13.2ms**、整定(7τ) **92ms** |
| USB非挿入時 | R3(330k) で GND に引かれ **0V** | 入力フロートなし |

- **【ファーム要件】`VBUS_SENSE` は 2.00V 閾値の二値判定にのみ使い、電圧値として読まない。**
  ADC1 12dB の推奨入力範囲は 0–3100mV だが、**線形領域の上端は約 2.9V**
  （Espressif `esp-iot-solution` の adc_range 文書）。`VBUS_SENSE` は公称 5.00V で 3.000V、
  5.25V で最悪 3.275V と線形域外に入るため、**VBUS の実電圧推定には使えない**。
  （`VBAT_SENSE` は最大 2.100V で線形域内なので、こちらは電圧として読んでよい。）
- 「電池からは1µAも流れない」は **未検証**。XIAO の 5V ピンが USB VBUS 直結であること自体は
  確認済みだが、電池駆動中に XIAO 内部から VBUS ネットへ漏れ電流があれば 550kΩ が常時吸う。
  v2 実装時に**電池駆動状態で 5V ピン電位と電池側電流を実測**すること。

### 6.5 ウェイクアップ設計（追加部品ゼロ）

ESP32-S3 の EXT1 は `ESP_EXT1_WAKEUP_ANY_LOW` / `ANY_HIGH` の**どちらか一方**で、
**ピンごとに極性を混在できない**（per-pin モード非対応のターゲットでは
`esp_sleep_enable_ext1_wakeup()` が `ESP_ERR_NOT_ALLOWED` を返す）。
スイッチ ON = LOW、VBUS 有 = HIGH なので、EXT1 単独では両立しない。

| 方式 | 内容 | 判定 |
|---|---|---|
| **採用** | SW = **EXT0（GPIO2, LOW）** / VBUS = **タイマウェイク 30秒ポーリング** | Sense装着時の deep sleep は元々 **3mA(typ)** と大きく、30秒ポーリングの増分は無視できる。全体設計書§5の「充電開始をトリガに同期」は**最大30秒遅延**で成立（実害なし） |
| 代案 | EXT0(LOW) + EXT1 ANY_HIGH の同時有効化 | S3 で成立するかは**未検証**。成立すれば即時ウェイク可 |
| 不可 | EXT1 に SW と VBUS を混在 | 極性混在不可のため原理的に不可 |

## 7. [v2 / 非実装] 電池電圧監視回路

> **v1.5 では実装しない。** 実装する場合は §9 のサテライト基板に載せること。

### 7.1 回路と分圧

```
   BATP ──[R4 220k]──┬──[R5 220k]── GND
                     ├──[C1 0.1µF]── GND
                     └──> D4 (GPIO5 / ADC1_CH4)     出力 = Vbat × 0.500
```

| 電池電圧 | 分圧出力 | ADC1 12dB 推奨範囲(0–3100mV) |
|---|---|---|
| 3.00V（PCMカットオフ近傍） | 1.500V | OK |
| 3.40V（警告閾値・推奨） | 1.700V | OK |
| 3.70V（公称） | 1.850V | OK |
| 4.20V（満充電） | 2.100V | OK |

- 1:1 を選ぶ理由: 4.2V を 2.1V に落とすと **ADC の推奨レンジの中央付近**に収まり、
  非線形が最も小さい領域を使える。3.1V 近傍に張り付かせない。

### 7.2 精度と校正（重要）

| 誤差要因 | ±5% 抵抗 | ±1% 抵抗 |
|---|---|---|
| 分圧比の誤差（電池電圧換算 @4.20V） | **±210mV** | **±42mV** |
| ADC 1LSB（12bit / 12dB） | 0.757mV（電池換算 1.51mV） | 同左 |
| ADC 自体の確度（eFuse校正後） | ±1〜2%（assumption） | 同左 |

- **分圧比の誤差は個体ごとに固定（系統誤差）**なので、**ファームの1点校正で消せる**:
  組立後にテスタで実電池電圧を測り、`VBAT_CAL = V_measured / V_adc` を NVS に保存する。
  これを行うなら ±5% カーボン抵抗で十分。行わないなら **±1% 金属皮膜を使うこと**。
- 目標精度は残量「**警告**」レベル（±100mV級）で足りる。ゲージ表示はしない。

### 7.3 常時消費と電池寿命への影響（試算）

| 項目 | 値 |
|---|---|
| 消費電流 | **9.55µA @4.20V / 8.41µA @3.70V** |
| 1日あたり | **0.229mAh** |
| 1年あたり | **83.6mAh** |
| allday 実効680mAh に対する比 | **1日 0.034% / 1年 12.3%** |
| slim 実効425mAh に対する比 | 1日 0.054% / 1年 19.7% |
| deep sleep 3mA(typ) に対する比 | **0.318%** |
| この分圧だけで電池を空にするのに要する時間 | allday 8.1年 / slim 5.1年 |

- **結論: 無視してよい。** LiPo 自身の自己放電（一般に 2–3%/月 = 24–36%/年）の方が桁で大きい。
- 分圧を MOSFET で切り離す回路は**採用しない**（部品とはんだ点が増える一方、
  削減できるのは 9.5µA = deep sleep の 0.3%）。

### 7.4 ファーム側に課される制約（回路から出る要求）

1. **整定待ち**: Rth 110kΩ × 0.1µF で τ=11.0ms。**ウェイク後 100ms 以上待ち、初回サンプルを捨てる**。
   VBUS側は Rth 132kΩ で τ=13.2ms（同様に 100ms）。
2. **多重サンプリング + eFuse校正**: `esp_adc_cal`（eFuse Two Point / Vref）を適用し、
   16〜64回平均を取る。110kΩ という高い源インピーダンスは ESP32 の SAR ADC の推奨を超えており、
   **C1 なしでは読みが暴れる（C1 は実質必須）**。
3. **USB接続中は SOC 推定を無効化**: VBUS 印加中は BAT+ が BQ25101 の充電出力（〜4.2V）に
   引かれるため、`VBAT_SENSE` は「電池電圧」ではなく「充電器の出力」を読む。
   **SOC 推定は `VBUS_SENSE` が LOW のときのみ有効**とすること。
4. **警告閾値**: 3.40V で警告（LED点滅パターン変更）、3.20V で録音停止＆deep sleep。
   PCM の UVLO（2.4–3.0V）に到達する前にソフトで安全側に倒す。

## 8. 保護設計

### 8.1 逆接続保護

| 版 | 方式 | 評価 |
|---|---|---|
| **v1.5（A-1・採用）** | **手順による保護**: ①JST-PH の極性キー（上下逆挿し不可） ②§5.4 の必須テスタゲート4項目 ③無通電状態ではんだ付け→検査→最後に嵌合 | **`removes_battery_polarity_risk = false`**。検出不能・修復不能 → 検出可能・修復可能に落とすだけ。手順を省略すれば壊れる |
| [v2 / 非実装] | **AO3401A（P-ch MOSFET）×2 の背中合わせ**（ソース突合せ・両ゲートGND） | 電気的に正しい唯一の解 |

**なぜ P-ch を1個で済ませてはいけないか（重要）**:
単体だと**ボディダイオードが充電方向に導通する**ため、逆挿しされたセルを内蔵充電ICが
**50mA で充電し続ける**（LiPo の逆充電＝発熱・膨張）。ソース突合せの2個構成なら
ボディダイオードが逆直列になり**双方向を阻止**できる。

- オン抵抗 2×50mΩ = 0.1Ω → WiFi送信の 300mA バーストで **30mV 降下**（許容）。
- **注意**: 放電終止 3.0V 時の Vgs = −3.0V における Rds(on) をデータシートで確認すること。
- **代償**: 保護FETは**主電池経路に直列**に入る。はんだ不良＝間欠断という
  ウェアラブル最悪の故障モードを2箇所増やす。**空中配線で実装してはならない理由でもある。**

> **【実装状況の明記】`MC-CARRIER-A` rev.A には Q1/Q2 を載せていない。**
> `pcb/LAYOUT.md` と `pcb/mindclip_carrier.kicad_pcb` に Q1/Q2 のフットプリントは**存在しない**。
> 理由は2つ:
> 1. キャリア基板でも BAT 経路は「窓 → ジャンパ線 → XIAO 裏面パッド」であり、保護FETは
>    **その空中ジャンパの途中に入る**ことになる。基板に載せる意味（シルク・キー・レジストで
>    誤りを物理的に防ぐ）が最も薄い場所であり、上記の「間欠断を2箇所増やす」代償だけが残る。
> 2. §5.3 の前提（`BATN ≡ GND`）が未検証のままだと、FET を入れる側（＋なのか−なのか）を
>    確定できない。実測してからでないとアートワークを描けない。
>
> よって **`removes_battery_polarity_risk` は v2（MC-CARRIER-A rev.A）でも `false` のまま**であり、
> 逆接続保護は **rev.B の要件**として §9.4 の離脱ゲート通過後に設計する。
> `netlist.json` の `optional_blocks.V2_REVPROT` にも同じ注記を入れてある。
> 「基板にすれば極性事故が消える」と書かないこと。

### 8.2 過放電・過電流・短絡

- **セル側 PCM（保護回路）内蔵が必須**（bom.md #2）。XIAO 内蔵の BQ25101 は充電制御ICであり、
  過放電・過電流・短絡保護は持たない（ELECTRICAL §5.1）。
- PCM 要求仕様: UVLO 2.4–3.0V、**連続放電 500mA(1C) 以上・瞬時1A程度を許容**
  （WiFi送信の瞬時300mA超バーストに対する要求）。
- ヒューズは別途設けない（PCM が過電流・短絡を担う）。

### 8.3 ESD・サージ

| 経路 | 露出 | 対策 | TVS |
|---|---|---|---|
| USB-C | あり（唯一の外部端子） | XIAO モジュール側の実装に依存（assumption） | 追加しない |
| LED ドーム（リッドから約2.7mm突出） | 樹脂のみ・**導体は露出しない** | エポキシ樹脂パッケージが絶縁。さらに `LED_DRV` には **220Ω が直列**に入り、GPIO への流入を制限 | 追加しない |
| スライドスイッチのレバー | 樹脂レバーのみ | 端子は筐体内 | 追加しない |
| 電池・信号線 | 全て筐体内 | — | 追加しない |

- **v1.5 では TVS/ESD ダイオードを追加しない。** 導体が外部に露出する箇所が
  USB-C しかなく、そこは XIAO モジュール側の領域だから。
- 組立時の人体帯電は手順で対処（金属に触れて放電してから作業。ELECTRICAL §5.4）。

### 8.4 絶縁・機械的保護（回路側からの要求）

- BATパッドのはんだ部と電池パウチの間に**ポリイミド（カプトン）テープ**を1枚挟む
  （突起はんだによるパウチ穿孔防止）。
- 全てのはんだ継ぎ目を**個別に熱収縮チューブ**で絶縁。
- XIAO 裏面の突出（はんだ盛り + AWG28 + カプトン）は **1.0〜1.5mm** 生じる。
  筐体の逃げは 1.40mm しかないため §5.6 の「線を重ねない」指定が必須。
- **[v2] 5V(VBUS)線を追加する場合**: 配色を専用色（紫）に分け、**電池リード・LED配線と同じ束に
  入れず、左内壁寄りではなく上壁寄りを通す**。GND や BATP と擦れた場合の故障が「即発熱」であり、
  保護が熱収縮チューブだけになる箇所を作らないこと。

### 8.5 テストポイント（基板がないので「測れる点」を定義する）

| TP | 実体 | 測るもの |
|---|---|---|
| TP_GND | XIAO の **GNDピン** | 全測定の基準 |
| TP_BATP | J1 の **＋側コンタクト**（嵌合前） | §5.4 ① |
| TP_BATN | J1 の **−側コンタクト**（嵌合前） | §5.4 ② |
| TP_SW | SW1 の中央端子(`SW1.2`) | 導通（ON でGND） |
| TP_LEDA | R1 と LED アノードの継ぎ目（熱収縮前） | LED点灯確認 |

**手順の順序が保護そのもの**: サブアセンブリ完成 → 全 TP をテスタで確認 →
USB給電で動作確認（README §8.2/§8.3）→ **最後に電池を嵌合**。

### 9.1 実装先は「案D のサテライト基板」であって空中配線ではない

- **slim では非推奨**（コネクタ天井余裕が +0.2mm しかない）。**allday 限定構成**とする。

### 9.2 サテライト基板に載せるもの（= `MC-SENSE-A`）

`J1`（電池コネクタをこちらに移設）/ `R2 220k` / `R3 330k` / `R4 220k` / `R5 220k` /
`C1 0.1µF` / `C2 0.1µF` / `J2`（XIAO へ出る6本のワイヤランド）

XIAO へ出る線は **BATP / BATN / D0 / D4 / GND / 5V の6本**。
**追加の4本（D0/D4/5V/GND）は XIAO 基板裏を通さない**こと（裏面の逃げは 1.40mm しかない）。
カステレーション側面はんだで**横（左方向）へ引き出す**。

- **GND スター点も BATP 中継ランドも、基板上では「ネット」になるので別部品として置かない。**
  `J2` の6ランドは配線ランドと**テストポイントを兼ねる**（10.0×15.6mm に TP を別置きする
  余地が無いため）。`GND / VBAT_SENSE / VBUS_SENSE / BATN / BATP / VBUS` の6ネットが
  全て露出しているので、**XIAO を繋ぐ前に基板単体で分圧比を測る**ことができる。
- 実体の設計は **[`LAYOUT.md`](LAYOUT.md)**、製造データは `pcb/gerber/mc-sense-a/`
  （Gerber RS-274X + Excellon + BOM/CPL）に生成済み。
  **ただし KiCad 本体の DRC は未実行**なので、LAYOUT.md §9.3 の手順を通すまで発注しないこと。
- 外形 10.0 × 15.6 × 0.8mm、**追加高さ 0.00mm・筐体CAD変更ゼロ**。
  **allday 専用**（slim は J1 嵌合体＋電線曲げ代 12.30mm がリッド内面 11.10mm を超える）。

### 9.4 案Aを捨てて基板へ移る条件（離脱ゲート）

1. **実測スタック厚が 7.5mm を明確に下回った** → slim にも基板を挟む余地が生まれる
2. **3台以上作る／他人に作らせる／書籍の作例にする** → 再現性が支配的になる
3. **VBUS検出・電池監視が必須要件に昇格した** → §9.1 のサテライト基板、または キャリア基板へ
4. **極性ミス破損を設計で排除することが要件化した** → 手順依存では原理的に残る

**実測の順序（最重要）**: 内寸奥行は `ID = max(XIAO側 XIAO_LIFT+8.1, 電池側 BOSS_H+BAT_T+1.8)`。
allday は電池側 11.20 が支配的で **XIAO下に 1.70mm の無料枠**がある（`XIAO_LIFT` を 1.4→3.10 まで
増やしても外形 14.6mm のまま）。一方 **slim は XIAO 側が既に支配的（9.50 > 8.20）で無料枠 0.00mm**。
したがって実測が 7.5mm を超えた瞬間に slim の内寸 9.5mm が破綻する。
**v1.5 を1台組んだら必ずノギスでスタック厚を実測し、`XIAO_STACK_T` を更新してから基板化を判断すること。**

## 付録B: ネットリストの読み方（`netlist.json`）

```
configurations[].id = "A1_HARNESS_V15"  … 採用構成。adopted=true / buildable=true / board=null
configurations[].id = "V2_SENSE_SATELLITE" … 非実装。adopted=false / buildable="gated"
components[].config  … その部品がどの構成に属するか（"A1_HARNESS_V15" か "V2_SENSE_SATELLITE"）
nets[].config        … 同上。v1.5 だけを作る場合は config=="A1_HARNESS_V15" のものだけを読む
nets[].connections   … "REF.PIN" 形式。PIN は components[].pins のキーと1対1で対応する
```

**v1.5 を作る後段工程は `config == "A1_HARNESS_V15"` のみを読むこと。**
`V2_SENSE_SATELLITE` の部品・ネットを混ぜて実装してはならない（§0.1）。
