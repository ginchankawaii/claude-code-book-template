# AIの判断は、自分の費用を稼げるか ―― 確かめるための指示書

版 0.2（2026-11-23）

> **所有者の方へ**
>
> 「プロのように自分で判断するAI（要人の発言や重要な発表の前には外す、など）を入れて、APIの費用を自分で稼がせる」ためのプロンプト、というご依頼への答えです。
>
> **先に結論**：指示書を書く前の設計の計算で、**いまの元手（約27万円）では、AIは費用を稼げない**ことが、ほぼはっきりしました（`docs/product/ai_value/RESULTS.md`）。
> - 「外す」は、この売買ルールでは、外すこと自体が高くつきます（でたらめな時刻に外しただけで、年率が下がり、最大の下落が約20ポイント増えます）。
> - 「新しく建てるのを少し待つ」は害がありませんが、完璧に当てたとしても、得は27万円で年に約900〜3,000円までです。月300円のAPI代にも届きません。
> - AIを本番の横で試しても、当たり外れを判定できるだけの件数が集まりません（該当する場面が年に1〜4回しかないためです）。
>
> **だから、いまは作りません。** この指示書は、「元手が大きくなった」または「それでもデータで確かめておきたい」ときに、残っている1つの問いを、**APIを1回も使わずに**確かめるためのものです。
>
> - 残っている問い：**本物の発表の日程で見たとき、発表の前後は、でたらめな時刻よりはっきり悪いのか。**
> - 始め方（やるとき）：新しい会話に、次の文を貼ってください。
>   「ブランチ claude/fx-trading-simulator-vnAEG にある fxsim/docs/AI_VALUE_PROMPT.md を読んで、その通りに進めて。このブランチと、claude/ で始まる作業用のブランチへのプッシュを許可します」
> - 意味が出てくる元手の目安：完璧に当てた場合で約33万〜109万円、現実的には約100万〜330万円から。

以下が指示書の本体である。`docs/PRODUCT_PROMPT.md` の R1〜R13（絶対に破らない規則）と§5（変更の分類）、`docs/product/guide/RESEARCH_RULES.md` は、この指示書にもそのまま適用する。最初に読むこと。

---

## 0. 最初に覚える5つ

1. **既定の結論は「AIは付けない」。** 設計の計算は、すでにその方向を指している。それを覆すには、事前に決めた基準を超える証拠が要る。
2. **APIを1回も呼ばない。** 鍵を求めない。この指示書の仕事は、全部が費用ゼロである。
3. **LLMに過去を判断させた結果は、証拠にしない。** モデルは過去の相場の結末を知っている。証拠は、決定論的な規則のバックテストだけ。
4. **規則にできるものは、規則で持つ。** 発表の日程は事前に分かる。日程に従って待つ・外すなら、AIは要らず、費用は0円である。
5. **円で報告する。** 得と費用を、所有者の元手での金額と、損益分岐の元手で言う。

---

## 1. 使命

所有者の目標は、複利で資産を増やすことである。そのために、プロのように判断するAIが、自分の費用を稼ぐことを望んでいる。
設計の計算（`docs/product/ai_value/RESULTS.md`。**最初に全部読む**）は、いまの元手ではそれが成り立たないことを示した。

あなたの仕事は、**残っている1つの問いに、自分を騙さない方法で答えること**である：

> 本物の発表の日程（FOMC、日銀、米国の雇用統計、米国の消費者物価指数）で見たとき、
> 「発表の前後は新しく建てない」（A）と「発表の前後は外して、同じ大きさ・同じ損切りで戻す」（B′）は、
> **でたらめな時刻に同じことをした場合より、はっきり良いか。**

答えが「いいえ」なら、そう報告して終える。答えが「はい」でも、行き先は「規則として持つ」であって、AIではない。

### 分かっていること（確かめ直してから使う）

- この売買ルールは、小さく何度も負け、たまに大きく勝つ型である。建ては年に約23回、約9割が負け（1回平均−0.36%）。利益は少数の長い取引に集中している。
- でたらめな窓（年40回）で外して建て直すと、近い長さ9通りの平均で年0.8〜1.7ポイント悪化し、最大下落が約20ポイント増える（建て直すたびに大きさと損切りが決め直されるため）。
  同じ大きさ・同じ損切りで戻す形（B′）でも、SMA2400で年1.4〜3.2ポイント悪化する。待つだけ（A）は、ほぼ変わらない（±0.2〜0.9ポイント）。
- 窓の中の負ける建てを全部ただで避けられたとしても、得は年0.33〜1.10ポイント。
- 候補を3つ試して最良を採ると、でたらめでも年+0.2〜+0.6ポイント良く見える。
- Round-3の審問で、AIが建玉を清算できたこと・見送りが高くつくこと・プロンプトが見送りを作り出していたことが確定し、AIの権限は既定で shadow（助言のみ）になった（`docs/RESEARCH.md`、`docs/AI_TRADER.md`）。
- いまの脳のAI層は、1回の判断でweb検索を最大6回、予定表の取得で最大5回（12時間ごと）使う作りである。鍵は所有者が止めてある。

## 2. この指示書だけの規則

- **V1 APIを呼ばない。** 仕組みは、環境に `ANTHROPIC_API_KEY` があったら実行を拒否する。
- **V2 「外して建て直す」（B）は、候補にしない。** 外すこと自体が成績を壊すと分かっている。試すのは A と B′ だけ。
- **V3 対照は、でたらめな窓の分布である。** 1回のでたらめではなく、100通り以上。本物の日程の結果が、その分布のどこに来るかで判定する。
  候補や窓の長さを複数試すなら、その数だけ選び直した場合の分布（最良を採った分布）と比べる。
- **V4 事前登録。** 結果を見る前に、次をコミットする：発表の種類と日程の表（出どころつき）、窓の長さ（2通りまで）、候補（AとB′）、判定基準、既定の行動。
  基準の閾値を、判定するデータから作らない。近い長さ9通りで判断する。試行はすべて台帳に数える。
  この研究は、所有者が明示的に求めたものとして、研究の枠（`RESEARCH_RULES.md`）の1つに数える。設計の段階のでたらめな窓の計算は、検定ではないが、台帳に記録する。
- **V5 判定基準の形**（数字は事前登録で決める。出発点の案）：近い長さ9通りの平均で、本物の日程の年率の変化が、でたらめな窓の分布の95%点（選び直しを数えたもの）を超える。
  かつ、最大下落が悪化しない。かつ、得（円）が、所有者の元手で意味のある大きさである。1つでも欠ければ「変更なし」。
- **V6 日程の表が作れなければ、やらない。** 公式の公表から作る。この環境から届かなければ、規則で作れるもの（例：雇用統計は原則として第1金曜）だけで近似し、近似であると明記する。
  それでは足りないと判断したら、そう報告して止める。（相場データのホストは R5 のとおり迂回しない。中央銀行と統計局の日程は相場データではないが、拒否されたら迂回しない。）
- **V7 合格しても、行き先は規則である。** 本番に入れるなら、脳の挙動の変更（`PRODUCT_PROMPT.md` の分類⑤）であり、所有者の承認と、その手続きが全部要る。AIの権限を上げる話にはしない。
- **V8 AIを前向きに試す段階は、作らない。** 件数が足りず、判定できないと分かっている。所有者が求めた場合は、その理由（年に1〜4回しか該当しない）を先に伝える。

## 3. 進め方

1. `PRODUCT_PROMPT.md` の規則と分類、`RESEARCH_RULES.md`、`docs/product/ai_value/RESULTS.md` を読む。`design/` のスクリプトを読み、基準の数字（SMA2400で年15.1%・最大下落25.8%・219回、9通りの平均で年約9%）を自分で再現する。
   スクリプトは走り書きである。使う前に、ハーネスの照合（14行）と突き合わせ、確定足方式でも同じ結論になるかを確かめる。
2. 発表の日程の表を作る（V6）。出どころと取得日を記録する。
3. 事前登録（`docs/product/ai_value/PREREG.md`）を書いてコミットする。**ここで止まり、実行は次のセッションで**（事前登録が結果より先にあることを、履歴で示すため）。
4. 実行する。でたらめな窓の分布（100通り以上）と、本物の日程の結果を、同じスクリプトで出す。
5. 判定し、所有者に報告する（下の形）。結果は `RESULTS.md` に追記する（前の記述は消さない）。

## 4. 所有者への報告の形

1. 結論を1行（発表の前後は、でたらめな時刻より悪かった／変わらなかった）。
2. 数字：本物の日程の結果と、でたらめな窓の分布のどこに来たか。良いほうにも悪いほうにも、同じ大きさの字で。
3. お金の話：「この差は、いまの元手で年○円。規則として持てば費用は0円」。
4. 分からないこと：日程が近似である、件数が少ない、など。
5. 次の選択肢（A 規則として本番に入れる手続きに進む／B 何もしない）。推奨と、進む場合にかかるもの。既定はB。

資産の増え方の見通しを尋ねられたら、次の事実を添える（2026-11の計算）：年9%なら27万円が100万円になるまで約15年、年4%なら約33年。
毎月2万円を足すと、年9%でも年4%でも、約2年半〜3年で100万円に届く（その大半は足したお金である）。**この大きさの口座では、運用の上乗せより、足す金額のほうがずっと効く。**
元手を足すことを勧めるのではない（下落も同じ割合で大きくなり、2015〜21年はほぼ0%だった）。判断の材料として伝える。

## 5. 記憶

`fxsim/docs/product/ai_value/` に置く：`RESULTS.md`（結果。追記する）、`PREREG.md`（事前登録）、`LEDGER.md`（試行の台帳）、`JOURNAL.md`（回ごとの記録。`PRODUCT_PROMPT.md` の型）、
`design/`（設計の段階のスクリプトと表）。本番の記録そのものは置かない（リポジトリは公開されている）。

## 6. やらないこと

- AIの仕組みを作る。APIを呼ぶ。鍵を求める。
- LLMに過去の相場を見せて「当たった」と数える。
- 候補や窓を足して、良い結果が出るまで試す。基準を後から動かす。
- 「外して建て直す」を本番に入れる。保有中の建玉をAIに閉じさせる。
- 「プロのように」見える文章や画面を作って、成績の代わりにする。
- 損益分岐を超えない費用を、所有者に払わせる。
