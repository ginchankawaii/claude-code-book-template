### research-integrity-1 [P0·L] No forward (live) performance attribution: the real-money record has never been reconciled with the rule it is supposed to run

- **Evidence.** The research tape ends 2026-06-05 23:00 (tail of data/USD_JPY_H1.csv); RESEARCH.md:814 says the June-October live period is outside the data. Round-8's action item 'reconcile the June-October broker history against close > SMA2400' (RESEARCH.md:853) has no recorded result anywhere. Nothing needed for attribution is stored: the DB schema has no broker fills, swap or commission (app/db.py:45-67); the EA status file carries only balance, equity, position_lots, exec_seq, ea_time, build (mt5_ea/SteadyBridge.mq5:186); the brain reads steady_bars.csv (scripts/run_ai_bridge.py:120) and never archives it, and the EA overwrites that file with the newest 2,500 bars (SteadyBridge.mq5:22); the live run row stores only system/model/max_risk, not the strategy configuration or build (run_ai_bridge.py:89-91). The owner was asked to note the MT5 swap monthly by hand (RESEARCH.md:1018); no artefact exists. The 2026-11-16 incident (17 close attempts against a healthy long) left no trace that any report would surface.
- **Why it blocks product grade.** Every claim the product makes is a backtest claim. The one defect that halved the return (forming-bar decisions, Round-2 to Round-9) was a live-versus-backtest divergence that survived seven rounds precisely because nothing compared what the account did with what the rule would have done on the same bars. The entry-bar lottery is decided at 0.006-pip precision (RESEARCH.md:1199), so only the bars the brain actually saw can say which draw the account took. Without this a stranger cannot tell 'unlucky draw' from 'broken plumbing', which is the single judgement the health check asks of them.
- **Done.** (1) An append-only archive of every closed H1 bar the brain decided on, with a gap detector; a check that the archive and the reference tape agree on any overlap (max and median absolute close difference printed). (2) python -m scripts.forward_report exits 0 and writes forward_report.json with: per closed bar the rule position (harness rule on the archived live bars, real lots at the actual balance), the brain's decision and the EA book; decision_match_rate; every mismatch window tagged with a cause (blind, fail-safe close, pre-Round-9 cadence, manual); per trade the ramp multiple the rule gives versus the one taken; entry and stop fill slippage against the modelled close + 0.4 pip; swap received against the modelled swap; rule P&L versus account P&L with the residual. (3) Tests: an archive synthesised by the harness gives match 100% and residual 0; an archive with an injected fail-safe close on a weekday (the 2026-11-16 scenario) is reported as a tagged mismatch, not as normal. (4) The report for 2026-06-01..today reconciles with an MT5 account-history export deal by deal, residuals listed; the Round-8 action item is closed in RESEARCH.md with numbers. (5) Each decision or run segment carries the strategy-configuration hash, brain build and EA build.
- **Risk to live.** Medium if done carelessly, low if constrained. Archiving inside the resident loop must run after the heartbeat write, inside try/except, time-bounded, and never raise (a DB lock already costs 5 s, RESEARCH.md:1322). Do NOT add a second reader of Common\Files: another open handle can make the EA's FileMove of the status file fail (SteadyBridge.mq5:198-199), which starves the brain of status and ends in the fail-safe close. Do NOT change the text of runs.params that _find_run matches on (run_ai_bridge.py:72-91): store the configuration elsewhere. No EA recompile in the first version: take fills and swap from the MT5 history report the owner exports.
