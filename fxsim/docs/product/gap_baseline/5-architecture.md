SHAPE OF THE BRAIN: main() is 526 lines; its while-loop body is 356 lines with 58 branches and 27 loop-carried local variables; decide_once is 193 lines and re-reads the status and bars itself. State is untyped locals, partly reconstructed after a restart by scanning the SQLite signals table and parsing JSON blobs. Output is 65 print() calls (0 uses of logging). The Python-MQL5 protocol exists only in comments, several of which contradict the code. There are 0 git tags over 109 commits and four unrelated version markers.

THE CENTRAL FINDING: the system's safety knowledge (41+ reproduced defects) is encoded as branches inside one function plus prose, and its key claim 'live decides like the backtest' is supported by a hand-written transcription of the brain (scripts/monitor_envelope.py replay 'closedbar'), not by replaying the brain's own code. The same seam (live loop vs backtest as separate implementations) is where the forming-bar defect lived from Round-2 to Round-9.

HOW TO GET THERE WITHOUT CHANGING BEHAVIOUR (recommended order): (1) golden-trace harness around the UNMODIFIED main() with a virtual clock and one reference EA model, plus a mutation gate proving the goldens bite; tag the baseline. (2) a real shadow mode so a candidate brain can run beside the live one and be diffed. (3) additive-only work that touches no decision: structured events, protocol spec + source-parsing tests, config schema report, schema version + backups, legacy quarantine. (4) only then the state-machine extraction in mechanical steps, each commit byte-identical on the goldens. (5) behaviour changes (surfacing blind reasons, one status read per tick, fixes for the 2026-11-16 incident) as separate changes whose golden diffs are reviewed line by line. (6) cutover at a weekend from a tagged release with one-command rollback.

REFACTORS NOT WORTH THEIR RISK (listed as the last gap so the build prompt can fence them): replacing the file bridge with sockets/IPC; replacing SQLite or reshaping the signals table; rewriting app/engine.py or the research harness to share the live loop (share the small pure primitives only); rewriting the lock; changing SEQ minting; renaming bridge files or tokens; deleting the legacy 3-column/unsequenced compatibility paths inside a refactor; whole-repo reformatting; stripping the incident comments; splitting the brain into several writer processes; dependency upgrades bundled with refactors.

## Already product-grade (do not redo)

- Atomic file exchange on both sides and torn-read handling: tmp + os.replace for the signal (app/bridge.py:171-173) and lock (scripts/run_ai_bridge.py:422-424), tmp + FileMove for the status (mt5_ea/SteadyBridge.mq5:176-199), all-or-nothing parsing of the extended status columns (app/bridge.py:129-135). Hardened over Rounds 4-7 with tests; move verbatim, do not redesign.
- SEQ/EXP/SL order semantics: the EA may always reduce or close but opens/increases only on a strictly newer SEQ, the executed id is persisted, flushed and re-touched (SteadyBridge.mq5:62-83, 109), EXP is written in the EA's clock. Pinned by 15 contract tests in tests/test_ea_protocol.py. The semantics are right; what is missing is a spec and execution on the MQL5 side, not a redesign.
- The single-writer lock (scripts/run_ai_bridge.py:186-430): wait-never-exit verdicts, liveness before age, checked heartbeat, bounded wait on unreadable locks. It caused three outages while immature and has ~20 tests now. Relocate it unchanged; never rewrite it as part of a cleanup.
- The fail-safe architecture: blind brain withholds the heartbeat so the EA flattens at EXP; a restored LONG is not heartbeated until a trusted probe adopts the book (intent_lots stays 0, run_ai_bridge.py:1051, 1432-1433), so a restart loop cannot keep an unsupervised position alive.
- One loader for both the probe and the decision (_load_bars, run_ai_bridge.py:103-159) with staleness, holiday allowance and plausibility gates; closed-bar signal/ramp/ATR (I12).
- Fail-closed parsing of the dials that exist: NFKC normalisation, loud warnings, leverage cap always in (0,5], authority whitelist, non-finite integers refused (app/config.py:29-139), and a 'dials in force' line at start (run_ai_bridge.py:993-995).
- Dependency reproducibility: 44 packages pinned in constraints.txt; CI installs exactly as the Dockerfile does and verifies installed == pinned in both directions (.github/workflows/fxsim-tests.yml); .env excluded from the image (.dockerignore).
- Research provenance in CI: scripts/research_harness (14 OK lines) and scripts/research_daily_port (4 OK lines) must reproduce the engine's documented numbers on every push. Keep the engine and harness frozen as the research reference.
- Audit discipline as written artefacts: docs/COVERAGE.md (invariants I1-I12 x component ledger), docs/AUDIT_PROMPT.md, and the rule that every fix is pinned by a test that fails without it. These should become inputs to the golden-scenario corpus, not be rewritten.
- Three end-to-end fault-injection tests that already drive the real main() under a virtual clock (tests/test_ai_bridge.py:903-1047, 1100-1196, 1240-1328). They are the seed of the golden-trace harness.
- Incident rationale written at the line it protects (e.g. run_ai_bridge.py:206-219, 1032-1037). This is the system's institutional memory; a refactor must carry each comment with its code.
- The fence on the legacy writer: scripts/run_bridge.py refuses to start beside a live brain (tests/test_legacy_bridge_refuses.py).

## Gaps

### architecture-1 [P0·M] No golden-trace replay harness around the unmodified live loop (prerequisite for every other change)

- **Evidence.** Only 3 tests drive main(), each with ~100-130 lines of bespoke monkeypatching of _time, datetime, the lock, AITrader, the calendar and bridge I/O (tests/test_ai_bridge.py:903-1047, 1100-1196, 1240-1328). Two unrelated Python EA models exist: FakeEA (tests/test_ea_protocol.py:23) and an inline one (tests/test_ai_bridge.py:1001-1012). No recorded trace of signal lines / DB rows / log lines exists anywhere in the repo (.mt5common holds only .gitkeep). The live loop has never been replayed over the 2015-26 tape: scripts/monitor_envelope.py:129-222 replay('closedbar') is a hand-written model of the brain and calls none of its code.
- **Why it blocks product grade.** Without a deterministic record of what the current code does in each known situation, 'refactor without changing behaviour' is a hope, not a check. The one earlier structural rewrite of a live component (the Round-6 lock) caused the 68-hour halt. Every later gap depends on this one.
- **Done.** (1) tests/sim/world.py: ONE SimWorld = virtual clock, real files in a temp Common dir, one reference EA model (superset of FakeEA: writes the status row, has not-logged-in, market-closed and failing-close states), scripted bar tape, temp SQLite; it drives the UNMODIFIED scripts.run_ai_bridge.main for N polls. (2) A trace = ordered list of (virtual time, exact signal-file text, each signals row, each stdout line); goldens committed as tests/golden/*.jsonl; `pytest tests/golden` byte-compares; regeneration needs an explicit flag and shows the diff. (3) At least 25 scenarios: one per incident class in docs/RESEARCH.md and each I1-I12 invariant, including the 2026-11-16 reboot/not-logged-in sequence (goldens that pin a known defect are labelled known-bad so a later fix changes them deliberately). (4) Mutation gate in CI: at least 5 historical defects kept as patches under tests/mutations/; each must make at least one golden fail. (5) Long replay job: the full H1 tape at 600 s polls through the real loop yields a trade list; its count and final balance are compared with monitor_envelope 'closedbar' and any difference is written down with its cause. (6) The baseline commit is tagged before any refactor.
- **Risk to live.** None: tests only, no production code touched. The only hazard is false confidence if scenarios are thin, which the mutation gate addresses.

### architecture-2 [P0·S] No shadow mode: a candidate brain cannot run beside the live one, so nothing can be verified on the real machine before it trades

- **Evidence.** The resident loop acquires and heartbeats the brain lock regardless of --dry: _acquire_brain_lock(args.poll) at scripts/run_ai_bridge.py:1031 and _touch_lock at :1449 are unconditional (args.dry is referenced only at :978, :987, :1322, :1373, :1432). A --dry resident therefore either waits forever on the live brain's lock or takes it. Dry mode also reads the live run's DB (run_ai_bridge.py:825-827).
- **Why it blocks product grade.** Replay equivalence proves the code against scenarios someone thought of. The real environment (Windows share semantics, MT5 clock, WSL2 clock lag, OANDA's actual status rows) produced most of the 41 defects. A product needs a way to prove a new version on the owner's own feed before cutover, and a stranger needs a safe 'try it without trading' mode.
- **Done.** A --shadow flag: takes no lock, never writes steady_signal.txt or steady_brain.lock (test: run a full golden scenario with the Common dir read-only except for a shadow output file; zero writes to protocol files), uses a separate DB path, appends its would-be signal lines to shadow_signal.jsonl with the poll time. scripts/compare_shadow.py exits 0 only if every live signal line in the window has a matching shadow line (action, lots, SL, new-vs-repeated SEQ class) within one poll. The release checklist requires a shadow window with zero diffs before each cutover of the decision path. SimWorld test: live and shadow copies of the same build produce identical lines for all goldens.
- **Risk to live.** Low. A second reader of the bridge files already exists (the dashboard). The risk is a bug that lets shadow write the real signal or lock; the read-only-directory test is the guard.

### architecture-3 [P1·L] The resident loop is a 526-line function with 27 untyped loop-carried variables; there is no explicit state machine shared with the simulator

- **Evidence.** Measured by AST: main() 526 lines, while-body 356 lines, 58 branches, 27 locals assigned before the loop and mutated inside it (intent, intent_lots, stop_price, order_seq, seen_long, settle_pending, reentry_bar, last_gate, last_decision, veto_until, entry_attempts, entry_backoff_until, entry_backoff_streak, ea_exec_seq, clock_skew, prev_skew, prev_raw_skew, skew_samples, last_ea_time, frozen_status, ea_build_seen, torn_row, buildless_streak, lock_fail, last_probe_ok, cal, cal_day). No dataclass/Enum in scripts/run_ai_bridge.py or app/bridge.py. _trend_gate returns a bare None for four different causes with no log line (run_ai_bridge.py:528-533); REPRODUCED: a status row '0.00,0.00,0.000,...,r6e-status' (what a not-logged-in EA writes) gives probe=None and zero printed lines, which is exactly the reasonless 'BLIND' of 2026-11-16 (:1427). Its annotation says a 3-tuple and it returns a 4-tuple (:523-546), i.e. nothing type-checks this file. decide_once reads status and bars again by itself (:749-757) and main() has four more read_status call sites (:1015, :1208, :1247, :1282), so one tick can act on up to six different readings. scripts/run_monitor.py:21 imports constants from the script. CI has no type check or lint (workflow runs pytest and two validations only).
- **Why it blocks product grade.** Nobody other than the author can change this function safely: each new rule must be threaded through 58 branches by hand, and each of the last ten rounds found a state combination the previous round missed. A maintainer needs the set of states and the legal transitions written down as data, and the simulator and the live loop need to run the same transition code so that a timing defect cannot hide in the gap between them again.
- **Done.** Package app/brain/: state.py (frozen dataclass BrainState with schema_version), observe.py (Observation; a Blind variant carrying a reason Enum), step.py (step(state, obs, cfg) -> (state, list[Effect]) with Effect = WriteSignal | RecordSignal | Emit), shell.py (lock, files, DB, sleep). Verifiable: (a) a test imports step.py with open, time.time, datetime.now, print and sqlite3 poisoned and runs all goldens through it; (b) scripts/run_ai_bridge.py shrinks to argument parsing plus a call; (c) mypy --strict and ruff (pyflakes/bugbear rules, no reformat) pass on app/brain, app/bridge.py, app/config.py in CI; (d) branch coverage of step.py >= 90% from goldens + unit tests, gated; (e) a property test over random observation sequences asserts I1, I2, I3, I7 on the emitted Effects. METHOD, each step its own commit with all goldens byte-identical (enforced by running the golden suite on every commit of the branch): 1. move the loop body verbatim into tick(state, io), locals become fields, every read/write goes through an io port; 2. hoist reads to the port while PRESERVING their number and order (the port replays them); 3. split the pure step from the shell; 4. only afterwards, as separate behaviour changes with reviewed golden diffs: surface the blind reason, one status read per tick.
- **Risk to live.** The highest of all gaps: this is the order path. Mitigations: goldens on every commit, the mutation gate, a shadow window with zero diffs, cutover on a weekend from a tag with a rehearsed one-command rollback. Do not start before the harness and shadow mode exist.

### architecture-4 [P0·L] The Python-MQL5 protocol is specified only in comments (some false), and the EA has no executable test

- **Evidence.** tests/test_ea_protocol.py:14-18: 'MQL5 cannot be executed here ... The transcription is checked by review'. Stale spec comments: SteadyBridge.mq5:12 documents a 3-column status while :186-196 writes 6; app/bridge.py:7-9 says 'recent daily OHLC' and a signal grammar without SEQ/SL; scripts/run_ai_bridge.py:24, :870 and :1321 say 'the EA places/holds no SL' while SteadyBridge.mq5:266-283 mirrors a broker SL. No test reads the .mq5 file (grep for mq5/EA_BUILD in tests finds only EA_BUILD_EXPECTED uses), so '#define EA_BUILD "r6e-status"' (mq5:33) and bridge.EA_BUILD_EXPECTED (bridge.py:31) can drift; a mismatch is a log warning only (run_ai_bridge.py:1188-1193). The status row has no field for terminal connected / logged in / trading allowed / last trade retcode, so 'not logged in' is indistinguishable from 'balance 0'; on expiry the EA calls CloseAll every 30 s with no connection or session check and reports no result (mq5:335-342). Bar timestamps are broker server time read as UTC (docs/AUDIT_PROMPT.md:108-109). The EA update path is manual copy + F7 + re-attach (run_ai_bridge.py:1191-1193).
- **Why it blocks product grade.** Two programs in two languages execute real orders from a shared file format, and only one side is tested. A change to either side can silently break the other, and the 2026-11-16 incident is a protocol hole (no way to say 'I am not connected') rather than a coding slip. A stranger cannot be asked to open MetaEditor and compile source.
- **Done.** (1) docs/PROTOCOL.md plus a machine-readable protocol/steady_bridge.v1.json: file names, signal grammar, status columns with types/units/timezone, lock line, timing constants (30 s timer, 600 s poll, 120 min TTL, stale thresholds), atomicity rule, the EA decision table, and the compatibility rule (additive columns/tokens only; an integer proto field). (2) A pytest that parses mt5_ea/SteadyBridge.mq5 as text and asserts EA_BUILD, file names, timer, InpBars >= SMA+5 and the status header equal the spec and app/bridge.py (zero live risk, do first). (3) The EA's decision logic extracted into a pure function in SteadyBridgeCore.mqh; protocol/vectors.csv (>= 200 cases generated from the Python reference model, covering every test in test_ea_protocol.py) is consumed by pytest AND by a self-test the EA runs in OnInit without trading; the result and the vector-file hash are exported in a new status column and run_monitor reads RED when it is absent or failed. (4) CI compiles the EA with MetaEditor's command line (Windows runner or Wine), 0 errors / 0 warnings, and attaches SteadyBridge.ex5 with its SHA-256 to the release. (5) Stale comments corrected to cite the spec.
- **Risk to live.** Spec, source-parsing test and comment fixes: none. EA refactor: medium. It needs a recompile and re-attach by the owner, OnInit re-runs ProcessSignal at once (mq5:92-93), and the EA cannot be shadow-run on the live account. Do it flat or on a weekend, on a demo terminal first; the new status column must stay readable by the old brain and the old EA's row by the new brain (bridge.read_status already ignores columns beyond six).

- **Evidence.** 65 print() calls in the live modules, 0 uses of logging. Logs live only in Docker's json-file driver capped at 3 x 10 MB (docker-compose.yml:34, :59) and are discarded when the container is recreated, which docs/DOCKER.md section 6 prescribes for updates (`docker compose up -d --build`). BLIND, frozen-EA, clock-skew and withheld-heartbeat states write no DB row (run_ai_bridge.py:1423-1429; only lock waits do, :307-322), so the 5 h 20 min of 2026-11-16 left no queryable trace and the health check read normal afterwards. The event vocabulary is free strings: the literal 'blocked-on-lock' is retyped in scripts/run_monitor.py:38, 65, 115, 235, 265, app/server.py:374, 398 and scripts/diagnose_live.py:193 instead of importing BLOCKED_TRIGGER (run_ai_bridge.py:304); diagnose_live.py:168 recovers a price by regex over the human-readable reason. - **Done.** (1) An append-only events store (new SQLite table added by migration, or data/events/YYYY-MM-DD.jsonl) with rows {ts_utc, ts_ea, tick_id, seq, type, version, git_sha, config_hash, payload}. (5) Golden-scenario test: each signal-file write has exactly one event with the same seq, and each position change of the reference EA has a fill row joined by seq. (6) Existing print lines stay byte-identical (docs tell the owner to look for them) and are rendered from events. (7) SimWorld test: events survive container recreate; a read-only or locked events store never raises into the tick. (8) scripts/explain.py --since prints a timeline from events alone.
- **Risk to live.** Low if strictly additive: new table/file, the signals table (the restore source) untouched, event writes wrapped so they cannot stop a tick. The fills file needs the EA change, with the EA risk described under the protocol gap.

- **Risk to live.** Low. The one real risk is changing an effective value on the owner's machine during consolidation (for example the compose-level FXSIM_DECISION_MODEL default or --calendar-mode anthropic); the before/after JSON diff is the guard.

### architecture-7 [P1·M] No releases: the running code is whatever the working tree held at the last process start

- **Evidence.** `git tag` prints nothing over 109 commits. Four unrelated version markers: BRAIN_BUILD 'r10c-2026-11' hand-bumped (scripts/run_ai_bridge.py:172), EA_BUILD 'r6e-status' (mq5:33), app/__init__.py:2 '0.1.0' (unused), package.json '1.0.0'. The owner pulls a development branch (claude/fx-trading-simulator-vnAEG) and the containers run the bind-mounted tree, not the image (docker-compose.yml:26, 51, 94 './:/app'); so a `git pull` followed by any unplanned restart (the 2026-11-16 Windows Update reboot is one) deploys code nobody decided to deploy. Images are fxsim:latest and cloudflare/cloudflared:latest; the base image floats (requirements.txt header says so; Dockerfile:3). There is no CHANGELOG; history is the 1,390-line docs/RESEARCH.md. No rollback procedure is documented. BRAIN_BUILD is printed once at start (:992) and appears in no DB row, health check or dashboard. Docs hard-code the owner's path C:\Users\<user>\... in 11 places across 6 files. scripts/setup.sh installs without constraints.txt.
- **Why it blocks product grade.** A product has named versions, a statement of what changed, a way to know which version is running, and a way back. Here the update instruction is a sequence of commands relayed by the developer, and confirming it worked means reading a log line by eye.
- **Done.** SemVer tags; CHANGELOG.md with, per release: behaviour changes, changed goldens, whether the EA must be recompiled, whether a rebuild is needed, minimum compatible EA protocol. Version and git sha generated at build into app/_version.py; shown in the start line, every event, /api/live and run_monitor; run_monitor RED when the running sha differs from the checked-out tag or the tree is dirty. The fx container runs code copied into an image tagged with the version on a digest-pinned base; only data/ and Common\Files are mounted (test: touching a source file on the host does not change the running container's version after restart). A tag-triggered workflow runs tests, harness validations, goldens, the EA compile, and publishes the .ex5 and checksums. update.ps1 <version>: fetch tag, verify checksums/CI status, build, preflight (check_config, goldens inside the image), swap, wait for the version line and a fresh heartbeat, otherwise roll back automatically; rollback.ps1 restores the previous image. Both rehearsed in SimWorld or a demo setup, and a release cannot be cut if goldens changed without a CHANGELOG entry naming them.
- **Risk to live.** Medium. Moving from a bind-mounted tree to image-baked code changes what a restart picks up and replaces commands the owner knows; the DB path and run identity (_find_run) must be unchanged or the brain starts a new run and loses its restore state. Do it at a weekend with the old compose file kept as the rollback.

### architecture-8 [P1·M] Durable state is a patchwork recovered from a log table; the database has no schema version, migration path, backup or integrity check

- **Evidence.** After a restart, intent/stop/last_decision are rebuilt by loading every signals row of the run and parsing JSON (run_ai_bridge.py:646-688), the re-entry mark from the newest row's JSON (:606-631), the order id from the signal file (:1058-1060), the size from the book (:1221-1222). Each was added after an incident (docstrings at :608-611 and :652-656). Breaker/backoff, veto_until, acted_events and the skew history are lost on restart (:1088-1101). app/db.py has no user_version, no ALTER, no migration (grep returns nothing); signals has PRIMARY KEY (run_id, time, source) with upsert (db.py:78, 336-340), so two rows with one timestamp overwrite silently; state lives in an untyped components JSON blob. Connections use default journal mode and timeout with no busy handling (db.py:111) on a Windows bind mount shared by two containers and one-off monitor runs. No backup or PRAGMA integrity_check exists in code or docs (grep for backup/WAL/journal in docs finds nothing relevant).
- **Why it blocks product grade.** The DB is both the audit record and the only memory that lets a restarted brain keep its stop and its re-entry block. A product must survive a schema change between versions and a corrupted or lost file without the developer, and a maintainer must be able to see the persisted state as one typed object rather than infer it from history.
- **Done.** PRAGMA user_version with ordered, idempotent migrations; test: a fixture DB in today's shape migrates and the brain restores exactly the same (intent, stop, last_decision, reentry_bar). A brain_state snapshot (one row or one atomically replaced JSON, with schema_version) written every tick. For a stated period both restore paths are computed at every start and any divergence is emitted as an event (required count: 0) before the snapshot becomes authoritative, as a separate release. A scheduled online backup (sqlite3 backup API) with retention, and an integrity check surfaced by run_monitor. A scripted restore drill (delete DB, restore the latest backup, brain adopts the open book with its stop) passing in SimWorld. A written list of state that is volatile on purpose. The signals table's columns and key are not altered.
- **Risk to live.** Additive parts (user_version, snapshot written alongside, backups): low. Switching the restore source: medium-high, because restart is where several of the worst defects lived (stale stop liquidating a position, blocked-on-lock row restoring FLAT). ### architecture-11 [P0·S] Guardrail: refactors that look like improvements and are not worth their risk on this live system

- **Evidence.** Each item is a surface that earlier rounds hardened or that deployed components depend on: file bridge atomicity (bridge.py:171-173; mq5:176-199); strictly-increasing wall-clock SEQ compared with a persisted id in the EA (run_ai_bridge.py:727-736; mq5:62-69); the lock (run_ai_bridge.py:206-430, three outages while it was being written); signals table read by restore, monitor, dashboard and diagnose; engine/harness numbers pinned by CI; the legacy 3-column and unsequenced compatibility paths are live escape hatches (run_ai_bridge.py:463-481 falls back to legacy mode after two build-less rows instead of staying blind; mq5:59-69); the long comments cite the round that justified each line.
- **Why it blocks product grade.** A build prompt that asks for 'product quality' invites exactly these rewrites. Each trades proven behaviour for tidiness, and the system's history shows that structural rewrites of live components are where outages came from.
- **Done.** The build prompt lists as out of scope, and the review checklist rejects: (1) replacing the file bridge with sockets, named pipes or the MetaTrader5 Python IPC; (2) replacing SQLite or altering the signals table's columns/key (add tables instead); (3) rewriting app/engine.py or the research harness to run on the live step (share primitives only); (4) rewriting, simplifying or re-timing the lock (relocate verbatim); (5) changing SEQ minting, token names, file names or the lock line format; (6) removing the legacy-EA and unsequenced-signal compatibility paths inside a refactor (only as a separately released behaviour change after the protocol handshake exists); (7) merging the up-to-six status reads per tick into one inside a refactor (it is a behaviour change; do it separately); (8) whole-repo auto-formatting or comment pruning (if formatting is wanted, live-path modules only, one commit, verified by AST equality); (9) splitting the brain into several processes that write the bridge, or making the loop async; (10) dependency or base-image upgrades in the same release as a refactor; (11) changing poll, TTL, cooldown or staleness constants as 'tidying'. Machine check where possible: a CI test asserts the signal/status/lock formats and the constants in the protocol spec are unchanged unless the spec version is bumped.
- **Risk to live.** None; this gap removes risk. The cost is some remaining untidiness.
