# 所有者とのやり取り

`docs/PRODUCT_PROMPT.md`（指示書）の一部であり、同じ拘束力を持つ。**所有者に報告・質問・手順を送る前に、全部読む。**
所有者に `docker`・`git` のコマンドや、再起動を伴う手順を渡すときは、あわせて `RELEASE.md` も読む（質問への答えの中でも）。

## 1. 原則

- 日本語。結論から。短く。専門用語は言い換える。所有者は短く返す（「続き」「あてたよ」）。意図を汲み、質問攻めにしない。
- 判断を仰ぐのは、本当に所有者のものだけ。選択肢に記号を振り、推奨を先頭に、理由を1行で。**まとめて尋ね、小出しにしない。** 所有者が知りえないことは尋ねない。
- 報告は「何が終わり、どう確かめ、所有者に何をしてほしいか（なければ無い）」。途中経過の実況はしない。
- 悪い知らせを薄めない。分からないことは分からないと言う。リターンについて期待を持たせる言い方をしない。金額は円でも言う。
- **こちらからは声をかけられない。** 所有者が会話を開いたときにしか返事ができず、利用枠が切れていれば返事もできない。だから：
  日付のある依頼は、所有者のカレンダーに入れてもらう。手順には、「返事がないときにどうするか」（既定は、何も再起動しない・手で売買しない・そのままにする）を必ず書く。
  「連絡してください」で終わる手順を、それだけにしない。
- 手順は R6 のとおり。チャットで渡す手順は、まず見るだけのものから。設定を変える手順は、戻し方つきで、こちらで確かめていない画面の言葉には「こちらでは未確認」と書く。
  再起動を伴う手順には、押す前の確認・時間の枠・うまくいかないときの分かれ道を必ず入れる（`FOR_OWNER.md` の「画面の前での再起動のしかた」を使う）。
  繰り返し使う手順は、所有者向けの文書に入れる（分類③）。
- **確かめ方を、所有者が読み違えない形で渡す。** MT5のチャートの `brain OK` は、脳が止まっていても最後の心拍から2時間は出たままである。見るのは文字ではなく数字
  （`more min` の前の数字が105以上＝直近15分以内に心拍があった）。**数字だけでも足りない**：再起動の直後、脳がEAの古い状態行を先に読むと、MT5が未接続でも猶予の間は心拍を書く。
  だから合格は「MT5の右下がつながっている」「`pos` の数字が前と同じ」「数字が105以上」の3つが揃ったときだけ。健康診断なら「脳稼働」の行の「心拍 ○秒前」（再起動から12分以上たってから、660未満）。
  総合判定は、健全でも最初の60日は🟡である。
- 外部のサービスを勧めるときは、名前を記憶から挙げない。選ぶ基準（無料の範囲、日本のスマホで使える、残高などの金額がPCの外に出ない、新しく作るアカウントの数）を示し、
  いまの規約と料金を確かめてから名前を出す。
- 所有者に決めてもらう・してもらうことを送ったら、そのメッセージを `docs/product/owner_messages/<日付>.md` に保存する（次のセッションは、所有者の「1A 2B」を、その文面なしには読めない）。
  ただし§2が優先する：弱点を直すお願い（例：パスワードの設定）は、対処が済むまで保存せず、`JOURNAL.md` には「依頼を送った」とだけ書く。
- **入金・出金を聞かれたら**（「入金していい？」「出金していい？」）：`docs/product/deposit/RESULTS.md` の§1を読み、そこに書いてある手順で答える。
  入金は、条件を1つずつ確かめ、条件ごとに「いつ・何で確かめたか」を書き、最後に「結論　まず半分：入れてよい／まだ　　残り：入れてよい／まだ」と書く。
  確かめる材料が無いことを、合格に数えない（「未判定」は「まだ」）。`docs/OVERVIEW.md` §6の5項目だけで答えない。
  出金は、入金の条件で止めない（§1の「出金を聞かれたとき」の4つを答える）。金額は記録しない（§2）。返事がないときの既定は「入れない・出さない」である。
  この問いの中で頼んでよいのは、見るだけのものに限る（`git pull`・再起動・設定の変更は頼まない）。
- 雛形の文面は、そのまま送ってよい。自分で足した・変えた手順の文は、独立した目（指示書の§8）で確かめてから送るか、次の報告に回す。日付や曜日を変えたら、機械で検算する。

## 2. このリポジトリは公開されている

2026-11-23の時点で、このリポジトリは誰でも読める設定である。プッシュは公開である。

- **リポジトリに書かないもの**：所有者の答えのうち防犯に関わるもの（画面をどこから見ているか、パスワードの有無、PCへのサインインの方法、在宅・不在に関わること）、
  ライブ口座の記録そのもの（取引履歴、チケット番号、残高の推移、入出金の額）、通知の届け先。
- それらは `DECISIONS.md` に「回答済み（内容は記録しない）」とだけ書き、**そこから導いた作業の決定**（例：「前倒しの(1)は行わない」）だけを書く。
  弱点を示す答えは、対処が済むまで、導いた決定も書かない。内容が要るときは、所有者にもう一度尋ねる。
- ライブ口座の記録が要る仕事（B3・B4）は、リポジトリが非公開になるまで、所有者のPCの上で計算して結果の要約だけを受け取る形にする。
- **既に公開されているもの**（所有者に知らせる。下の「決めてほしいこと」の6）：仕組み、弱点の調査結果（`gap_baseline/`）、口座のおおよその大きさ、ブローカーの名前、
  11/16の記録の匿名化した抜粋、`FOR_OWNER.md`（Windows の更新を止める時期を含む）、古い文書6つの手順の中の、実在の Windows のユーザー名を含むパス。
  一度公開されたものは、非公開にしても、写しを持つ人からは消せない。
- 所有者が非公開の場所への移行を選んだら：履歴を引き継がず、ユーザー名を除いた写しから新しい場所を作る。その後、この節の制限を見直す。
  ユーザー名の扱いは、D5を待たず、6の答えを受けた時点で決める。
- 同じリポジトリの既定ブランチ（main）には、別のウェブページが入っている。リポジトリを丸ごと非公開にすると、そのページが見られなくなることがある。
  だから推奨は「fxsim を別の非公開の場所に移す」であり、やり方と所有者のPCの更新手順への影響は、頼む前にこちらで調べる。

まだなら、ほかのことより先に、この2つだけ読んでください。①は今週の月〜木の夜、②は 12/9(水) の夜です。こちらはこのあと数時間、調べるだけの作業をします。」

（日付は、送る日に合わせて直す。返事が「まだ」か無いままなら、セッションの終わりにもう一度同じことを言う。）

6. 教えてほしいこと

## 4. 返事の扱い

- **返事のない項目**：1と2はAで進める。3・4・6は、答えがあるまで該当の作業を始めない（3はM4、4はM2の通知先。6は§2の制限のまま進める）。
  **5は、はっきりした答えがあるまでB（使わない）として扱う。黙っていることを、利用枠を使う許可に数えない。**
- 「おまかせ」は 1A・2A・4C・5B とする。3と6は「おまかせ」でも、手順を渡す直前に、所有者の作業の中身を添えて、もう一度確かめる。
- 「続き」だけの返事は、「返事があった」として扱い（M0の関門）、上の既定を当てはめる。
- ア〜クに答えがなくても、M1-Aまでは進めてよい。ウが「B・C」でウ2が「聞かれない」なら、パスワードの設定の案内を、最初のお願いにする（指示書の§7の「前倒し」）。
- オ・カ・クの答えは、11/16の原因の切り分けに使う（指示書の§2.3）。答えを受けたら、ポストモーテムに訂正として追記する。
- 決定は日付つきで `DECISIONS.md` に記録する（§2の制限に従う）。

## 5. Windows の更新と年末年始の考え方（文面を直すときのために）

- **経緯**：作者は11/16に、(a) MT5で「パスワードを保存」にチェックを入れる、(b) Windows Update を5週間一時停止する、(c) 更新は相場が閉まっている土曜の昼間に手動で行う、と伝えた。
  (c)は誤りで、`FOR_OWNER.md` で取り消してある（週末の再起動は R6(e) に反する）。(b)をその日に行っていれば、一時停止は12/21ごろに切れる。所有者がどれを実際に行ったかは、確かめていない。
- **形**：月例の更新を、「日本に届いた週の水曜か木曜の夜に、所有者が画面の前で入れて再起動し、見届けて、すぐ最長の一時停止をかける」習慣にする。
  11/16の再起動は、月例の更新が届いた数日後、日曜から月曜にかけての夜中に Windows が自分で行ったものだった。届いてから最初の週末を迎える前に済ませれば、その形を避けられる。
  2026年12月は 12/9(水)、2027年1月は 1/13(水) が届く日である（米国時間の第2火曜の翌日）。
- **年明けに一時停止を外す日は、次の月例の更新が届く日から決める。** 届く前に外して放置すると、届いた後の最初の週末に同じ形になる。
- **「平日」ではなく「月〜木」**と書く（金曜の夜は、失敗したときに直す時間が残らない）。12/24(木)・12/31(木) は、翌朝から休場なので金曜と同じに扱う。
- Windows の一時停止には上限（約5週間）があり、上限に達すると、更新を入れて再起動するまで再び止められない、という挙動が知られている。**こちらでは未確認。**
  「新しい5週間をもらえる場合」は、②を行えば 12/24〜1/4 に守りの無い夜は残らない。「短くしか止められない／止められない場合」は、12/24〜27 と 12/31〜1/3 に守りが無い。
  そのために、12/23・12/30 の夜に Windows Update を見るお願いと、12/28・1/4 の朝に MT5 を見るお願いが入っている。文面を直すときは、両方の場合を日付で追い直す。
- **日付や曜日を直したら、曜日・休場・更新の届く日・一時停止の期限を機械で検算し、記録を `evidence/` に残す。**
- 12/18以降に「再起動が必要」が残っていたら、年内に消す最後の機会は 12/21(月)〜12/23(水) の夜。それも過ぎたら何もせず、「週末や休みの間にPCが再起動していたら」の手順に頼る。
- **金曜〜日曜に「再起動が必要」と出たと連絡が来たら**：Windows がいつ自分で再起動する予定か（画面に出ている時刻）を見てもらい、月〜木の夜まで延ばせるかを一緒に確かめる。
  延ばせないと分かった場合は、Windows に任せて夜中に再起動させるより、**相場が閉まってからできるだけ早い昼間に、所有者が画面の前で**再起動し、ログインと心拍が戻るのを見届けるほうがよい
  （相場が閉まっている間はEAの決済は通らず、開場の前に心拍が戻れば何も起きない。11/16の記録）。これは R6(e) の「週末には行わない」の、ただ1つの例外であり、自分の都合で選ぶ再起動には使わない。
- 「MT5の自動ログインを試す」ための再起動は頼まない。「パスワードを保存」の確かめは、見るだけで行う。
- 「再起動していたら」の手順に、MT5のアルゴ取引を一時的に切る操作（EAが決済できなくなる）を足すのは、デモの端末で確かめてから。戻し忘れると以後の売買が実行されない。
- **「休みの間は止めておきたい」と言われたときの手順は、頼まれてから考えない。** 最初の報告までに、所有者の文書に既にあるコマンドだけでできる手順を1つ書き、
  何が起きるか（建玉がいつ・どう決済されるか、再開のしかた、再開したときに大きさが決め直されること）を添えて用意しておく。
  確かめられなければ、`FOR_OWNER.md` の文面を「止め方は、まだ確かめられていません」に直す（分類③）。
- **年内の当座の備え**：年内に通知（M2）は間に合わない。コードを変えずに済む方法として、MT5に元からある「売買が成立したら、スマホのMT5アプリに知らせる」設定を調べる。
  MT5の再起動が要らないことと、何がPCの外に出るかを確かめたうえで、**12/17(木) までに**次の文面で選んでもらう。確かめられなければ、勧めない。間に合わなければ送らない。
  「年内は、異常をスマホに知らせる仕組みが間に合いません。当座の備えとして、MT5に元からある設定で『売買が成立したら、スマホのMT5アプリに知らせる』ことができます（こちらでは未確認の手順です）。
  届くのは『売買が成立した』という事実だけで、原因までは分かりません。スマホにMT5のアプリを入れる必要があります。
  A 設定する（10分ほど。手順を渡します。MT5の再起動は要りません）　B しない」

## 6. その時が来たら尋ねること

## 8. 作業の見込みを持ち、伝える

- 残りのPCでの作業の見込み（回数と、1回あたりの時間）を `ROADMAP.md` の先頭に持ち、マイルストーンごとに更新して、報告のたびに一言伝える
  （「PCでの作業は、あと約○回の見込みです」）。見込みが5回以上増えたら、理由を添えて伝える。
- 出発点の見込み（2026-11-23。確かなことは言えない）：全体で半年〜1年、PCでの作業は30回前後（1回10〜30分）、長いものが3回ほど
  （練習用の環境づくり、EAの入れ替え、止まったときの練習。各1時間前後）。EAの入れ替えは週末の昼間と月曜の朝。これとは別に、毎月1回の Windows の更新。
- PCでの作業は週1回が目安。急ぎの安全対策でそれを超えるときは、理由を先に言う。
