# 罠の一覧

`docs/PRODUCT_PROMPT.md`（指示書）の一部であり、同じ拘束力を持つ。**分類②以上の変更を設計する前に、全部読む。`main()` を走らせる仕掛け（M0の再生、M1-0）を作る前に、最初の節を読む。**
基準測定と、指示書の試運転・敵対的レビューが先に見つけたものである。ここに無い項目は、`docs/product/gap_baseline/` の該当項目の Risk to live を読む。

## 検証の仕掛け（模擬世界で `main()` を走らせるとき）

- ロックの生存確認は、**実ファイルの更新時刻**を見る。仮想の時計だけ進めても、ロックの場面は正しく走らない（今のテストはロックを差し替えて素通りしている）。
- DBの `runs.started_at` は `app/db.py` の中で実時計を読む。ロックの行はプロセス番号とホスト名を含む。そのままでは記録が毎回変わる。
- 本番の起動引数は `--calendar-mode anthropic` である。忠実に再現すると、環境に鍵があればAPIを呼ぶ（R4）。
- 所有者は、文書の案内どおりに自分のPCで pytest を走らせることがある。その `app` コンテナは本番のブリッジと本番のDBを持つ。テストが一時フォルダを使い損ねると、
  本番のシグナルファイルやDBに書く（`BAR_SPEC.md` のA1）。
- テストを既定のまま走らせると、リポジトリの中に空の `data/fxsim.db` ができる。
- 生き残った変異を「ループを編集して」直してはいけない。足すのはテストであり、本体の変更は別の分類である。
- 基準測定の再生スクリプトは、仮定（ログアウト中のEAの書き方、期限の時刻）を埋め込んでいる。走らせ直しても仮定は確かめられない。記録と合わない点がある
  （試行16回。記録は17回）。自分の再生は、一次記録の件数（EAの記録11回・BLIND 28回・決済の試行17回）に合うことを先に確かめる。
- 自分の結論も疑う。分類①の仕事には独立のレビューが無いので、`DECISIONS.md` に書いた「この指示書は誤り」「これは不可能」は、次のセッションがそのまま信じる。
  書く前に、もう一度別の角度から確かめる。

## 脳の中の「表示だけ」

- ループの `try` の中で例外が出ると、その回の心拍の書き込みまで飛ばされる。
- ファイルの先頭に足した import が失敗すると、脳はロックを取る前に落ち、再起動を繰り返す。その間にEAが決済する。import はガードの内側で、遅延して行う。
- `except BaseException` で囲むと、停止シグナルによる終了まで飲み込む。捕まえるのは `Exception` だけ。
- 表示の関数がファイル・DB・ネットワークを読んだり待ったりすると、ループが止まり、心拍が止まり、ロックが古くなる。
- 表示のために、注文経路の関数の戻り値・引数・状態ファイルを読む回数を変えたくなる（型のある「盲目の理由」を返す、原因を調べるために1回多く読む）。どちらも③′ではなく④である。
  既存の関数の中で、その場で既に持っている値を、ガードつきの呼び出しに渡すのは③′に収まる。
- 盲目の経路に足したコードは、健全な週には1行も実行されない。「本番で1週間動いた」は証拠にならない。
- 脳が読み込むようになったモジュールは、その時から注文経路のファイルである。以後の文言の変更も、分類③ではなくなる。
- 表示のために足した推定（「相場が開いているはず」など）は、1回のリファクタリングで心拍の判断に流れ込む。流用は分類⑤である。

## 観測（通知・記録・診断・照合）

- 監督状態の記録を `signals` テーブルに書くと、復元の処理がそれを判断として読む（過去に、ロック待ちの行がFLATとして復元され、健全なロングを決済した）。
- 本番のDBファイルは、別の表であっても観測が書いてはいけない。SQLiteのロックはファイル単位で、脳は判断の記録を書いてからシグナルを書く。
  観測がDBを掴んでいると、脳のその回の判断と心拍が飛ぶ。起動時に読めなければ、状態の復元に失敗し、次の判断でストップが現在値の近くに置き直される。
- シグナルファイルを観測が開いている間、EAは開けずに黙ってその回を終え（期限切れの判定もしない）、脳の置換は失敗する。足のファイル・状態ファイルも同様に、
  開いている間はEAの書き込みが失敗しうる。ロックファイルを開けば、脳は「ロックを更新できない」と見て、次の回の心拍を止める。
- 画面（`/live`）は、開いている間3秒ごとに状態を読む。これを「既存の頻度」の基準にしない。
- Windowsで直接動く道具（起動時の点検、導入、診断、更新、バックアップ）が Common\Files のファイルを開く・コピーする・掃除するのは、共有違反の典型的な原因である。
- 新しい読み手のための秘密を `.env` に足すと、fx にも渡る。`.env` が壊れると、fx は次に作り直された時に空のフォルダを向いて、`Up` と表示されたまま盲目になる。

## 起動・compose・リリース

- 起動時の検査や承諾の「門」は、既存の環境を次の再起動で止めうる。止まれば、1時間半〜2時間後にEAが決済する。
- compose の変更は、再起動では効かない。作り直した時だけ効く。「閉じた」と報告する前に、効いたことを `docker compose ps` で見る。
- dashboard のポートをこのPC限定にしても、Cloudflare のトンネル経由の閲覧は閉じない（トンネルは compose の内側から届く）。家のWi-Fiからの閲覧は閉じる。
- サービスごとに環境変数を絞るとき、脳に要る変数を落とすと本番が変わる。`docker compose config` の前後を比べる。
- dashboard のマウントを読み取り専用にするとき、起動時のDB初期化を壊さない。
- バインドマウントからイメージ焼き込みへの移行は、「再起動で何が動くか」を変える。DBのパスと実行の同定が変わると、脳は新しい実行を始めて復元状態を失う。
  設定の読まれ方も変わる（`RELEASE.md` の§7）。
- 更新の自動の巻き戻しは、原因が環境（MT5が未ログインなど）のとき、「心拍が出ない → 戻す → 出ない → …」という再起動の嵐になる。1回だけにする。
- 所有者に見せる手順の中の `git pull` は、その時点の本番ブランチの先頭を取る。手順を書いた時点の先頭ではない。
- 影モードを環境変数で選ぶと、`.env` 経由で本番の脳まで影になる。

## データと設定

- `data/USD_JPY_H1.csv` は、EAの足が1本も無いときの脳の予備の履歴として読まれる。動かさない・改名しない・新しい足を足さない。
- `data/calendar.json` は、日付が変わるたびに脳に読まれ、判断のきっかけを足す。テスト用のデータや整理のつもりで触ると、pull の翌日から本番の判断が変わる。
- `runs.params` の文字列は実行の同定に使われている。変えない。
- 旧世代のコードの隔離は、dashboard がそれらを読み込んでいないことを確かめてから（読み込んでいるものがある）。
- 健康診断や `diagnose_live` の基準値を直すと、所有者が見る数字が変わる。成績が変わったと誤解されないよう、リリースの説明に書く。
- 鮮度の規則を厳しくして心拍に使うと、薄い時間帯やメンテナンスで健全なロングを決済しうる。これは「修正が作る11/16」である。
- 休場を考慮した鮮度の判定は、実際の年末年始の休場を、本番ではまだ一度も通っていない。

## EAとMT5

- EAは `OnInit` で直ちにシグナルを処理する。付け替え・入力の変更・ログインのし直しで `OnInit` が走る（`EA.md` の§1）。
- 期限が切れた後にMT5を起動する・ログインさせると、EAは最初の点検で建玉を決済する。「MT5を起動する」は安全な自己修復ではない。
- 自己試験に失敗したEAが初期化を失敗させると、EAはチャートから消え、フェイルセーフもストップの維持も消える。
- 同じPCの2つ目のMT5は、本番と Common\Files を共有する。いま動いているMT5で別の口座にログインすると、本番の建玉が決済されうる（`STAGING.md`）。

## 所有者

- 所有者は「推奨」をそのまま選ぶ。推奨に数字と代償が書かれていなければ、それは承認ではない（R1の承認として数えない）。
- 「週1回まで」「2回まで」のような約束は、安全のために破る場面がありうる。約束ではなく目安として伝え、超えるときは理由を先に言う。
- 所有者が善意でやること（更新を今日一時停止する、デモ口座を先に作る、PCを再起動して確かめる）が、事故の引き金になる。やってほしくないことは、最初に、理由つきで言う。
- MT5のチャートの `brain OK` は、脳が止まっていても最後の心拍から2時間は出たままである。健康診断の「脳稼働」🟢も、心拍が30分古くなるまで出る。「出ていれば終わり」と書かない（数字で言う）。
- こちらからは声をかけられない。「連絡してください」で終わる手順は、返事が来ない場面（利用枠が切れている、月曜の朝6時40分）で所有者を立ち往生させる。返事がないときの既定を書く。
- 日付の計算は、コードと同じだけ間違える。「平日」は金曜を含む。「月〜木」は休場の前夜（12/24・12/31）を含む。一時停止の期限は、次の月例の更新の日に重なる。機械で検算する。
