# 合格基準（Product Bar）の全文

`docs/PRODUCT_PROMPT.md`（指示書）の一部であり、同じ拘束力を持つ。進捗は `docs/product/BAR.md` に書き、このファイルは書き換えない
（基準そのものを変えるときは、理由を `DECISIONS.md` に書いてから）。

各項目は「**何が**／**どんな証拠で**満たされるか」で書いてある。細かい達成条件は `docs/product/gap_baseline/` の該当項目の Done と Risk to live を
出発点にしてよい（対応表は末尾）。

## `BAR.md` の書き方

M0で作る。項目ごとに1行：**番号・名前・状態・証拠の区分・測り方と結果・証拠へのリンク**。基準の文はここを参照し、写さない。

**状態**（使う言葉はこの7つだけ。進み具合の順に並べてある。「〜以上」はこの順で読む）

1. **未測定**：まだ読んでも測ってもいない。
2. **基準のみ**：`gap_baseline/` の記述を読んだだけ。自分では測っていない。
3. **未着手（自分で測定）**：自分の手段で確かめ、「無い／足りない」と分かった。測り方と結果へのリンクがある。
   「無い」ことは、記録に残した検索（何を・どこで探したか）で示してよい。動かさないと分からないものは、動かして測る。
4. **進行中**：証拠の一部がある（この計画より前からあるものを含む。例：エンジン＝ハーネスの照合）。何が残っているかを書く。
5. **達成（実機待ち）**：クラウドとCIで採れる証拠は揃い、別の目で確認済み。残るのは所有者のPC（Windows・MT5）でしか採れない証拠で、
   何を・いつ・誰が採るかが `ROADMAP.md` にある。
6. **達成**：証拠がすべて揃い、別の目で確認済み。
7. **対象外**：所有者の決定で範囲から外した（`DECISIONS.md` の該当行へのリンクつき）。

基準測定を書き写して「自分で測定」と書かない。証拠は `docs/product/evidence/<マイルストーン>/` に `.txt` か `.json` で置き、
それを作ったスクリプトは同じ場所の `tools/` に置く。

**証拠の区分**（どこで採れるか。`BAR.md` の各行に書く）

- **機械**（クラウドのコンテナかCIだけで採れる）：A1・A2・A3・A8・B5・C1a・C2・C6（テープの部分）・C9・D1・D3・D5・D6・D8・E1・E3・E4・E5・E7・F2・F3・F5・F6・F7・G3・G5・G6・G7・G8・H1・H2
- **機械＋実機**（機械の部分が揃ったら「達成（実機待ち）」。残りは所有者のPCで採る）：A4・A5・A6・A7・A9・A10・B1・B2・B3・B4・C1b・C3・C4・C5・C7・C8・C10・C11・D2・D4・D7・E2・F1・F4・G1・G2・G4
- **所有者の条件つき**：E6

実機の部分に要る所有者の作業（取引履歴の書き出し、設定の項目名の貼り付け、テスト通知の受信確認、デモ端末での観測）は、項目ごとに `ROADMAP.md` の
「所有者待ち」に書き、R6 に従ってまとめて頼む。Pythonの転写の上だけで通した適合試験は、EAの証拠としては半分である（A6・G2）。

## A. 安全 — 注文経路の正しさを証拠で示す

- **A1 ゴールデントレース。** **書き換えていない** `main()` を、仮想の時計・一時フォルダの実ファイル・**1つの**基準EAモデルで、運用点で駆動し、
  シグナルファイルの全書き込み・DBの判断行・ロックの書き込み・ログ行を記録して1バイト単位で比べる。事故の型とI1〜I12のそれぞれに1本以上（25本〜）。
  11/16の再現（週末と平日）を含む。既知の欠陥を固定しているトレースには「既知の不良」と札をつける。
  **仕掛けの条件**：
  - ファイルの更新時刻を仮想の時計から設定し、ロックの場面も書き換えなしで走らせる（今のテストはロックを差し替えて素通りしている）。
  - `ANTHROPIC_API_KEY` があれば実行を拒否し、カレンダーとAI層は差し替える。時計は `app/db.py` の中も含めて仮想にする。ロックの行のプロセス番号とホスト名は正規化する。
  - **所有者のPCで走っても害がないこと。** 所有者の文書は `docker compose run --rm app python -m pytest tests -q` を案内しており、その `app` コンテナは
    本番の Common\Files と本番のDBを持つ。CIにはこの環境が無いので、CIの緑はこの経路の安全を示さない。だから：(1) M1-0の**最初のコミット**で、
    `tests/conftest.py` に全テスト共通の仕掛けを入れ、`MT5_COMMON_FILES` と `FXSIM_DB` を一時フォルダに強制する。(2) オラクル・シミュレータ・デモモード（D1）は、
    自分で作った一時フォルダ以外をブリッジやDBとして受け取ったら起動を拒否する（APIキーの拒否と同じ強さで、テストつき）。「本番を模したフォルダを指す環境変数を
    立てたまま全テストを走らせ、そのフォルダとDBへの書き込みがゼロ」をCIの検査にする。(3) (1)が本番ブランチに入るまで、`main()` を駆動する新しいテストを本番ブランチに入れない。
    所有者の文書から pytest の案内を外すのは、(1)(2)の後（分類③）。
  **種**：M1-0で作る最小の差分記録器を育てる。
- **A2 決定論的シミュレータ。** 同じ仕組みで11年分のテープを、30秒ごとのEAと600秒ごとの脳を噛み合わせて走らせ、I1〜I8・I11・I12を**毎ステップ**検査する
  （I10は場面ごとに健康診断を走らせて検査する。I9はG1・G3のテストで扱う）。
  故障注入：PC再起動と起動順、プロセス強制終了、ファイルの切断・欠落・凍結、時計のずれと飛び、ブローカーのログイン喪失、休場と拒否、部分約定、
  窓開けでのストップ飛び越え、ロック競合、書き込み不能、DBの破損とロック。乱数シード1つで再現できる。CIで固定シード群（プッシュのたび）。
  **夜間の定期実行は、ワークフローが既定ブランチ（main）に無い間は動かない**（`fxsim-tests.yml` は本番ブランチにしか無い。main には触れない）。
  それまでは、セッションの開始時に決めた回数のランダム探索を手元で回し、シードと結果を `evidence/` に残すことで代える。main に置くかは所有者の決定（リポジトリの扱いと一緒に尋ねる）。
  *証拠*：過去の重大欠陥を5種以上（形成中足での判断、ストップ後の買い戻し、ロック待ち行の誤復元、空のロックでの無限待機、終了による再起動ストーム）
  再導入すると、検査が必ず落ちる。**再発見できないオラクルは信用しない。**
- **A3 網羅と変異の門。** 常駐ループ・ブリッジ・サイジングの分岐網羅95%以上（除外は理由つきの台帳）。注文経路の変異スコア90%以上。
  **分母は、コミットした変異の一覧（基準測定の36個を含む）。等価な変異は、理由を書いた台帳に載せて分母から外す。** 基準測定で生き残った16個は、
  すべて検出されるか、等価と判定した理由が台帳にある（基準測定は2個を「既定の設定では隠れる」と報告している。隠れなくなる設定のテストを足して検出する。本体は変えない）。
  CIで、注文経路のファイルに触れるプッシュのたび。測定の道具は固定した環境の外に入れ、CIでは「固定どおり」の検査の**後**の別の段で入れる。
  変異を殺すテストは、オラクル（A1）の上に、運用点で書く（差し替えだらけの既存の型で数だけ満たすのは達成ではない）。
- **A4 どの瞬間に落ちても回復する。** 副作用の境界ごとに脳を強制終了して再起動し、不変条件が保たれることをシナリオ全体で示す。
  判断の記録に注文の識別子を先に採番して入れ、「注文して約定」「注文して未約定」「未注文」を区別できる（分類⑤。変えるのは採番の**時点**だけで、方式・値・トークン名は変えない）。
- **A5 EAの仕様・適合・実行。** ファイルプロトコルとEAの判断表を、版つきの仕様書（人が読むもの＋機械可読）にする。`.mq5` を文字列として読むテストで、
  ビルド印・ファイル名・列・定数が仕様とPython側に一致することを確かめる。EAの判断を純粋な関数に切り出し、Pythonの基準モデルから生成した適合ベクトルを、
  pytest と **MT5の中で走る自己試験**の両方が通す。CIでEAをコンパイルする（エラー0・警告0）か、できない理由と代替を記録する。
  ログアウト中・切断中にEAが実際に何を書くかを、デモの端末で観測して仕様に書く（今は推論。指示書の§2.3）。
- **A6 EA自身の最後の砦。** 脳が何を書いても越えられない上限（最大ロット・最大レバ）。拡大には識別子・期限・有効なストップが揃って必須。買い足しにも約定の時からストップが付く。
  ストップは現在値から決めた範囲の中にあるものだけ受ける。未接続・未ログイン・取引不可・純資産0のときは取引行為をしない（実行済みとして記録せず、戻ったら評価し直す）。
  キルスイッチ（「新規を止める」「いますぐ決済」）。上限はEAの入力で持ち、シグナルの行からは外せない。
  *証拠*：偽造した行を流して約定ゼロを、適合試験とデモ口座のドリルで示す。
- **A7 ブローカー側のストップを観測する。**「あるはず」ではなく、実際のSL価格を毎回確かめ、意図と違えば原因つきで警告する（警告のみ。自動決済はしない）。

  ハザード ↔ 不変条件 ↔ 検査 の対応に空欄がない（`docs/product/HAZARDS.md`。M3で作り始め、マイルストーンごとに更新する）。

## B. 忠実 — ライブが検証済みの戦略どおりであることを毎日示す

- **B1 判断の材料を残す。** 判断ごとに、使った足の時刻・終値・SMA・ATR・現在値・残高・脳とEAの版を記録する。確定したH1足を追記専用で保存し、欠落と書き換えを検出する。
  足の保存は観測（分類②）で行い、保存先に `data/USD_JPY_H1.csv` を使わない（これは脳の予備の履歴で、新しい足を足すと予備が“新鮮”になり、EAの足が消えた時に脳がそれで売買を続ける）。
  脳の判断行にキーを足すなら、注文は変えないがDBの行が変わるので分類⑤として扱い（意図した差分＝足したキーだけ、と先に書く）、復元の処理が未知のキーを無視することをテストで固定する。
- **B2 日次の判断照合。** 保存した足を検証済みエンジンに再生し、ライブの判断（建てた足・倍率・ストップ・降りた足）と一致するかを毎日判定する。
  不一致は、最初に食い違った足とともに🔴。2026年6月以降の足と取引履歴を、所有者の書き出しから1回だけ埋め戻す（届かなければ「ここから先だけ」と明記する）。
  *証拠*：形成中足での判断と、ストップ幅の変異を入れると、最初の不一致から決めた時間以内に100%検出される（感度は先に決めて `DECISIONS.md` に書く。提案：1営業日）。
- **B3 ブローカーとの突合。** 約定履歴（チケット・価格・時刻・スワップ・手数料）が注文の識別子につながる。「当初残高＋損益＋入出金＝現在残高」が1円以内で成り立つ。
  どの判断にも結びつかない約定は🔴。所有者の取引履歴の書き出しが届くまでは「進行中」。
- **B4 フォワード成績の帰属。** ルールどおりなら得たはずの損益と、口座の損益の差を、スプレッド・スリッページ・スワップ・停止時間に分解して示す。
  バックテストの仮定（スプレッド0.8pipなど）と実測の対比表を持つ。
- **B5 入出金を正しく扱う。** 資金の出入りを記録し、リターンとドローダウンは時間加重で出す。*証拠*：10万円の出金・30万円の入金の合成データで、成績が「範囲内・約0%」と読める。

## C. 無人運転 — 作者がいなくても動き続け、壊れたら知らせる

- **C1 原因に名前がある。** すべての盲目・待機・停止を、閉じた一覧の原因コードに分類し、健康診断・画面・通知・脳のログが同じコードと同じ「次の一手」を使う。2段階で達成する。
  - **C1a（いまのEAで言えること。M1）**：観測できる事実に名前をつける。事実から推し量る原因は**推定として**言う
    （例：「MT5から届く口座の状態が使えません（純資産が0以下、または状態ファイルが読めません）。MT5がブローカーにログインしていない可能性が高い →
    MT5の右下の接続表示を見てください。PCとMT5は再起動しないでください」）。
    **脳の外（M1-A）で言えるのは**、状態ファイルとシグナルファイルの有無・新しさ・中身と、DBの行から分かるものだけ。「ロック待ち」はDBの記録から言う（ロックファイルは読まない）。
    「共有フォルダに書けない」は脳にしか分からないので、M1-Aでは「心拍が更新されていません（原因は脳のログにあります）」と言い、名前つきで言うのはM1-Bから。
    **脳の中（M1-B）で言えるのは**、ループと既存の関数がその場で既に持っている値から言えることだけ（読み取りを足さない・戻り値を変えない）。
    *証拠*：原因ごとの注入テスト。11/16の再生（週末・平日）を、ログアウト中のEAの書き方として記録とコードから残る**2つの場合それぞれ**
    （純資産0以下の行を書き続ける／読める状態ファイルが無い）で走らせ、どちらでも、再生の中の最初の盲目ポーリングの時刻に走らせた健康診断が、
    その場合に合った文を出し、**「fxを再起動」とは決して出ない。** 実機がどちらなのかは未確認と `BAR.md` に書く（確かめるのはA5）。健全な週末・休場では何も増えない。
  - **C1b（EAがログイン状態を報告してから。M5）**：未ログイン／切断／アルゴ取引OFF／取引不可を、推定ではなく事実として言う。
- **C2 「稼働」と「成績」を分ける。** 稼働＝正常／要確認／要対応。成績＝範囲内／判定には早い／範囲外。副作用のない関数1つを、コマンド・画面・要約・通知が共有する。
  健全なシステムの初日が「稼働：正常」と読める。健康診断は「要対応」で0以外の終了コードを返し、機械が読める出力（`--json`）を持つ（この変更はR10の手続きで、M2）。
- **C3 通知。** 脳とは別の読み取り専用プロセスが、要対応・フェイルセーフの発動・外部決済・復旧を所有者のスマホに送る（原因＋やること1つ、平易な日本語、重複は抑える）。
  毎朝の要約（判定、建玉、ストップ、前日比、直近24時間の出来事、版）。「テスト通知を送る」操作が1つある。通知の速さの目標は、試験の前に決めて `DECISIONS.md` に書く（`OWNER.md`）。
  *証拠*：模擬の送信先に対して、故障注入ごとに決めた分数以内に送信が記録される。M1-0の場面と、テープから作った健全な週末・休場の状態ファイルの列
  （EAの基準モデルだけで生成）では1通も出ない。所有者のスマホへの実配信は、所有者が「テスト通知が届いた」と答えた記録で確かめる（こちらでは未確認と書く）。
  脳つきで全テープを回す検証は、A2ができた後にやり直して追記する。
- **C4 外部の死活監視。** PCごと止まっても（電源断・スリープ・回線断・Dockerの停止・更新画面での停止）、通知が届く。PCの中からの通知だけでは、この型は検出できない。
  *証拠*：(1) 模擬で、PCの中からの送信が止まってから決めた分数以内に「途絶」と判定される。(2) 実地は、所有者が自分の都合でPCを止める機会か、
  R6(e)の条件でどうせ行う再起動に、通知が届いた時刻を1回記録する（確かめるための停止は頼まない）。
- **C5 起動の連鎖と自己点検。** 起動に必要な環を1つずつ書き出す（Windowsのサインイン、MT5の起動とログイン、EAとアルゴ取引、Docker、マウント、時計、ディスク、
  スリープと更新の設定）。Windowsで直接動く点検が、起動のたびと数分おきに各項目を合否で示し、結果を通知する。Common\Files のファイルは開かない（R9）。
  自己修復は「Docker Desktop の起動」と「止まっているコンテナの起動」に限り、シグナル・ロック・DBには書かない。稼働中のコンテナを再起動しない。
  **MT5の自動起動は「安全な修復」ではない**：期限が切れた後にMT5が立ち上がってログインすると、EAは最初の点検で建玉を決済する。自動起動を入れてよいのは、
  A9が本番で有効になっており、かつ期限がまだ切れていないことを点検が確かめた時だけ。それ以外は知らせるだけにする。A9が対象外なら、最後まで入れない。
  2つのMT5があるPCでは、起動する端末を取り違えないことを点検する。所有者の環境を変えるものは分類⑦。
- **C6 相場の時間を踏まえた鮮度。** 平日に配信が凍った状態を、決めた時間内に名前つきで検出する。まず**警告のみ**として出す
  （心拍の判断に使うのは別の⑤の変更）。*証拠*：全596休場と週中の欠落で誤検出ゼロ、という基準を結果を見る前に決めておく。
- **C7 リリースと更新。** リリースはタグ。動いている版（コミット）が、ログ・状態ファイル・健康診断・画面に出る。コードはイメージに焼き、
  作業ツリーが黙って本番にならない。1コマンドの更新が「事前点検 → 適用 → 新しい版の心拍を確認 → だめなら前の版へ」を行う。所有者のPCでテストは走らせない。
  更新が断る条件：盲目中、12/24〜1/4のような休場をまたぐ期間、期限の残りが60分未満、状態ファイルが凍結。自動の巻き戻しは**1回だけ**
  （戻した版でも心拍が出なければ、原因は版ではなく環境なので、それ以上は再起動せず、通知して止まる）。巻き戻すのは**コードだけ**で、DB・シグナル・ロックは戻さない
  （古いDBを戻すと、古いFLATが復元されて健全な建玉が決済されうる）。脳とEAの、動作を確かめた組み合わせの一覧を1ファイルで持ち、それより古い版へは戻さない。
  1つ前のイメージを変わらない名前で残す。切り替えそのもの（バインドマウント → イメージ）の出し方は `RELEASE.md`。
  *証拠*：わざと壊した版への更新が自動で巻き戻り、注文の期限が切れる前に心拍が戻る（GitHub Actions のコンテナ上と、ステージングで）。
  切り替えの前後で、復元された状態と実効設定が同一。
- **C8 状態を失わない。** DBが壊れても読めなくても、保有中の建玉の心拍は続く（保持のみ・新規なし。起動時の挙動が変わるので分類⑤、単独リリース）。
  定期バックアップ（動いているDBファイルの単純なコピーでは取らない）と、演習済みの復元。コンテナを作り直しても消えない出来事の記録。
- **C9 事故の台帳とSLO。** 監督状態の変化（監督中／盲目／EAオフライン／ロック待ち／フェイルセーフ発動／復旧）を原因つきで残す（本番のDBファイルではなく、別のファイルに）。
  「相場が開いている時間のうち監督されていた割合」「健全な建玉をフェイルセーフが決済した回数（目標0）」「検知から通知までの時間」を定義・計測・表示する。
  目標の数字は、測る前に決めて `DECISIONS.md` に書く（`OWNER.md`）。事故ごとに、修正の前に再現シナリオを足す。
  *証拠*：11/16を再生すると、事故1件として翌朝の健康診断にも残る。
- **C10 訓練。** 故障を2種類に分ける。(a) **双子だけに閉じる故障**（ステージングの fx を止める、デモ側のMT5をログアウトする・閉じる、デモ側のアルゴ取引を切る、
  ステージングのDBを壊す）は、ステージングで実際に起こし、検知・通知・回復が設計どおりかを記録に残す。(b) **PC全体に及ぶ故障**（Docker Desktop の停止、回線断、
  電源断、Windowsの再起動、スリープ）は、**本番が動いているPCでは決して起こさない**（本番の建玉に対して11/16を再現することになる）。詳しくは `STAGING.md`。
- **C11 ステージングは本番に触れない。** 同じPCの2つ目のMT5は、本番と同じ Common\Files を共有する。分け方・作り方・証拠は `STAGING.md`。
  *証拠*：**動いているコンテナ**の実際のマウント元・プロジェクト名・イメージ・DBのパスを読み、本番と1つも重ならないことを示す点検。
  模擬世界で「ステージングの脳が本番のフォルダを向いて起動した」場面を走らせ、シグナルとロックへの書き込みがゼロで終わること。

## D. 所有者体験 — 作者に聞かなくても分かる

- **D1 デモモード。** 口座もMT5もなしで、模擬EAと模擬ブローカーを相手にシステム全体（脳・画面・通知）が動く。どのOSでも数分で試せ、故障も起こせる
  （A2の仕組みを製品機能としても使う。CIはこのモードで端から端まで走らせる。A1の「所有者のPCで走っても害がない」条件を満たす）。
- **D2 導入。** MT5とデモ口座がある新品のWindows 11で、初めての人が1ページの説明に従い、コマンドを1つも打たずに「稼働：正常」に到達する。
  導入は、Docker/WSLの確認、MT5のフォルダの自動検出、設定ファイルの生成、起動、EAの配置とコンパイル、ショートカット（状態を見る／診断を集める／更新する）の作成までを行う。
  既存の本番環境を見つけたら、確認なしに設定・コンテナ・EAを上書きしない。**本番のPCで導入の仕組みを試さない。**
  *証拠*：(1) 導入の仕組みの各段（検出、設定の生成、既存環境の上書き拒否、ショートカット）を、GitHub Actions の Windows ランナーで、MT5のフォルダ構成を模した
  作業フォルダに対して走らせる。(2) 実機は、まっさらなWindows（所有者が用意できる場合。`OWNER.md` で尋ねる）で、デモ口座を相手に1回通した記録。
  得られなければ「達成（実機待ち）」のままにし、保証しないことの一覧に載せる。
- **D3 状況が1画面で分かる。** 判定・原因・次の一手・「N分前に確認」。建玉（ロット、建てた時刻と値段、ストップの値段、ストップで決済されたときの損失額、含み損益）。
  口座（円、今日と開始来の増減）。期待値。直近7日の出来事。版。すべてのカードが、脳が実際に書くデータに結びついている（定数や常に空の表を出さない）。
  取得に失敗したら「接続が切れています」と出る。*証拠*：ブラウザで実際に描画するテスト（幅390pxと1280px）。所有者に見える文字列に英語がない。
- **D4 診断バンドル。** 1回の操作で、秘密情報を除いた診断一式（版、ログ、状態、出来事、ブリッジのファイル、MT5のログ、Windowsの起動記録など）と、
  平易な日本語の自己診断（過去の事故の型との照合）が出る。ブリッジのファイルは、状態・シグナル・足の先頭と末尾を既存の読み手の出力から取り、
  ロックファイルは開かず更新時刻と大きさだけにする（R9）。*証拠*：偽の秘密を仕込んで、1つも含まれないことをテストする。
- **D5 説明書は1冊。** 作業別（はじめる／毎朝／更新／困ったとき／年末年始／入金・出金／止める）。用語集。症状から引ける対処。
  年末年始は特定の年ではなく毎年の手順として書く。年間の損益はブローカーの報告書を使う、と明記する。鍵の入れ替えの手順がある。
  *証拠*：説明書のコマンドは実在するものだけ、引用するログの文はコードに実在するものだけ（CIで照合）。数字はコードの定数と一致。旧世代の文書は書庫へ。
  古い数字や個人のパスが残っていないこと、実マネーで動く箇所に「シミュレータ」と書いていないことを機械で確かめる。
- **D6 期待値を、判断の場面に出す。** スマホの画面、入金のとき、ドローダウンのとき、レバ上限を変えるときに、期待値・最悪ケース・「手で決済しない」を示す。
  期待値の数字の出所は1つだけ。
- **D7 見知らぬ人テスト。** リポジトリと説明書だけを渡した、何も知らないエージェント（または人）が、質問なしで「導入 → 初回確認 → 運用開始 → 故障からの復旧」を完走する。
  詰まった箇所がゼロになるまで直す。エージェントが完走できるのは、デモモード（D1）での通しと、Windowsの手順を読んで詰まる箇所の列挙まで。
  Windows実機の通しは、所有者以外の人が得られなければ、所有者がステージングで説明書だけを見て行い、「知っていたから飛ばせた箇所」を自己申告してもらう
  （見知らぬ人の代わりにはならない、と書く）。
- **D8 所有者が作者に尋ねたことに、製品が答える。** 指示書の§3-10の質問のそれぞれについて、製品のどこが答えるかの対応表がある。

## E. 証拠と再現性

- **E1 主張の台帳。** 所有者に見せる数字のすべてに、再生成するコマンドがある。CIが再生成して差分で落ちる。再生成できない数字は作り直すか、
  「歴史的・再現不能」と明記して所有者向けの文書から外す（所有者向けの数字や文言を変えるのは分類③、R10）。
- **E2 データの来歴。** データファイルごとに、チェックサム・期間・時刻の基準・出所・再配布の可否を記録し、CIで照合する。ファイルは動かさない・改名しない。
- **E3 試行台帳と事前登録。** 試行を1行ずつ機械可読で持ち、台帳の行数を正確に出す。スクリプトが失われた初期の試行には「再現不能」の印をつけ、総数は下限であると明記する。
  事前登録は、結果より先にコミットされたことをgitの履歴で確かめられる。
- **E4 凍結した戦略。** 検証済みの設定の組をハッシュにし、既定値がずれるとCIが落ちる。設定で逸脱したときは、**止めずに**「未検証の設定」と表示する
  （レバ上限を下げるのは所有者の正当な操作であり、逸脱として扱わない。脳のログに出すのは分類③′、健康診断に出すのは③）。
- **E5 優位性の言い直し。** 現在の有意性（p≤0.014）は、後に“最上位の引き”と分かった経路で測られている。くじの影響を除いた検定を、事前登録のうえ1回だけ行う。
  弱ければ「この標本では運と区別できない」と所有者向けの文書に書く——この文言の規則を、結果を見る前に決めておく。
- **E6 独立データでの1回きりの確認。** 所有者が2003〜2014年のH1データを別の出所から入手できる場合に限り、凍結した規則を、先に決めた基準で1回だけ走らせる。
  何も選び直さない。2回見たら証拠ではなくなる。
- **E7 実装どうしの鎖。**「エンジン＝ハーネス＝健康診断が期待するもの＝脳がやること」の各環を、CIのテストで結ぶ。

## F. 構造 — 何年も保守できる形

- **F1 影モード。** ロックを取らず、プロトコルファイルに書かず、別のDBを使い、「書いたはずの行」を記録するモード。ライブの行と突き合わせるスクリプト。
  影モードは、影のサービスの `command:` の引数でだけ選ぶ（環境変数では選ばない。`.env` は fx にも渡るので、本番の脳が影になれば心拍が止まる）。
  影のサービスはブリッジのフォルダを読み取り専用でマウントし、コードに欠陥があっても書けないようにする。まず、脳のファイルを書き換えずに作れるか
  （別の入口スクリプトが、ロックの取得とシグナルの書き込みを差し替えて `main()` を呼ぶ）を検討し、それで足りれば分類②。脳のファイルの書き換えが要るなら④。
  *証拠*：プロトコルファイルを読み取り専用にして全ゴールデンを走らせ、書き込みゼロ。影の引数を持たない起動（本番の起動行そのまま）で、全ゴールデンが変更前と一致する。
  本番のPCで動かす前に、読み方がR9を満たすことをステージングで確かめる。
- **F2 状態機械。** 型のある状態、観測、そして副作用のない `step(状態, 観測, 設定) → (状態, 効果の列)`。ライブとシミュレータが同じ関数を使う。
  **抽出の手順**：(1)ループ本体をそのまま関数に移す、(2)読み取りを回数と順序を保ったまま入出力の口に寄せる、(3)純粋な部分と殻を分ける。
  各段をそれぞれ1コミットにし、全ゴールデンが一致すること。挙動の変更（1ティック1回の状態読み取りなど）は、その後に別の変更（分類⑤）として行う。
- **F3 構造化された出来事の記録。** 種類は1つの列挙型。1ティックに1件。判断 → 注文の識別子 → 約定がたどれる。既存のログ行は1文字も変えない（足すのは③′(d)の形で）。
- **F4 設定のスキーマ。** ライブ経路が読む設定は1つのスキーマだけ。名前の打ち間違いを最も近い正しい名前とともに指摘し、「書いても効かない設定」をゼロにする。
  *証拠*：所有者が貼った設定の**項目名だけ**の一覧（値は貼らない。貼り方を案内する）と同じ形の設定で、移行の前後に実効値が同一。
- **F5 DBの版と移行。** スキーマの版、順序つきの移行、状態のスナップショット。復元元を切り替える前に、新旧両方で計算して差分ゼロの期間を置く。`signals` の列とキーは変えない。
- **F6 範囲の境界。** 製品（脳・ブリッジ・監視・画面・EA・仕様）、研究、旧世代を分け、製品が他を読み込まないことをテストで固定する。
  古いスクリプトを1回走らせると健康診断が別の実行を見てしまう現象（再現済み）を直す（分類③）。所有者が打つコマンド名は変えない。
- **F7 ルールの基本部品の共有。** 確定足のシグナル・ランプ・ストップ幅・切り捨てのサイズ計算を小さな純粋関数にし、ライブ・健康診断・再生が同じものを使う。
- F2・F4・F5・F7は**分類④の手続きでのみ**行う。割に合わない作り替え（指示書の「やらないこと」）はやらない。

## G. セキュリティと配布の準備

- **G1 脅威モデルと最小権限。** 誰が何を書けるかを書き出す。dashboard と `app` はブリッジとコードを読み取り専用で受け取り、非rootで動き、自分に必要な環境変数だけを持つ（CIで固定）。
  非rootでの動作は、Windowsの共有フォルダの権限が Linux と違うので、ステージングで確かめるまで「達成（実機待ち）」。
  dashboard から `.env` とブリッジへの書き込みを外す部分は、G2の前提なので M5 の前に済ませる。
- **G2 注文チャネルの認証。** シグナルの行に、導入ごとの秘密による認証子を付け、EAは認証のない拡大を拒む（A6と同じEAの版で。設計の条件は `EA.md`）。
  同じWindowsユーザーのソフトがMT5を直接操作できる、という残余リスクは正直に書く。
- **G3 ダッシュボード。** 既定でこのPCからだけ。すべての経路に認証。試行の制限。DB由来の文字列は無害化して表示。ライブのDBは読み取り専用。
  日本語のパスワードは使えるか、起動時にはっきり断る。パスを受け取る入力は許可リストで検査する。`REMOTE.md` の別の公開方法は同じ門を通すか、削る。
  *証拠*：全経路を列挙して、認証なしでは401になることをテストする。一部は前倒しする（指示書の§7）。
- **G4 秘密と個人情報。** 設定オブジェクトの表示に鍵が出ない。CIで秘密の混入を検査する。作業ツリーの文書から実在のユーザー名を除く
  （gitの履歴には残る。履歴の書き換えは所有者の決定で、既定はしない）。PCの外に出る情報の一覧を持つ。
- **G5 供給網。** ベースイメージとトンネルのイメージをダイジェストで固定。依存はハッシュつき。GitHub Actions の部品はコミットで固定。既知の脆弱性の検査。部品表。
- **G6 配布の準備。** 専門家に確認すべき質問の一覧（金融商品取引法上の位置づけ、成績の表示、利用規約、ブローカーの規約、データの再配布、
  AI提供者の規約、著作権とライセンス）。**結論を書かない。** 答えが出るまで、成果物には「個人利用・配布不可」と明示する。
  所有者が配布を決めるまで、他人の資金・口座に関わる機能、シグナル配信、成績の宣伝は作らない。
- **G7 リスクの開示。** 成績を約束しない文言と最悪ケース。初回に承諾を記録する仕組みを足すなら、既存の環境は適用除外にして止めない（R8）。
- **G8 年次の見直し。** セキュリティの不変条件を台帳に載せる。管理項目（発注前の上限、キル、監視、非本番での試験、変更管理、記録、事業継続）ごとの年次点検表を持つ。
  `SECURITY.md` に連絡先と知らせ方を書く。

## H. 研究（上限つき）— `RESEARCH_RULES.md`

- **H1 運用点モード。** ハーネスが、実際の残高・0.01ロットの切り捨て・不感帯・ストップ1つ・確定足方式で走る。モードを切れば照合の14行がそのまま通り、
  入れれば文書にある実ロットの事実（1倍の引きで0.01ロット、5倍の引きで0.08〜0.09ロット）を再現する。
- **H2 研究ごとの事前登録と判定。** 所有者が「やる」と答えた場合だけ。事前登録が結果より先にコミットされ、試行がすべて台帳にあり、
  既定の結論「変更なし」に対する判定が記録されている。「やらない」なら対象外。
