# EAを変えるとき（分類⑥、M5）

`docs/PRODUCT_PROMPT.md`（指示書）の一部であり、同じ拘束力を持つ。**EA（`mt5_ea/SteadyBridge.mq5`）やファイルプロトコルに関わる設計の前に、全部読む**（M5に限らない。`app/bridge.py` の読み書き・識別子・期限に触れる分類④⑤の設計の前にも）。
EAは、どのテストでも一度も実行されていない唯一の注文経路であり、所有者のPCでしか動かせない。だからこの分類が最も重い。

## 1. いまのEAとプロトコルについて、変える前に知っておく事実

（2026-11-23にコードで確かめたもの。着手の前に自分で確かめ直す。）

- **シグナルの行**は `LONG <ロット> SEQ <n> EXP <unix> SL <値段>`。EAもPythonの読み手も、3語目以降を**2語ずつ**（キーと値の対で）読む。
  1語だけのトークンを途中に1つ入れると、それ以降の SEQ・EXP・SL がすべて読めなくなる（SEQ=0・EXP=0・SL=0）。期限のフェイルセーフが消え、
  ストップが付かず、ストップ約定後の買い戻しが復活する。
- **状態ファイル**は「見出し1行＋データ1行」。Pythonは**最後の行**をデータとして読む。行を足すと、脳は盲目になる。
- 脳と健康診断は、EAのビルド印を**1つだけ**知っている（`app/bridge.py` の定数）。違う印のEAを付けると、健康診断は「EAビルド🔴 → 再コンパイルして付け直す」と出し続ける。
- EAは `OnInit` で直ちにシグナルを処理する。`OnInit` は、付け替え・再コンパイル・**入力の変更**・テンプレートの読み直し・**ログインのし直し**・口座の切り替えで走る
  （11/16の記録で、認証の直前にEAが読み込み直されている）。
- EAはシグナルファイルを共有なしで開き、開けなければ黙ってその回を終える（期限切れの判定もしない）。
- EAのファイル名とマジック番号は入力で変えられるが、既定は本番の名前である。新しくチャートに付けると、新しいファイルの既定の入力値が使われる。
  マジック番号かシンボル名が前と違うと、EAは自分の建玉が見えず、脳は「外で決済された」と判断する。
- MetaEditorでのコンパイルは、チャートで動いている同じ名前のEAを、その場で入れ替える。
- 既存の文書と🔴の対処文は、`mt5_ea/SteadyBridge.mq5` をコンパイルして付け直すよう案内している。

## 2. プロトコルに足すときの規則

- 列とトークンは**追加のみ**。意味を変えない・消さない・並べ替えない。
- シグナルの新しいトークンは、必ず**「キー 値」の2語の対**で、行の末尾に足す。
- 状態ファイルは「見出し1行＋データ1行」のまま、列を右に足すだけ。古い脳は先頭の列しか読まないので、新しい列は付け替えの時から出してよい。
- 旧脳×新EA、新脳×旧EAの両方で動くこと。
- 以上を、適合ベクトルと、**現行の** `.mq5` を文字列として読むテストで固定する。

## 3. 付け替えと有効化を分ける

EAの新しい挙動（上限、認証、ログイン状態の報告、再ログイン直後の扱い、キル）は、それぞれ R1 の「単独リリース」に当たる。付け替えの回数には限りがある（§6）。だから：

**1回目の付け替えで入れるもの**：新しい版、追加の状態列、導入ごとの秘密（G2。EAの入力）、A6の上限の入力。それ以外の新しい挙動は**すべてオフ**で、新旧両方の形式を受理する。

- 上限の値は、付け替えの前に所有者が決める（`OWNER.md`）。正当な注文を拒まない値（この口座で脳が出しうる最大より上）であること。
- **「旧版と同一」の意味**：脳が出しうるすべての行について、注文・変更・決済の行為と、状態ファイルの先頭の列が同一。これを適合ベクトルで示す
  （＝付け替えただけでは挙動が変わらない）。

**有効化は、そのあと1つずつ、それぞれ単独のリリースとして。** 脳からの行で有効化できる設計にすれば、MT5に触らずに済む。その設計の条件：

- 行で動かせるのは**締める方向だけ**。緩める方向（認証をやめる、未ログイン時の停止をやめる、猶予を延ばす、上限を上げる）は、所有者がMT5の入力で行う以外の道を作らない。
  「再ログイン直後の猶予」（A9）はフェイルセーフを弱める挙動なので、長さの上限をコンパイル時の定数で持つ。
- 有効化の指示は、**認証つきの行でだけ**受け付ける。認証を最初に有効にする。
- **A9（再ログイン直後の猶予）は、緩める方向の挙動である。有効化の道を、設計の前に1つに決めて `DECISIONS.md` に書く。**
  - (i) 認証つきの行で有効にしてよい「緩める挙動」を、A9ただ1つに限る。長さはコンパイル時の定数を超えられない。行で**無効に戻せる**（無効化は締める方向である）。
    有効・無効と実効の長さを、状態ファイルの列で報告する。適合ベクトルに「認証のない行・古い行の再送では A9 が有効にならない」を入れる。
  - (ii) (i)を採らないなら、A9の有効化はMT5の入力の変更であり、本番のEAへの接触が1回増える。計画の回数は「2回」ではなく「3回」であると、M5の前に所有者に伝え、
    `FOR_OWNER.md` の「全体で2回の予定」を直す（分類③）。
- **行での有効化は片道である。** 締めた挙動を戻すには入力の変更（＝EAの再初期化）が要る。有効化のリリースごとに、戻し方（入力のどれを・いつの窓で・回数への影響）を先に書き、所有者の承認に含める。
- 有効にした挙動が本番で害を出しているときの緊急の戻しは、§5の「週末」を待たない：建玉が無い時、または月〜木の相場が開いている時間に所有者が画面の前で行う。
  この場合の前後の確認（ロット数・実行済みの識別子・ストップが付いていること）を、付け替えの手順とは別に用意しておく。
- 一度有効にした挙動は、**EAが保持する**（行に指示が無いこと＝オフ、にしない。脳が止まっている時こそ効いていなければならない）。保持の場所と、端末の異常終了での
  消失の扱いを仕様に書く。**実際に効いている挙動の一覧を、EAが状態ファイルの新しい列で報告する。** 脳・健康診断・通知は、その列を真実として表示する。
- 認証の秘密は、1回目の付け替えの時にEAの入力として入れる（後から入れるのは入力の変更＝EAの再初期化で、付け替えと同じ危険があり、回数に数える）。
  入っていること・脳の秘密と合うことを、秘密そのものを出さない照合値の列で確かめてから、付け替えを終える。
- 秘密を `.env` に置くなら、**先に** dashboard から `.env` とブリッジへの書き込みを外す（G1のその部分がM5の前提）。今のままでは、外に公開されうる dashboard が
  同じ秘密と書き込み権を持ち、認証は何も防がない。
- 更新の巻き戻し（C7）との組：EAで有効な挙動ごとに「対応できる最も古い脳の版」を1つの表に持ち、更新はそれより古い版へ自動で戻さない。
  「認証を有効にした後で、認証を書かない脳に戻る」場面を、適合ベクトルと模擬世界に入れる。認証の無い心拍（期限の延長だけ）を受け付けるか否かを、理由つきで仕様に書く。

**2回目の付け替え**は、旧形式の受理をやめる時だけ。

## 4. EAは、自分をチャートから外さない

- **どんな自己試験の失敗でも、初期化を失敗させない・自分をチャートから外さない。** EAが消えると、期限のフェイルセーフもストップの維持も消える。
- 失敗時は「新規と建て増しだけを拒否し、縮小・決済・ストップの維持・期限の判定は続ける」に縮退し、状態ファイルの列で報告する（R8をEAにも適用する）。
- 「未ログイン・取引不可のときは取引行為をしない」は、「実行済みとして記録しない・戻ったら評価し直す」まで書く。

## 5. 付け替えの手順に含めるもの

**前提**（付け替えの前に済ませる）

- デモ口座でのドリルを終えている（`STAGING.md`）。所有者が承認している。
- **EAの新しいビルド印を受け入れる脳と健康診断のリリース**（受け入れる印を集合にする。`app/bridge.py` なので fx のリリース）が、付け替えの前に本番で慣らしてある。
  ビルド印を旧版と同じにして回避しない。
- 新しいEAのソースは、付け替えのリリースまで `mt5_ea/SteadyBridge.mq5` を置き換えない（別名で置く）。.ex5 も別名にして、旧版と並べて置く（戻すときは旧版をチャートに付け直すだけ）。

**当日**

1. 前に控える：いまのEAの入力値（シンボル名・マジック番号・本数・ファイル名）、状態ファイルのロット数と実行済みの識別子。
2. 行う時：**建玉が無い時が最良**（月〜木の相場が開いている時間に、所有者が画面の前で。決済されるものも、見失うものも無い）。建玉があるなら、週末の休場中で、開場まで12時間以上あり、
   所有者が画面の前にいるとき（相場が閉まっている間は、`OnInit` での誤った注文が通らない）。日次の短い休止と 12/24〜1/4 は不可。**MT5を再起動しない。**
   始める前に、心拍が新しいこと（チャートの `brain OK` の数字が105以上）、MT5の右下が「回線不通」でないこと、MT5の更新の案内が出ていないこと（出ていたら延期）を見る。
2b. 途中でMT5が閉じた・固まった場合：すぐに起動し直し、右下の表示を見る。つながれば、旧版のEAがチャートに付いていることを確かめて、その日は中止する。
   「回線不通」のままなら、`FOR_OWNER.md` の「週末や休みの間にPCが再起動していたら」の手順に移る。週末のMT5の再起動は R6(e) が禁じている形であり、
   この付け替えの中で起きうる最悪の場合である、と所有者に先に伝える。
3. 直後に見る：ロット数と実行済みの識別子が前と同じ／ビルド印が新しい／「エキスパート」タブに `FLAT fail-safe` と `NOT re-opening` の行が無い／健康診断が🟢／
   **EAが取引を許可されている**（付けるときの設定の「アルゴリズム取引を許可」、チャートのEA名の横の表示、新しい状態列の「取引可否」。画面の言葉はこちらでは未確認）。
   違えば、その場で旧版をチャートに戻す（相場が閉まっている間は注文が通らないので、戻す時間がある）。
4. 月曜の開場から1時間以内に、所有者が、健康診断と、MT5の建玉にストップの値段が付いていること、「エキスパート」タブに新しいエラーが無いことを見て完了とする。
   開場の時刻に画面の前にいられる週を選ぶ。

## 6. 回数の扱い（R6(f)）

- 本番のEAに触る回数は、計画全体で**2回が目標**（デモ側は数えない）。数えるのは、再コンパイル・付け替え・入力の変更・テンプレートの読み直し。
  取引しない補助スクリプト（約定履歴の書き出しなど）を本番の端末で動かす場合も1回に数える。
- 不具合のあるEAを旧版に戻すこと、安全のための付け直しは、回数を理由に見送らない。3回目が要ると分かったら作者は決めない：理由・代替案・危険を書いて所有者に尋ね、`DECISIONS.md` に残す。
- 回数を守るために、EAの不具合を脳の側で迂回しない（それは分類⑤）。
- **M5の設計の前に、後のマイルストーンがEAに求めるものを1枚の「EA要求一覧」にまとめる**（後から3回目を生まないため）：
  A6の上限とキル、A7のSLの列、A9の再ログイン直後の扱い、C1bのログイン・接続・取引可否の状態、G2の認証、B3の注文コメントと約定の書き出し、
  C6の最終ティック時刻、D3のストップ価格、F3の約定の対応づけ、A5の自己試験結果の列、チャートの表示の日本語化、A7の失敗の記録の間引き。

## 7. 所有者がステージングを置かないと決めた場合

EAは現行版のまま凍結する。M5のEAの変更（A5の実機部分・A6・A7・A9・G2・C1b）は「対象外」にして `DECISIONS.md` に記録する。
11/16の競合は「知らせる（C1a・C3・C4）」と「再起動の安全則（R6(e)）」だけで扱う。**本番のEAを練習なしに替える道は用意しない。**
