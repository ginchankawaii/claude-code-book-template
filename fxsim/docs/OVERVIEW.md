# FX自動売買システム — まとめ（概要・仕組み・起動・運用）

> USD/JPYを「H1の長期トレンド」で長く持つ、低頻度・リスク管理重視の自動売買システム。
> **実資金で稼働中**（OANDA証券・MT5のSteadyBridge EA経由）。AI（Claude）の層は既定で「助言のみ」で、
> 現在はAPIキーを止めているため、トレンドのルールだけで売買している。
> **コアはインデックス投資、これはサテライト（失っていい範囲の実験）。**

---

## 1. これは何か（1行）

**確定したH1足の終値が100日平均（SMA2400）より上の間だけUSD/JPYをロング、流れが切れたら降りて待つ。**
ショートはしない。AIは既定で助言のみ（意見をログに残すだけで、建てない・小さくすることはしない）。

- 期待値の目安（Round-10）：**年9%前後**。2015-26年のH1で、平均線の長さ9通り（SMA2000〜2800）を
  バックテストと確定足方式の両方で回した平均。長さによって年2〜15%、最大DDは平均30%・最悪35%。
  本番SMA2400単独の年15.3%・最大DD 27%は、9通りの中で最上位の「引き」なので、計画には使わない。
- 正直な期待値：2021-09〜2022-12の大トレンド1本を除くと**年約4%**。2015-01〜2021-09の6.7年は、9通りの平均で
  **ほぼ0%**。1995-2014年の日足近似も年4%・最大DD 52%。大きなトレンドが来れば大きく勝ち、来なければ横ばい〜マイナス。
  **負ける年もある・レジーム依存**（docs/RESEARCH.md Round-9/10）
- 性格：勝率は低い（小さく何度も負け、たまに大きく勝つ）。年約20往復（建玉変化 約40回）。判断は確定したH1足のみ（Round-9）。

## 2. 仕組み（アーキテクチャ）

```
 [Windows]  MT5 + SteadyBridge EA ──共有フォルダ(steady_*.csv/.txt)──┐
                                                                     │
 [Docker]   fx コンテナ (run_ai_bridge) ─── Python頭脳（判断）────────┘
 [Docker]   dashboard コンテナ (app.server) → http://localhost:8000/live
            （記録は SQLite: data/fxsim.db に集約）
```

**役割分担：**

| 部品 | 実体 | 役割 |
|---|---|---|
| EA | MT5内 `SteadyBridge.mq5` | 手足。H1バー・口座状況を書き出す／注文を執行 |
| Python頭脳 | `scripts/run_ai_bridge.py` | いつ・何を売買するか判断（トレンドのルール。AIは助言のみ） |
| 記録 | `data/fxsim.db` | 判断ログ・エクイティ・建玉を保存 |
| 監視 | `app.server` | DBを読んで `/live` に表示 |

**判断はすべてPython側。EAは賢いことをしない。** MT5とはファイル経由でやり取り（IPCが不安定なため）。

### 判断の流れ（1回 = decide_once）
```
 statusとH1バーを読む
   → 直近の「確定した」H1足の終値 > SMA2400(≒100日線)？
       ・下 → FLAT（待機・AIは呼ばない）
       ・上 → LONG。AIにも意見を聞くが、既定（shadow）では助言として記録するだけ
              ・APIキー停止中はログに「AI unavailable」と出る＝正常（トレンドのルールでLONG）
   → サイズ＝確信度ランプ：確定足の終値が平均線から1.5ATR離れているほど大きく、1倍〜5倍（5倍がハード上限）
     ・建てた足で1回だけ決まり、決済までロット数は変えない
     ・DDブレーキは既定OFF（含み損で自動的に小さくなることはない）
   → signalファイルに書く（"LONG 0.08 ... SL 151.234" or "FLAT 0"）→ EAが執行
     （1.5ATRのストップはブローカー側にも実注文で置く）
   → 判断理由・エクイティをDBに記録
```
判断のタイミング：**10分ごと**に確定したH1足とSMA2400を比べ、交差したらその場で建てる／降りる。
加えて約20時間ごとの定例判断と、高インパクト指標の直後（いずれもルールは同じ）。

**建玉の倍率は「くじ」**（Round-10）：倍率は交差した足の強さで決まり、そのトレンドの間ずっと固定される。
2021-22年の大トレンドは、SMA2400では5.0倍、SMA2500では1.0倍で持った。成績の差の大半はこの1件。
27.2万円では0.01ロット刻みなので、1倍の引き＝0.01ロット（実効約0.55倍）、5倍の引き＝0.08〜0.09ロット。
**手動で買い増さないこと**（検証した買い増し案は、同じDDで年約3pt負けた）。

## 3. 戦略の確定設定（なぜこれか）

| 項目 | 値 | 理由 |
|---|---|---|
| 通貨 | USD/JPY のみ | 多通貨検証で「エッジはUSD/JPY専用」と判明 |
| 時間足 | H1 | 日足より良くコスト頑健（OOS検証） |
| トレンド | SMA2400（≒100日） | 1800〜2400で堅い・低頻度 |
| 方向 | ロングのみ | 円のキャリー＋構造的上方ドリフト。ショートは利益ゼロ |
| リスク/取引 | 4% | これ以上はDDだけ増えCAGR頭打ち |
| レバ上限 | 5倍（ハード） | 複利の天井。超えると逆効果 |
| 利確(TP) | なし | 勝ちを伸ばす |
| AI | 既定shadow（助言のみ） | 検証されていない層なので、売買を変える権限は持たせない（Round-3）。今はAPIキー停止中 |
| モデル | compose既定 claude-sonnet-4-6（`FXSIM_DECISION_MODEL`） | キー停止中は呼ばれない |

**検証で棄却した案（＝なぜこの設定なのか）：**

| 試したこと | 結果 |
|---|---|
| レバ5倍超 | ❌ CAGR低下・DD爆発 |
| 短い足(M15) | ❌ 過剰売買でコスト負け |
| ショート追加 | ❌ 利益ゼロ上乗せ・DD増 |
| 週末ノーポジ | ❌ リターン↓・DD↑ |
| 利確(TP)あり | ❌ 勝ちを切りすぎ |
| 上位足フィルター追加 | ❌ 高値掴み増 |
| 多通貨分散(4ペア) | ❌ 薄まるだけ（エッジはUSDJPY専用） |

→ 結論：**いじらない方が強い。** 現行が局所最適。

## 5. 日常運用

```powershell
docker compose logs -f fx                                     # FXの判断ログを追う
docker compose run --rm app python -m scripts.run_monitor     # 週1のPDCA点検
docker compose restart fx                                     # git pull後の反映（通常）
docker compose up -d --build                                  # git pull後の反映（再ビルドの案内があった時）
docker compose down                                           # 全停止
```

**更新（git pull）の後の反映：** 普段は `docker compose restart fx`。`requirements.txt`・`constraints.txt`・
`Dockerfile` が変わった更新（更新案内に「再ビルド」と書く。Round-10は該当）は `docker compose up -d --build`。
再ビルドは建玉中でも安全：新しい脳は最大約12分で引き継ぎ、EAの注文期限は120分ある。
年末年始の休場中（12/25・1/1をまたぐ週末）は更新しない。

**監視ツール `run_monitor` の見方：**
- 🟢 健全（同じ長さの期間のバックテストの範囲内）
- 🟡 観察 or データ不足（最初の数ヶ月は正常に🟡。「例のない水準」と出たらログを確認）。
  リターンの「低め」は、平均線9通りの下位10%を下回っただけ（横ばいの時期によくある）
- 🔴 要対応：最大DDが警告線36%超（平均線9通りのバックテストの最悪35.4%を超える。平均は30%前後で、27%超は🟡。
  故障とは限らない。自動では小さくならないので、ルール通りならサイズの見直しを自分で判断）／戦略と建玉の不一致／
  過去に例のない過剰売買・損失。取引頻度とリターンは2026-11の確定足方式に切り替えた後の期間だけで判定。
  損失の🔴は主にドローダウン36%で出る（リターン単独の🔴は、普通の不運をくじ外れと区別できないので出にくくしてある）
- 「基準」行：`年+9%前後（2〜15%） / 最大DD 30%前後（最悪35%・警告線36%） / 建玉変化 約41回/年`。
  比べる相手は本番SMA2400だけでなく近い長さ9通り（回数はSMA2300〜2500）
- 「今の建玉」行：`0.04ロット（実効1.6倍） ｜ 建てた時のランプ倍率 1.7倍 ｜ 2026-11-10 17:00 UTC建て`。
  ランプ倍率は建てた足で決まった1〜5倍の値、実効は「今のロット×価格÷口座」。0.01ロット刻みなので実効はランプより
  小さく出る。時刻はUTC（日本時間は+9時間）

**正常な挙動：** MT5+EA稼働中なら `trend-up... > SMA2400 → wrote signal: LONG x.xx`。
APIキー停止中は `trend-up; AI unavailable (...)` と出る（＝正常、トレンドのルールでLONG）。
判断ログの `lev 1.7x` は新規エントリーの行だけに出る（保有中の行は `size held from entry`、FLATの行は `no position`）。
MT5未起動なら `waiting for EA status`（＝正常、起動すれば繋がる）。

**年末年始（2026-12-25・2027-01-01は金曜）：** 木曜の深夜〜月曜の朝（日本時間）まで相場が止まり、H1足も止まる。
脳は、12/25か1/1をまたぐ休場に限り、最後の足から**99時間まで**正常として扱う（普段は75時間。Round-10）。
- 休場中もログは約20時間ごとに同じ終値で `(daily) trend-up ... decision: LONG ...` を出す＝正常
- PC・Docker Desktop・MT5は起動したままにする。更新・再起動はしない
- 再開が遅れて99時間を超えると `bars STALE (... > 99h ...)` → 30分後に `BLIND ... withholding heartbeat` →
  EAが最大2時間で決済する（フェイルセーフ・正常）。再開後は、脳が次の確定足で入り直す（倍率は引き直し）
- その場合も**手で買い戻さない**。STALE行の時刻はMT5サーバー時刻（UTC+2）で表示される

デモの目的は「儲かるか」でなく**配管と自分の心臓の確認**（エッジは検証済み）。

- [ ] `run_monitor` の執行一致が数週間🟢

- [ ] レバが5倍以内

## 8. リスク・正直な注意

- **必勝法ではない。** 検証値（平均線9通りで年9%前後。SMA2400単独の15%は最上位の引き）は、2021-22年の円安トレンド
  1本に大きく依存する（それを除くと年約4%）。負ける年もある。
  1995-2014年の日足近似では年4%・最大DD 52%・12年間高値を回復できず（docs/RESEARCH.md Round-9）。
- 最大DD 30%前後、相場次第で約50%に耐える前提。底で投げないこと。
- 単一通貨・単一戦略。相場の質が変われば効かなくなりうる。
- **コアはインデックス、これはサテライト（資産の1割・失っていい範囲）。**
- 「1日100万」系SNSは生存者バイアス。高レバ＝いつか全滅とセット。真似しない。

## 10. トラブルシュート

- **localhost:8000が開かない** → `docker compose ps` で dashboard が up か。8000使用中なら compose の `"8000:8000"`→`"8001:8000"`
- **fxが waiting のまま** → `.env` のMT5パス／MT5でEAアルゴ取引ON か
- **Docker起動しない** → WSL2更新(`wsl --update`→`wsl --shutdown`)・仮想化有効化・再起動
- **ファイルが繰り返し消える** → ウイルス対策の隔離を疑う（Pythonフォルダを除外）
