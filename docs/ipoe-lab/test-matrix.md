# 検証マトリクス・切替シナリオ・トラブル再現レシピ

## 1. 事前ヒアリングシート(案件受領時に必ず埋める)

切替トラブルの多くは、この時点の情報不足が原因です。

| # | 項目 | トラブルに直結する理由 |
|---|---|---|
| 1 | ひかり電話の有無(→ RA 方式 /64 か PD 方式 /56 か) | ルータの IPv6 設定方式が変わる |
| 2 | HGW 型番・VNE 対応機能の内蔵有無 | HGW が勝手に IPoE 終端して二重終端になる |
| 3 | 切替先の方式(MAP-E 系か DS-Lite 系か、どの VNE か) | ルータの対応方式が機種・ファーム単位で異なる |
| 4 | ルータ機種・ファームバージョン | 同上。ファーム更新が切替当日に必要になるケース多数 |
| 5 | 固定 IP 利用・サーバ公開・ポート開放の有無 | MAP-E は制限ポートのみ、DS-Lite は開放不可 |
| 6 | VPN の種別(IPsec/L2TP/PPTP/SSL) | PPTP は不可。IPsec はポート固定のため MAP-E で失敗しやすい |
| 7 | PPPoE 併用の要否(固定 IP 用等)と ISP の併用可否 | IPoE 開通で PPPoE が止まる ISP がある |
| 8 | 複数拠点・二重ルータ・ブリッジ構成の有無 | RA/PD の通過可否、経路非対称の原因 |

## 2. 検証マトリクス(優先度順)

ラボ列 = NGN-SIM モード / 有効にする VNE 機能。CPE は「参照」= OpenWrt-CE、「実機」= 案件同型機。

| No | 構成(実案件側) | ラボ再現 | 主な確認点 |
|---|---|---|---|
| 1 | ひかり電話なし + MAP-E + 市販ルータ | ra + map-br、実機 | RA だけで MAP アドレスを計算できるか。PD 前提設定になっていないか |
| 2 | ひかり電話あり + MAP-E + 市販ルータ | pd + map-br、実機 | PD 取得、MAP パラメータ自動計算値の一致、ポート制限下の業務アプリ |
| 3 | ひかり電話あり + DS-Lite + 市販ルータ | pd + aftr、実機 | AFTR 到達性、ポート開放不可の影響範囲、MTU |
| 4 | HGW 内蔵 IPoE + 配下ルータ(二重ルータ) | pd + map-br、参照 2 台直列 | 配下での二重 NAT/二重終端、どちらを終端にするかの設計確認 |
| 5 | PPPoE 併用(固定 IP は PPPoE、一般は IPoE) | ra or pd + map-br + BRAS 同時 | ポリシールーティング、経路非対称、セッション競合 |
| 6 | 切替過渡期(PPPoE→IPoE 移行当日) | シナリオ §3 を通しで | セッション残留、DNS キャッシュ、切戻し手順 |
| 7 | VPN あり構成 | 2 or 3 + クライアント VPN | IPsec NAT-T / L2TP の張り直し可否、ポート衝突 |
| 8 | プレフィックス変更(ひかり電話の契約変更) | ra→pd 切替 | CPE の再取得追従、内部 LAN の再広報 |

新規案件は「どの No に一番近いか」を当てはめ、一致しない差分(機種・ファーム・アプリ)だけを追加検証する運用にすると、組み合わせ爆発を吸収できます。

## 3. 切替リハーサルシナリオ(1 案件 1 回は通しで実施)

### Phase 0: 切替前の現状採取(PPPoE 状態)

1. CPE を PPPoE で接続(BRAS 認証)
2. `run-checks.sh` を実行し結果を保存(**切替後の比較基準**)
3. 記録: WAN IPv4/IPv6、DNS 応答、MTU 実測値、PPPoE セッション ID(BRAS 側 `accel-cmd show sessions`)、開放中ポート、VPN 接続状態

### Phase 1: 切替

1. (実案件で必要なら)ファーム更新をここで実施
2. CPE の PPPoE 設定を無効化 → **BRAS 側でセッションが正常切断されたことを確認**(残留していれば再現レシピ R2)
3. IPoE / IPv4 over IPv6 設定を投入(MAP-E なら自動計算値がラボの期待値と一致するか確認)
4. IPv6 → IPv4 over IPv6 の順に上がることを確認

### Phase 2: 切替後確認

1. `run-checks.sh` を再実行し Phase 0 と比較(MTU が 1454→1460 に変わる、送信元 IPv4 が共有アドレスになる、等の**期待される差分**を確認)
2. INET-SIM の応答ページで出口アドレス・方式を確認
3. 業務アプリ相当の確認(VPN 再接続、ポート利用のあるアプリ)

### Phase 3: 切戻し訓練

1. IPoE 設定を無効化 → PPPoE 再設定 → 復旧までの所要時間を計測
2. 切戻し後に `run-checks.sh` が Phase 0 と一致することを確認
3. 所要時間と手順を切替当日の作業手順書に反映

## 4. トラブル再現レシピ

各レシピは「再現手順 → 症状 → 現場での切り分けコマンド」の順。スナップショットから数分で再現できます。

### R1: RA 方式なのに PD 前提設定(最頻出)
- 再現: NGN-SIM を `ra` モード、CPE で DHCPv6-PD を要求する設定に
- 症状: IPv6 アドレスが付かない/MAP-E が上がらない
- 切り分け: CPE で RA 受信は見えるが PD 応答がない(`tcpdump -i wan ip6 and udp port 547`)

### R2: PPPoE セッション残留
- 再現: CPE の電源断で PPPoE を切断(正常切断させない)→ 即座に再接続 or IPoE 切替
- 症状: 再接続失敗(ISP 側同時セッション数超過相当)、切替後も課金/セッションが残る
- 切り分け: BRAS の `accel-cmd show sessions`。実案件では ISP へのセッション強制切断依頼が必要と判断できる

### R3: MAP-E ポート制限
- 再現: map-br 構成で、配下から 240 を超える同時セッションを張る(`for i in $(seq 300); do curl -s http://203.0.113.80 & done` 等)、または well-known ポートの開放を試みる
- 症状: セッション超過時に新規接続断続失敗。80/443 等の待受公開は不可
- 切り分け: CPE の NAT テーブル使用数。ポート要件がある案件は DS-Lite でなく MAP-E でも不可 → 固定 IP 系か PPPoE 併用を提案

### R4: DS-Lite でポート開放不可
- 再現: aftr 構成でポートフォワード設定 → 外部(INET-SIM)から到達確認
- 症状: 設定 UI 上は入るが一切着信しない(NAT が網側のため)
- 切り分け: 仕様であることをエビデンス付きで説明できるようにしておく

### R5: MTU ブラックホール
- 再現: VNE で ICMPv4 Fragmentation-Needed / ICMPv6 Too-Big を drop(`nft add rule ip6 filter forward icmpv6 type packet-too-big drop` 相当。setup スクリプトの `break-pmtu` 参照)
- 症状: 小さいページは開くが大きいページ・ファイルダウンロードだけ固まる(切替後問い合わせの定番)
- 切り分け: `ping -M do -s 1432` は通るが `-s 1472` が通らない、TCP MSS 調整で回復

### R6: DNS フォールバック遅延
- 再現: `setup-inet.sh break-v6`(AAAA は返るが v6 到達不可)
- 症状: サイト表示が数秒〜数十秒待たされる。Happy Eyeballs 実装差で端末により症状が違う
- 切り分け: `curl -4` は即応、`curl -6` はタイムアウト

### R7: 二重終端(HGW 内蔵 IPoE + 配下ルータでも IPoE 設定)
- 再現: OpenWrt-CE を 2 台直列にし両方で MAP-E を設定
- 症状: IPv4 が二重 NAT になる/片方が MAP アドレスを取れず不安定
- 切り分け: どちらを終端にするかの設計を切替前に確定する(ヒアリング #2)

### R8: v6オプション未契約相当
- 再現: NGN-SIM で VNE への経路を遮断(`ip -6 route del` で CORE 向け経路を落とす)
- 症状: IPv6 アドレスは付くのにインターネットに出られない=「開通したのに繋がらない」
- 切り分け: NGN 網内(NGN-SIM)へは ping が通るが AFTR/BR に届かない → 契約状態の確認へ誘導

### R9: プレフィックス変更で LAN 側が追従しない
- 再現: 接続中に NGN-SIM を `ra`→`pd`(または kea の委譲プレフィックスを変更)して再起動
- 症状: WAN は新プレフィックスだが LAN 内端末が旧アドレスを保持し通信断
- 切り分け: CPE の再起動または RA の有効期限切れ待ちが必要か、機種ごとの挙動を記録

### R10: PPPoE 併用時の経路非対称
- 再現: マトリクス No.5 構成で、固定 IP 宛通信が IPoE 側から出る設定ミスを仕込む
- 症状: 戻りパケット不達で特定通信のみ失敗
- 切り分け: 送信元アドレスベースのポリシールーティング設定を確認

## 5. 結果の記録

- `run-checks.sh` の出力をそのまま `検証結果/<案件名>/<日付>-<フェーズ>.log` として保存
- マトリクスの各 No に「実施日 / CPE 機種・ファーム / 結果 / 備考」を追記して、機種×方式の実績表として育てる(これが溜まるほど新規案件の検証が省ける)
