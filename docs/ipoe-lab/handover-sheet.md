# 引き継ぎシート(構築したら埋めてください)

**このファイルは枠だけです。実値は各自の環境ごとに違うので、埋めてから
社内の共有(Box 等)に置いてください。**

> **リポジトリにこのファイルの実値を commit しないこと。**
> IP・ホスト名・鍵の所在は環境情報です。**枠は共有、値は社内。**

模擬勉強会で「代打の司会では開催不能になる唯一の要因」と判定されたのが、
**アクセス情報・環境の現在状態・物理結線**の 3 点でした。技術の説明は
runbook とスライドのノートで足りていて、**残っているのはここだけ**です。

## 1. アクセス情報

| 項目 | 値 | 備考 |
|---|---|---|
| 司会が操作する端末 | | どの PC から作業するか |
| ハイパーバイザ (vCenter/ESXi) | | URL とアカウントの所在 |
| SSH 鍵の置き場所 | | パスは書いてよい。**鍵そのものは置かない** |
| `lab-mode.sh` を実行する場所 | | ハイパーバイザ上 / 作業端末 |

### `lab-hosts.conf` の実値

`lab/ipoe/lab-hosts.conf` に置きます(`.example` をコピーして作成)。

```
NGN=labadmin@
VNE=labadmin@
INET=labadmin@
```

> リンクローカルを使うなら **`%<ブリッジ名>` を忘れないこと**(例 `fe80::...%vmbr0`)。
> **`./lab-mode.sh status` が「(未設定)」を出したら、まずこのファイルを疑ってください。**
> 模擬開催では、壊れているのか未設定なのか分からず 30 分溶けました。

## 2. 環境の現在状態(最後に触った人が更新)

| 項目 | 値 | 更新日 |
|---|---|---|
| いまの方式 | 例: RA + MAP-E(共有IP) | |
| ルール配布サーバ | 起動中 / 停止中 / 未構築 | |
| CE に使っている機材 | 892FJ / C1111-8P / OpenWrt | |
| スナップショットの有無 | 取得済みの世代と日付 | |
| 既知の不調 | | |

**確認コマンド**(これを打てば上の 1〜3 行目は分かります):

```bash
./lab-mode.sh status
```

出力の「配布ルール」の行は**サーバと BR を実測**しています。
「⚠ 不一致」と出たら `./lab-mode.sh prov rule shared` で揃えてください。

## 3. 物理結線

**写真を 1 枚撮って貼るのが最も速いです。**文章より確実です。

| 何を | どこに挿すか |
|---|---|
| 実機 CPE の WAN | 物理スイッチの PG-ACCESS 側 |
| 実機 CPE の LAN | 検証用 PC |
| コンソールケーブル | 司会端末 / 受講者端末 |
| 検証用 PC の有線 NIC | CPE の LAN ポート(番号も書く) |

> **892FJ と C1111-8P で WAN ポートの位置が違います。**
> C1111-8P は `GigabitEthernet0/0/0` が WAN、`0/1/0`〜`0/1/7` が LAN スイッチです。
> **見た目で 10G と 1G の RJ45 は区別できません**(サイクル 4 で踏みました)。

## 4. 開催前チェック(前日にやる)

- [ ] `./lab-mode.sh status` が方式を正しく表示する
- [ ] `EXPECT_SRC4=... ./ipoe/tests/run-checks.sh` が PASS する
- [ ] 実機 CPE のコンソールに入れる
- [ ] 検証用 PC の**有線アダプタ**がある(社用 PC は無い人がいます)
- [ ] MAP-E をやるなら `./lab-mode.sh prov status` でサーバが起動している
- [ ] **演習 6(MTU)と演習 8 を一度通す。**この 2 つは実機での通し実走がまだです
- [ ] スナップショットを取る(壊す演習の前に戻せること)
