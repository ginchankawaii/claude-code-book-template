### 0-2. なぜ IPv6 に変えるのか — 建前と本音を分けます

**お客様が今お金を出す理由は「IPv6 が欲しいから」ではなく「PPPoE が遅いから」です。**

教科書に書いてある理由(建前):

- IPv4 アドレスが足りなくなった。だから IPv6 に移行する
- 正しいのですが、**これは「きっかけ」であって、目の前の案件でハンコを押す理由ではありません**

現場でお金が動く理由(本音):

- **夜になると遅い。Web 会議が切れる。**この相談から始まります
- 原因は回線速度ではなく、**多くの場合 PPPoE が通る「網終端装置」の混雑**です
- **IPoE** — 認証なしで回線に直接つなぐ方式です。仕組みは第2部でやります —
  **にするとこの装置を通らなくなる**ので速くなります

この区別ができると、次の質問に自信を持って答えられます。

> **「社内も IPv6 にするんですか?」**
> → **普通はしません。**LAN は IPv4 のままです。
> IPv6 にするとアドレスの設計をやり直し、ファイアウォールを見直し、アプリも検証し直しになります。
> 要件でない限りやりません。**IPv6 は「外を速く通るための道」**であって、社内を作り替える話ではないです。

ただし「将来も IPv6 化しない」とは言わないでください。**今回の案件でやらないだけ**です。

**教科書**: 第18章「IPv4 アドレスの在庫枯渇」(p.335〜) / 付録 A.3「IPv6 PPPoE と IPv6 IPoE」(p.443)

## 第1部 IPv6 そのもの — どこの国でも同じ話(9 分 / 4 枚)

### 1-1. IPv4 との違いは、現場では 5 つだけ

**全部覚える必要はありません。現場で効くのはこの 5 つです。**

| | IPv4 | IPv6 | 現場でどう効くか |
|---|---|---|---|
| **アドレスの長さ** | 32 ビット | 128 ビット | 枯渇しない。ただし覚えられないのでコピペ前提で作業する |
| **1 サブネット** | 好きに切れる | **`/64` が原則** | `/64` より細かく切ると自動設定が動かなくなる |
| **1 枚の NIC のアドレス** | ふつう 1 個 | **複数が当たり前** | 「アドレスが 2 つ付いている」は異常ではない |
| **ARP** | ある | **無い**(NDP = 近隣探索 という仕組みに変わる) | **ICMPv6 を止めると通信が死にます。**FW 設計の事故で一番多い |
| **フラグメント** | 途中のルータも分割 | **送信元だけ** | MTU の問題が表に出やすい(第3部で扱います) |

**このうち一番大事なのは 4 つめです。**
「ICMP は ping だから止めていい」は IPv4 の感覚です。**IPv6 では ICMPv6 が住所解決そのもの**なので、
まとめて落とすと**通信ができなくなります**。

**教科書**: 2.10「IPv6 と IPv4 の違い」(p.51) / 第5章「ICMPv6」(p.115) / 第6章「近隣探索プロトコル」(p.127)

---

### 1-2. アドレスの読み方と、なぜ `/64` なのか

**`/64` は決まりごとです。「なんとなく」ではありません。**

書き方のルールは 3 つだけです。

- 各ブロックの先頭の `0` は省ける → `2001:0db8:0000:0001` は `2001:db8:0:1`
- `0` が続くところは `::` で **1 回だけ**省ける → `2001:db8:0:0:0:0:0:1` は `2001:db8::1`
- URL に書くときは `[ ]` で囲む → `http://[2001:db8::1]/` (忘れると動きません)
  - なぜ囲むかというと、**ポート番号のコロンと区別できなくなるから**です(`[2001:db8::1]:80`)

**なぜ `/64` なのか。**

- 後ろの 64 ビットは「インタフェース ID」に使うと決まっています
- 端末が **MAC から作るか、ランダムに作る**ので、**下位 64 ビットは端末が勝手に決めます**
- だから **`/64` より細かく切ると**(たとえば `/80`)**自動設定が動きません**

実務での見え方はこうです。**ここが後で効いてきます。**

| ひかり電話 | 降りてくるもの | 呼び方 |
|---|---|---|
| **なし** | `/64` が 1 本だけ | RA 方式 |
| **あり** | `/56` が委譲される(= `/64` が 256 本使える) | PD 方式 |

**この違いが効くのは「LAN をいくつのセグメントに切れるか」です。**
どちらでも MAP-E や DS-Lite は組めます。

**教科書**: 第3章「IPv6 アドレス体系」(p.67) / 7.7「グローバルアドレスの生成」(p.172) / 8.7「DHCPv6-PD」(p.201)

### 1-3. `fe80::` が必ず付いている理由 — ここが IPv4 と一番違う

**アドレスをもらう前に通信する必要があるからです。**

考えてみてください。

- アドレスをくれるのはルータです
- でもルータと話すにはアドレスが要ります
- **鶏と卵**です

だから IPv6 では、**NIC が上がった瞬間に自分だけで作れるアドレス**を必ず持ちます。それが `fe80::` です。

その結果こうなります。

- **RA も DHCPv6 も送信元は `fe80::`**。グローバルアドレスは後から付きます
- **既定ゲートウェイも `fe80::` で指します**。IPv4 のように `192.168.1.1` とは書きません
- **ルーティングプロトコルの隣接も `fe80::`** です

**だから「グローバル IPv6 が付いていない = 壊れている」ではありません。**

実際、うちの検証環境では **VM に管理用の IP を振らず、`fe80::` だけで SSH して構築しました**。

> **注意**: `fe80::` は同じリンクの中でしか使えないので、**どのインタフェース経由かを必ず書きます**
> (`fe80::1%eth0` のように)。ここを書き忘れて「届かない」と悩むのが最初の関門です。

**あわせて**: 1 枚の NIC に `fe80::` と グローバル が同時に付きます。これが「複数が当たり前」の中身です。

**教科書**: 3.5「リンクローカルユニキャストアドレス」(p.74) / 3.6「スコープのゾーン」(p.76) / 2.9(p.48)

### 1-4. アドレスはどうやって決まるのか

**ルータが「私がゲートウェイだ」と自分から言いに来ます。IPv4 の DHCP とはそこが違います。**

流れはこうです。

1. 端末が「ルータいますか」と聞く(RS)
2. ルータが「私がいます。プレフィックスはこれです」と答える(**RA**)
3. 端末が**下位 64 ビットを自分で作って**アドレスを完成させる(**SLAAC** = 自動設定)

DHCPv6 を使う場合もありますが、**その指示自体も RA で伝えられます。**

| RA の中身 | 意味 |
|---|---|
| **A フラグ** | これが立っていれば **SLAAC でアドレスを作ってよい** |
| **M フラグ** | 立っていれば **DHCPv6 でもアドレスをもらう** |
| **O フラグ** | 立っていれば **DNS などの情報だけ** DHCPv6 からもらう |

> **よくある誤解**: 「M が立っていれば SLAAC はしない」は**違います**。
> SLAAC するかどうかを決めるのは **A フラグ**なので、**M と A が両方立っていれば両方動いて
> アドレスが 2 本以上付きます**。
> そもそも M/O は**ルータからの推奨でしかなく、従うかは OS 次第**です(Android は DHCPv6 を使いません)。

**ルータがもらう `/56` は別枠**で、**DHCPv6-PD** といいます。アドレスではなく**プレフィックスの委譲**です。

**教科書**: 第6章(p.127) / 7.1「SLAAC の流れ」(p.160) / 第8章「DHCPv6」(p.179) / 8.7(p.201)

## 第2部 日本の回線 — ここからは日本だけの話(11 分 / 4 枚)

### 2-1. 「ISP」と言っても 3 者います

**速度を決めているのは、お客様が契約している ISP ではありません。**

```
お客様の CPE  ──  NTT の網(NGN)  ──  VNE  ──  インターネット
  ルータ            フレッツ光         IPv6 を実際に流す
                   ここまでは NTT     事業者
                                          ↑
                                    ISP は契約・課金の窓口。
                                    VNE とは限らない
```

- **NGN** = NTT の網。フレッツ光の部分
- **VNE** = **NGN の上で IPv6(IPoE)接続を ISP に卸す事業者**。多くは IPv4 の運び方もセットで提供する
- **ISP** = お客様が契約している相手。裏で VNE を借りている

**「ISP を変えたのに速度が変わらない」の正体はこれです。**速度を決めるのは VNE 側だからです。

> **提案・見積の前に聞くこと**: 「ISP はどこですか」ではなく **「VNE はどこですか」** です。
> お客様は答えられないことが多いので、**契約書か、開通後に実測**で確かめます。

### 2-2. 分かれ道の 1 段目 — PPPoE か IPoE か

**速度の話はここで決まります。**

| | PPPoE(従来) | IPoE |
|---|---|---|
| 認証 | ID とパスワード | **なし**(回線に紐づく) |
| 網終端装置 | **通る** → 夜が遅い | **通らない** → 速い |
| IPv4 | そのまま流れる | **別途トンネルが要る** |

**両方同時に使えます。**「IPv6 は IPoE、IPv4 は PPPoE」という併用は実際によくある構成です。

> **切替当日の注意**: **PPPoE を落としてから IPoE に切り替えてください。**
> セッションが残っていると、原因の分からない不通になります。

**教科書**: 付録 A.3「IPv6 PPPoE と IPv6 IPoE」(p.443)

### 2-3. 分かれ道の 2 段目 — MAP-E か DS-Lite か

**ここは選べません。VNE が決めています。**

| | MAP-E | DS-Lite |
|---|---|---|
| **誰が NAT するか** | **CPE(お客様のルータ)** | **網側(AFTR という装置)** |
| CPE のやること | IPv4 を IPv6 で包む + アドレスとポートの計算 | ただ包むだけ |
| もらえる IPv4 | **他人と共有**。使えるポートが決まっている | 共有。**利用者側にアドレスが見えない** |
| ポート開放 | **割り当てられたポートなら可能** | **不可** |

**違いが一番出るのは「ポート開放できますか?」への答えです。**第3部で詳しくやります。

### 2-4. 実際のサービスはどれなのか(明日から使える表)

**商品名から方式を引けるようにしておいてください。**

| サービス名 | VNE / 提供 | 方式 | ポート開放 |
|---|---|---|---|
| **v6プラス** | JPIX(旧 JPNE) | **MAP-E** | 限定的(割り当てられたポートのみ) |
| **OCN バーチャルコネクト** | NTT ドコモビジネス(旧 NTT Com) | **MAP-E** | 限定的(割り当てられたポートのみ) |
| **BIGLOBE IPv6 オプション** | BIGLOBE 系 | **MAP-E** | 限定的(割り当てられたポートのみ) |
| **transix** | インターネットマルチフィード | **DS-Lite** | 不可(固定 IP 契約が別途必要) |
| **クロスパス(Xpass)** | アルテリア・ネットワークス | **DS-Lite** | 不可(固定 IP 契約が別途必要) |
| **v6 コネクト** | 朝日ネット | **DS-Lite** | 不可(固定 IP 契約が別途必要) |
| ソフトバンク光 IPv6 高速ハイブリッド | BBIX | **独自方式** | 光BBユニット前提。**今日の話の対象外** |

**使うときの注意が 3 つあります。**

1. **同じ ISP 名でもプランで VNE が違うことがあります。**光回線は再販が多いためです。
   机上で決めつけず、**開通後に実測**してください
2. **事業者名が変わっています。**JPNE → JPIX、NTT コミュニケーションズ → NTT ドコモビジネス
3. **方式が分かっても動くとは限りません。**CPE 側の対応が要ります。
   たとえば **Cisco 892FJ は古い IOS なので、そもそも MAP-E の機能を持っていません**。
   だから実機検証は DS-Lite で通しました(第4部)

## 第3部 IPv4 をどうやって運ぶか — 今日の本題(14 分 / 5 枚)

### 3-1. なぜわざわざ IPv4 を IPv6 に載せ替えるのか

**社内は IPv4 のままだからです。**

- IPoE で降りてくるのは **IPv6 だけ**です
- でも社内の機器も、行き先のサイトも、まだ IPv4 が要ります
- だから **IPv4 のパケットを IPv6 のパケットの中に入れて運びます**

宅配便で言えば、**IPv4 の荷物を IPv6 の箱に詰めて送る**イメージです。
受け取る側(網の中の装置)が箱を開けて、中の IPv4 を取り出してインターネットに流します。

この「箱の詰め方」の流儀が **MAP-E** と **DS-Lite** の 2 つです。

**教科書**: 第24章「IPv4 アドレス共有」(p.421〜) / 21.1「IPv4/IPv6 共存技術のバリエーション」(p.381)

---

### 3-2. DS-Lite — CPE は包むだけ、NAT は網がやる

**お客様のルータは何も考えず包んで送るだけです。**

```
[PC 192.168.1.10] → [CPE] → IPv6 の箱に詰める → [AFTR] → 箱を開けて NAT → インターネット
                                                    ↑
                                        ここで初めてグローバル IPv4 になる
```

- CPE 側は **NAT をしません**。トンネルの入口(B4)になるだけです
- **NAT は網側の AFTR という装置**がまとめてやります
- だから **CPE の負荷が軽く、設定も簡単**です

**代わりに、利用者側からはグローバル IPv4 アドレスが一切見えません。**
だから **ポート開放する手段がありません。**「ルータの設定でなんとかする」ができない構造です。

> **お客様への説明**: 「お客様のルータには外から見えるアドレスが無く、
> 通信は事業者の設備でまとめて変換されています。**設定でどうにかできる話ではありません。**
> 外から入る通信が必要なら、**固定 IP のオプション契約**が要ります」

**教科書**: 24.1「DS-Lite」(p.421) / 19.4「IPv4 アドレス共有技術の課題」(p.362)

---

### 3-3. MAP-E — IPv4 アドレスを他人と分け合う

**1 個の IPv4 アドレスを何人かで分け合い、使えるポート番号を分担します。**

- グローバル IPv4 アドレスは**他人と共有**します
- 代わりに、**「あなたはこのポート番号を使ってください」と範囲が決められます**
- どのアドレスとどのポートを使うかは、**降ってきた IPv6 プレフィックスから計算で決まります**

**うちの検証環境で実際に計算した例**(手計算した値と、CPE が自動計算した値が完全に一致しました):

| 項目 | 値 |
|---|---|
| 降ってきた IPv6 | `2001:db8:100a:500::/56` |
| 計算で出た共有 IPv4 | `198.51.100.10` |
| 使えるポートの塊 | 16 個ずつ × 15 塊 = **240 個** |
| 最初の塊 | `4176` 〜 `4191` |

**ポートは全部で 65536 個あるのに、使えるのは 240 個です。**

参考までに、実サービスでは **v6プラスが 240 個、OCN バーチャルコネクトが 1008 個**と言われています。

> **240 個は少ないです。**ブラウザは 1 つのタブで数十本の接続を張ります。
> **拠点の台数が多い、監視系がある、といった環境では足りなくなります。**
> 方式を決める前に**同時接続数を実測**してください。

**教科書**: 24.4「MAP-E、MAP-T、4rd」(p.425) / 24.3「A+P」(p.423)

### 3-4. 「ポート開放できますか?」— これで即答できます

**今日いちばん実務で効くページです。**

| 方式 | 答え方 |
|---|---|
| **PPPoE(従来)** | **できます。**今までどおりです |
| **MAP-E** | **割り当てられたポートなら できます。**ただし「80 番を開けて」は**たいてい無理**です |
| **DS-Lite** | **できません。**利用者側に手段がありません。固定 IP のオプション契約が必要です |

**なぜ MAP-E で「80 番」が無理なのか。**
使えるポートが計算で決まってしまうからです。**さっきの例だと 4176〜4191 のような番号しか使えません。**
80 番や 443 番は、たまたま自分の割り当てに入っていない限り使えません。

**先に聞いておくべきこと(切替前のヒアリング):**

- 外から入ってくる通信はありますか(**VPN、拠点間、監視、カメラ、リモートデスクトップ**)
- ある場合、**そのポート番号は何番ですか**
- **1 つでもあれば、DS-Lite と MAP-E は要注意です。**固定 IP か PPPoE 併用を検討します

> **これを切替後に発覚させると事故になります。**「速くなりました」の翌日に
> 「拠点間 VPN が張れません」と言われるのが最悪のパターンです。

### 3-5. MTU 1460 — 「Web は見えるのにファイルが落ちない」の正体

**箱に詰めると、その分だけ中身が小さくなります。**

- ふつうの Ethernet は **1500 バイト**まで運べます
- IPv6 の箱に詰めると **ヘッダ 40 バイト**を使うので、**中身は 1460 バイト**まで
- だから MAP-E も DS-Lite も **MTU は 1460** になります

**厄介なのは症状の出方です。**

| パケットの大きさ | 結果 | 見え方 |
|---|---|---|
| **小さい**(Web の表示、ping、DNS) | 通る | **「つながってる」と見える** |
| **大きい**(ファイル送信、メール添付) | 落ちる | **「たまに固まる」「大きい添付だけ失敗」** |

**だから「ping が通るから大丈夫」は通用しません。**

**直し方**は決まっています。CPE 側で **TCP が 1 回に運ぶデータの上限(MSS といいます)を書き換える**
(MSS clamp)だけです。

- Cisco なら `ip tcp adjust-mss 1420`
- OpenWrt ならファイアウォールの `mtu_fix`

**うちの実機検証では、この 1 行が無いと 5MB のファイルが落ちてきませんでした。**

**教科書**: 第10章「Path MTU Discovery」(p.215) / 第9章「IP フラグメンテーション」(p.205)

## 第4部 検証環境で実際に見たもの(12 分 / 6 枚)

### 4-1. なぜ検証環境を作ったのか

**「やってみたら動かない」を客先で起こさないためです。**

困っていたことは 3 つでした。

1. **組み合わせが多すぎる。**IPv6 の配り方 × IPv4 の運び方 × CPE の機種 × 構成
2. **本番の回線では試せない。**お客様の回線を壊すわけにいきません
3. **座学だけでは身に付かない。**RA も MAP-E も、**パケットを一度見れば腹に落ちます**

そこで、**自宅に NTT の網と VNE を丸ごと再現した検証環境**を作りました。
これから会社の VMware にも同じものを持ち込みます。

> **ここは 1 分で流してください。**次の構成図から本番です。

---

### 4-2. 何を再現しているのか

```
 [CPE]  ──  [NGN-SIM]  ──  [VNE]  ──  [INET-SIM]
OpenWrt      RA / DHCPv6-PD   MAP-E の受け口  Web と DNS
または         を配る          DS-Lite AFTR  模擬インターネット
実機 892FJ
     │
  [PPPoE 用の BRAS] ← 切替前の状態も再現できる
```

| 役 | 中身 | 何をしているか |
|---|---|---|
| **NGN-SIM** | Linux + radvd + Kea | NTT の網の代わり。RA を撒き、`/56` を委譲する |
| **VNE** | Linux + トンネル + nftables | MAP-E の受け口(BR)と DS-Lite の受け口(AFTR) |
| **INET-SIM** | Linux + nginx + dnsmasq | 模擬インターネット。**アクセス元のアドレスを表示してくれる** |
| **BRAS** | Linux + accel-ppp | PPPoE の受け口。**切替前の状態**を作れる |
| **CPE** | OpenWrt または実機 | お客様のルータ役 |

アドレスは全部**ドキュメント用に予約された範囲**を使っています
(`2001:db8::/32`、`198.51.100.0/24`、`203.0.113.0/24`)。**本物の誰かに迷惑をかけません。**

---

### 4-3. これで何ができるのか

**教科書を読んでも分からない「実際の挙動」を、壊しながら見られます。**

| できること | 具体的に |
|---|---|
| **切替の練習** | PPPoE から IPoE に切り替える手順を、本番と同じ順番で通せる |
| **方式の切り替え** | MAP-E と DS-Lite を行き来できる。RA 方式と PD 方式も切り替えられる |
| **パケットを見る** | RA、DHCPv6 のやり取り、トンネルの中身をキャプチャできる |
| **わざと壊す** | ポート枯渇、MTU の問題、DNS の遅延などを**再現できる** |
| **実機を繋げる** | 物理の Cisco 892FJ を収容して、本物の設定を投入できる |

**MAP-E の計算が合っているかも、ここで確かめました。**
手計算した共有 IPv4 `198.51.100.10` と 先頭ポート `4176〜4191`、MTU 1460 が、
CPE が自動計算した値と**完全に一致**しました。理屈どおりに出ます。

**わざと壊せるのが一番大きいです。**
本番で起きたら大事故になる現象を、**先に見て、直し方を手で覚えられます。**

---

### 4-4. 実機の Cisco 892FJ で DS-Lite を通した結果

**教科書の理屈が、実機と実際の Windows PC で、そのとおりになりました。**

物理の 892FJ を検証環境に繋ぎ、その配下に Windows PC を直結して測った値です。

| 確認したこと | 実測値 | 何を示しているか |
|---|---|---|
| **アクセス元のアドレス** | **`203.0.113.1`** | **網側で NAT された = DS-Lite が成立している** |
| ping | 0% 損失 / **TTL=62** | 相手の Linux は 64 で返す。手元に 62 で届いた = **ルータを 2 つ越えた** |
| MTU 1460 で送る | **通る** | トンネル分を引いた大きさが確保できている |
| MTU 1500 で送る | **CPE が「分割が必要」と返す** | **経路 MTU の通知が正常に動いている** |
| 5MB ダウンロード | **1.15 秒で完走** | **MSS clamp が効いている** |

> **一番大事なのは 1 行目です。**
> ping が通っただけでは「たまたま届いた」かもしれません。
> **「どのアドレスで外に出たか」を見て初めて、意図した経路を通ったと言えます。**

---

### 4-5. やってみて分かった「効かない直感」3 つ

**この 3 つは、教科書を読んだだけでは絶対に気づけませんでした。**

**① 「疎通した」は「正しい経路を通った」ではない**

検証スクリプトが全項目 PASS したのに、**実は CPE を通らずに出ていた**ことがありました。
`ping` も `curl` も成功するので、**見た目では絶対に分かりません。**

→ **必ず「出口のアドレス」を確認してください。**これだけが唯一の証拠です。

**② 設定が入ることと、動くことは別物**

Cisco の仮想ルータで MAP-E を試したとき、**設定は通り、確認コマンドも正しい値を返しました。**
それなのに**パケットが 1 つも流れませんでした。**転送エンジンが落ちていたのです。

→ **確認コマンドで終わらせず、パケットを流して測るところまでやってください。**

**③ 症状が 1 つでも、原因は 1 つとは限らない**

「ping は通るのに名前解決だけ死ぬ」という症状を追ったら、**独立した原因が 3 つ重なっていました。**
1 つ直しても直らないので、**「直したのに変わらない = 見当違い」と判断すると迷子になります。**

→ **1 つ直したら 1 つ確かめる。**まとめて直さないでください。

### 4-6. 会社でどう使うか

**同じものを会社の VMware に再現できるように、手順書一式を用意してあります。**

| 用意したもの | 中身 |
|---|---|

3. **切替当日の判断材料**(同じ症状を先に見ておく)

## まとめ(2 分 / 2 枚。残りは質疑に使ってください)

### 5-1. 3 行まとめと、明日から使うチェックリスト

**今日の話を 3 行にすると:**

1. **PPPoE が遅いから IPoE に変える。**アドレス枯渇の話ではありません
2. **社内は IPv4 のまま。**だから IPv4 を IPv6 に載せて運ぶ。それが MAP-E と DS-Lite です
3. **どちらになるかは選べません。**VNE が決めています

**案件で最初に確認する 5 つ:**

- [ ] **ひかり電話はありますか** → `/64` か `/56` かが決まる
- [ ] **VNE はどこですか** → 方式が決まる(ISP 名だけでは分かりません)
- [ ] **外から入ってくる通信はありますか** → VPN / 拠点間 / 監視 / カメラ
- [ ] **ある場合、ポート番号は何番ですか** → MAP-E でも開けられるかが決まる
- [ ] **同時接続数はどれくらいですか** → MAP-E のポート数(240 など)で足りるか

**切替後に必ず確認する 1 つ:**

- [ ] **どのアドレスで外に出たか。**疎通確認だけでは、経路が正しいことを示せません
