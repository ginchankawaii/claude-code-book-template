### 0-3. 話の全体を、宅配便でたとえます

**この 1 時間、ずっとこのたとえで通します。**

- **IPv6 の道** = 新しくできた広い高速道路。空いていて速い
- **IPv4 の荷物** = 社内の機器が出す荷物。**この高速道路をそのままでは走れない**
  - **IPv4 と IPv6 には互換性がなく、そのままでは直接やり取りできない**からです
- だから **IPv4 の荷物を IPv6 のトラックに積んで運びます**

**積み方が 2 通りあります。**それが **MAP-E** と **DS-Lite** です。

> **1 つだけ言い直させてください。**
> **速いのは IPv6 そのものではなく、IPoE という「通り方」です。**
> 混んでいる装置(網終端装置)を通らなくなるから速い。**この区別が後で効いてきます。**

**違いは第3部でやります。そこが今日の本題です。**
いまは「2 通りあるんだな」だけで大丈夫です。

### 0-4. なぜ IPv6 に変えるのか — 建前と本音を分けます

**お客様が今お金を出す理由は「IPv6 が欲しいから」ではなく「PPPoE が遅いから」です。**

教科書に書いてある理由(建前):

- IPv4 アドレスが足りなくなった。だから IPv6 に移行する
- 正しいのですが、**これは「きっかけ」であって、目の前の案件でハンコを押す理由ではありません**

現場でお金が動く理由(本音):

- **夜になると遅い。Web 会議が切れる。**この相談から始まります
- 原因は回線速度ではなく、**多くの場合「網終端装置」の混雑**です
  - 網終端装置 = **PPPoE の通信が全部集まってくる装置**。ここが混みます
- **IPoE** — 認証なしで回線に直接つなぐ方式です。仕組みは第2部でやります —
  **にするとこの装置を通らなくなる**ので速くなります

この区別ができると、次の質問に自信を持って答えられます。

> **「社内も IPv6 にするんですか?」**
> → **普通はしません。**LAN は IPv4 のままです。
> IPv6 にするとアドレスの設計をやり直し、ファイアウォールを見直し、アプリも検証し直しになります。
> 要件でない限りやりません。**IPv6 は「外を速く通るための道」**であって、社内を作り替える話ではないです。

ただし「将来も IPv6 化しない」とは言わないでください。**今回の案件でやらないだけ**です。

**教科書**: 第18章「IPv4 アドレス在庫枯渇とその解決策」(p.335) / 付録 A.3「IPv6 PPPoE と IPv6 IPoE」(p.443)

## 第1部 IPv6 そのもの — どこの国でも同じ話(7 分 / 6 枚)

### 1-1. IPv4 との違いは、現場では 5 つだけ

**全部覚える必要はありません。現場で効くのはこの 5 つです。**

| | IPv4 | IPv6 | 現場でどう効くか |
|---|---|---|---|
| **アドレスの長さ** | 32 ビット | 128 ビット | 枯渇しない。ただし覚えられないのでコピペ前提で作業する |
| **1 サブネット** | 好きに切れる | **`/64` が原則** | `/64` より細かく切ると自動設定が動かなくなる |
| **1 枚の NIC のアドレス** | ふつう 1 個 | **複数が当たり前** | 「アドレスが 2 つ付いている」は異常ではない |
| **相手の探し方** | ARP で探す | **ARP が無い**。ICMPv6 という仕組みで探す | **ICMPv6 を止めると通信が死にます。**FW 設計の事故で一番多い |
| **フラグメント** | 途中のルータも分割 | **送信元だけ** | MTU の問題が表に出やすい(第3部で扱います) |

**このうち一番大事なのは 4 つめです。**
「ICMP は ping だから止めていい」は IPv4 の感覚です。**IPv6 では ICMPv6 が住所解決そのもの**なので、
まとめて落とすと**通信ができなくなります**。

**教科書**: 2.10「IPv6 と IPv4 の違い」(p.51) / 第5章「ICMPv6」(p.115) / 第6章「近隣探索プロトコル」(p.127)

---

### 1-2. ICMPv6 は「まとめて落とす」をやってはいけません

**IPv4 の感覚で `deny icmp` を書くと、IPv6 では通信そのものが死にます。**

- IPv6 では**相手の MAC を調べるのも ICMPv6** です。ARP の代わりだからです
- 経路の途中で「そのサイズは無理」と教えるのも ICMPv6(第3部の MTU の話)

**最低限これは通してください。**

| 種類 | なぜ要るか |
|---|---|
| **エラー通知 4 種**<br>宛先到達不能(**1**)/ **パケット過大**(**2**)/ 時間超過(**3**)/ パラメータ異常(**4**) | **「パケット過大」を落とすと大きいファイルが送れなくなります** |
| **近隣探索**(**133〜137**)<br>相手を探す / アドレス重複を確かめる / ルータを探す | これが無いと**そもそも通信が始まりません** |
| **エコー要求・応答**(**128 / 129**) | 運用で要るので普通は通します |

```
permit icmp any any packet-too-big    ← Cisco ならこの形で 1 種類ずつ許可します
```

**最終確認は必ず RFC 4890 で。**上の番号は「まずこれを通す」の目安です。

**細かい番号は RFC 4890 と教科書 第5章「ICMPv6」(p.115)を見てください。**
**案件で ACL を書く前に、必ず一度は目を通すこと。**

> 「よく分からないから全部落とす」は IPv6 では成立しません。**ここは事故が最も多い場所です。**

---

### 1-3. アドレスの読み方 — ルールは 3 つだけ

**`/64` は決まりごとです。「なんとなく」ではありません。**

書き方のルールは 3 つだけです。

- 各ブロックの先頭の `0` は省ける → `2001:0db8:0000:0001` は `2001:db8:0:1`
- `0` が続くところは `::` で **1 回だけ**省ける → `2001:db8:0:0:0:0:0:1` は `2001:db8::1`
- URL に書くときは `[ ]` で囲む → `http://[2001:db8::1]/` (忘れると動きません)
  - なぜ囲むかというと、**ポート番号のコロンと区別できなくなるから**です(`[2001:db8::1]:80`)

---

### 1-4. なぜ `/64` で切るのか — 案件のヒアリングに直結します

**`/64` は決まりごとです。「なんとなく」ではありません。**

- 後ろの 64 ビットは「インタフェース ID」に使うと決まっています
- 端末が **MAC から作るか、ランダムに作る**ので、**下位 64 ビットは端末が勝手に決めます**
- だから **`/64` より細かく切ると**(たとえば `/80`)**自動設定が動きません**

実務での見え方はこうです。**ここが後で効いてきます。**

| ひかり電話 | 降りてくるもの | 呼び方 |
|---|---|---|
| **なし** | `/64` が 1 本だけ | RA 方式 |
| **あり** | `/56` が**まとめて貸し出される**(= `/64` が 256 本使える) | PD 方式(まとめ借り方式)。**= DHCPv6 の「プレフィックス委任」機能** |

> **「なんで電話の有無でアドレスの配られ方が変わるの?」**
> ひかり電話ありの回線は、**電話用の機器(HGW)にプレフィックスをまとめて配る提供形態**になっているためです。
> **技術的な必然ではなく、NTT の提供のしかたの違い**です。ここは深入りしません。

**この違いが効くのは「LAN をいくつのセグメントに切れるか」です。**
どちらでも MAP-E や DS-Lite は組めます。

**教科書**: 第3章「IPv6 アドレス体系」(p.67) / 7.7「グローバルアドレスの生成」(p.172) / 8.7「DHCPv6-PD」(p.201)

### 1-5. `fe80::` が必ず付いている理由 — ここが IPv4 と一番違う

**アドレスをもらう前に通信する必要があるからです。**

考えてみてください。

- アドレスをくれるのはルータです
- でもルータと話すにはアドレスが要ります
- **鶏と卵**です

だから IPv6 では、**NIC が上がった瞬間に自分だけで作れるアドレス**を必ず持ちます。それが `fe80::` です。

その結果こうなります。

- **RA も DHCPv6 も送信元は `fe80::`**。グローバルアドレスは後から付きます
- **既定ゲートウェイも `fe80::` で指します**。IPv4 のように `192.168.1.1` とは書きません
- **ルータ同士の経路のやり取りや隣接の会話も `fe80::`** が普通に使われます

**だから「グローバル IPv6 が付いていない = 壊れている」ではありません。**

実際、うちの検証環境では **VM に管理用の IP を振らず、`fe80::` だけで SSH して構築しました**。

> **使うときの注意 — ここが最初の関門です。**
> `fe80::` は「同じリンクの中だけ」のアドレスなので、**同じ番号が別の線にもあります。**
> だから **「どの線から出すか」を必ず一緒に書きます。**それが `%` のうしろです。
>
> `ping6 fe80::1%eth0`  ← eth0 という線から出す、という意味

**あわせて**: 1 枚の NIC に `fe80::` と グローバル が同時に付きます。これが「複数が当たり前」の中身です。

**教科書**: 3.5「リンクローカルユニキャストアドレス」(p.74) / 3.6「スコープのゾーン」(p.76) / 2.9(p.48)

### 1-6. アドレスはどうやって決まるのか

**ルータが「私がゲートウェイだよ」と自分から言いに来ます。ここが IPv4 と一番違います。**

流れはこれだけです。

1. 端末が **「ルータいますか」** と聞く
2. ルータが **「私がいます。住所の前半はこれです」** と答える ← これが **RA**
3. 端末が **住所の後半を自分で作って** アドレスを完成させる ← これを **自動設定** と呼びます

**IPv4 の DHCP と何が違うのか。**

- IPv4 … 端末が聞きに行って、サーバが住所を**まるごと**渡す
- IPv6 … **ルータが前半だけ配って、後半は端末が自分で決める**

> **よくある誤解**: **「DHCPv6 を併用すると、自分で作るほうは止まる」→ 止まりません。**
> 両方が同時に動きます。止める / 止めないを決めるのは**別のフラグ**です。
> だから「アドレスが 2 つ以上付いている」のは**正常**です。
> 住所を配る係(DHCPv6)を併用しても、**自分で作るのは止まりません。**両方動きます。

**ルータがもらう `/56` は別の話**で、**アドレスではなく「住所の前半」をまとめて借りる**ものです。

**教科書**: 第6章(p.127) / 7.1「SLAAC の流れ」(p.160) / 第8章「DHCPv6」(p.179) / 8.7(p.201)

> **【話す人向けの補足。スライドには出しません】**
> ルータは RA の中で 3 つのお願いをしています。仕様上は **A / M / O フラグ**という名前です。
>
> - **A** =「自分で作っていいよ」 ← 自分で作るかどうかを決めるのはこれ
> - **M** =「配る係(DHCPv6)からももらってね」
> - **O** =「DNS などの情報だけ 配る係からもらってね」
>
> 「M が立っていれば自分で作るのは止まる」と思われがちですが**違います。**決めるのは A です。
> そもそもこれは**ルータからのお願いでしかなく、従うかは端末次第**です
> (Android は DHCPv6 を使いません)。質問されたらこう答えてください。

## 第2部 日本の回線 — ここからは日本だけの話(11 分 / 7 枚)

### 2-1. 「ISP」と言っても 3 者います

**速度を決めているのは、お客様が契約している ISP ではありません。**

```
お客様の CPE  ──  NTT の網(NGN)  ──  VNE  ──  インターネット
  ルータ            フレッツ光         IPv6 を実際に流す
                   ここまでは NTT     事業者
                                          ↑
                                    ISP は契約・課金の窓口。
                                    VNE とは限らない
```

- **NGN** = NTT の網。フレッツ光の部分
- **VNE** = **NGN の上で IPv6(IPoE)接続を ISP に卸す事業者**。多くは IPv4 の運び方もセットで提供する
- **ISP** = お客様が契約している相手。裏で VNE を借りている

**「ISP を変えたのに速度が変わらない」の正体はこれです。**速度を決めるのは VNE 側だからです。

> **提案・見積の前に聞くこと**: 「ISP はどこですか」ではなく **「VNE はどこですか」** です。
> お客様は答えられないことが多いので、**契約書か、開通後に実測**で確かめます。

### 2-2. 分かれ道の 1 段目 — PPPoE か IPoE か

**速度の話はここで決まります。**

| | PPPoE(従来) | IPoE |
|---|---|---|
| 認証 | ID とパスワード | **なし**(回線に紐づく) |
| 網終端装置(通信が集まる装置) | **通る** → 夜が遅い | **通らない** → 速い |
| IPv4 | そのまま流れる | **別途「箱に詰めて運ぶ仕組み」が要る** |

**両方同時に使えます。**「IPv6 は IPoE、IPv4 は PPPoE」という併用は実際によくある構成です。

> **PPPoE に戻す(残す)ときの注意**
> PPPoE を電源断などで乱暴に切ると、**網側にセッションが 1 分ほど残り、その間は再接続できません。**
> また再接続すると**払い出されるアドレスが変わることがあります**(固定 IP 前提の設定が壊れます)。
> 切替は **「PPPoE を正常に切断 → IPoE を確認 → 戻すときは 1 分待つ」** の順で。

**教科書**: 付録 A.3「IPv6 PPPoE と IPv6 IPoE」(p.443)

### 2-3. 分かれ道の 2 段目 — MAP-E か DS-Lite か

**ここは選べません。VNE が決めています。**

冒頭の宅配便のたとえで言うと、こうです。

| | **MAP-E** | **DS-Lite** |
|---|---|---|
| 誰が荷物を積むか | お客様のルータ | お客様のルータ(同じ) |
| **誰が仕分けするか** | **お客様のルータが自分でやる** | **高速の出口にいる業者がやる** |
| その結果 | **使える伝票番号が、あらかじめ決まっている** | **伝票が自分では見えない** |

**この「伝票」の話が、第3部で「ポート開放できますか?」の答えになります。**

| | MAP-E | DS-Lite |
|---|---|---|
| **誰が変換するか** | **お客様のルータ** | **網側の装置**(AFTR と呼びます) |
| CPE のやること | IPv4 を IPv6 で包む + アドレスとポートの計算 | ただ包むだけ |
| もらえる IPv4 | **他人と共有**。使えるポートが決まっている | 共有。**利用者側にアドレスが見えない** |
| ポート開放 | **割り当てられたポートなら可能** | **不可** |

**違いが一番出るのは「ポート開放できますか?」への答えです。**第3部で詳しくやります。

### 2-4. 実際のサービスはどれなのか(明日から使える表)

**商品名から方式を引けるようにしておいてください。**

## 第3部 IPv4 をどうやって運ぶか — 今日の本題(19 分 / 11 枚)

### 3-1. なぜわざわざ IPv4 を IPv6 に載せ替えるのか

**社内は IPv4 のままだからです。**

- IPoE で降りてくるのは **IPv6 だけ**です
- でも社内の機器も、行き先のサイトも、まだ IPv4 が要ります
- だから **IPv4 のパケットを IPv6 のパケットの中に入れて運びます**

宅配便で言えば、**IPv4 の荷物を IPv6 の箱に詰めて送る**イメージです。
受け取る側(網の中の装置)が箱を開けて、中の IPv4 を取り出してインターネットに流します。

この「箱の詰め方」の流儀が **MAP-E** と **DS-Lite** の 2 つです。

**教科書**: 第24章「IPv4/IPv6 共存技術の運用形態」24.1〜24.4(p.421〜) / 第21章「IPv4/IPv6 共存技術の分類」21.1(p.381)

---

### 3-2. DS-Lite — お客様のルータは包むだけ、変換は網がやる

**お客様のルータは何も考えず包んで送るだけです。**

宅配便のたとえで「**出口の業者が仕分けする**」と言ったのが、これです。

```
[PC] → [お客様のルータ] IPv6 の箱に詰める → [網側の装置] 箱を開けて変換 → インターネット
                                                    ↑
                                        ここで初めてグローバル IPv4 になる
```

- お客様のルータは **アドレスの書き換え(NAT)をしません**。ただの入口になるだけです
- **変換は網側の装置(AFTR)**がまとめてやります
- だから **お客様のルータの負荷が軽く、設定も簡単**です

**代わりに、利用者側からはグローバル IPv4 アドレスが一切見えません。**
だから **ポート開放する手段がありません。**「ルータの設定でなんとかする」ができない構造です。

> **お客様への説明**: 「お客様のルータには外から見えるアドレスが無く、
> 通信は事業者の設備でまとめて変換されています。**設定でどうにかできる話ではありません。**
> 外から入る通信が必要なら、**固定 IP のオプション契約**が要ります」

**教科書**: 24.1「DS-Lite」(p.421) / 19.4「IPv4 アドレス共有技術の課題」(p.362)

---

### 3-3. MAP-E — IPv4 アドレスを他人と分け合う

**その前に、NAT の話を 2 行だけ。ここが入っていないと、この先が全部呪文になります。**

- **NAT は「アドレス + ポート番号」の組で通信を見分けています。**アドレスを書き換えているだけではありません
- **だからポート番号を分担すれば、1 個のアドレスを何人かで共有できます。**MAP-E はこれを事業者と利用者の間でやる仕組みです

**1 個の IPv4 アドレスを何人かで分け合い、使えるポート番号を分担します。**

- グローバル IPv4 アドレスは**他人と共有**します
- 代わりに、**「あなたはこのポート番号を使ってください」と範囲が決められます**
- どのアドレスとどのポートを使うかは、**降ってきた IPv6 の**住所の前半(プレフィックス)**から計算で決まります**

### 「計算で決まる」って、どういうこと?

**式は覚えなくていいです。**知っておくべきは次の 3 つだけです。

1. 降ってきた IPv6 の**決められた位置のビット**が、
   **共有 IPv4 アドレスの一部**と**自分のポート番号の素**になります
2. **計算するのは CPE です。**人間が計算する場面はありません
3. だから **「計算で一意に決まる = こちらでは選べない」**。ここだけ覚えてください

> 「なんで 80 番が使えないの?」の答えもここです。
> **ポート番号は計算の結果として決まる**ので、**ウェルノウンポート(0〜1023)は
> どのサービスでも、どの人にも配られません。**(v6プラスのようにさらに広く
> **0〜4095 を除外**するサービスもあります)
> **選べないから 80 番が来ない**、という順番です。

**うちの検証環境で実際に計算した例**(手計算した値と、CPE が自動計算した値が完全に一致しました):

| 項目 | 値 |
|---|---|
| 降ってきた IPv6 | `2001:db8:100a:500::/56` |
| 計算で出た共有 IPv4 | `198.51.100.10` |
| 使えるポート | **240 個**(連続ではなく、とびとびの番号) |
| 最初の塊 | `4176` 〜 `4191` |

**ポートは全部で 65536 個あるのに、使えるのは 240 個です。**

### ここで話が 2 つに分かれます(混同しやすいので注意)

| | 出ていく通信(Web を見る) | 入ってくる通信(ポート開放) |
|---|---|---|
| 240 個をどう使うか | **使い回す** | **この中からしか選べない** |
| 何が問題になるか | **足りるかどうか** | **番号が合うかどうか** |

**次のページは「入ってくる通信」の話です。**

参考までに、実サービスでは **v6プラスが 240 個、OCN バーチャルコネクトが 1008 個**と言われています。

> **240 個は少ないです。**ブラウザは 1 つのタブで数十本の接続を張ります。
> **拠点の台数が多い、監視系がある、といった環境では足りなくなります。**
> 方式を決める前に**同時接続数を実測**してください。

#### 「同時接続数を実測」って、どうやるのか

**既設ルータで NAT のテーブル数を数えます。**

```
show ip nat translations | count      ← Cisco の場合。行数を数える
```

**業務時間帯に何回か測ってください。**昼休みと夕方でまったく違います。

#### 測ったあと、どう判断するか

**目安の数字は出せません。**台数・業務アプリ・監視の有無で変わるので、他社の数字は当てになりません。
代わりに **「判断の型」** を置いておきます。

> **ピークの実測値 × 安全率 2 倍** が **割当ポート数**を超えたら、**MAP-E 単独は避ける**
>
> 例: ピーク 180 本 × 2 = 360 > 240 → **固定 IP か PPPoE 併用に倒す**

**安全率 2 倍はこの資料での仮置きです。**実績が貯まるまでの暫定なので、
**案件を何本か通したら社内で決め直してください。**
「測れるのに判断できない」状態をなくすための型です。

**足りないと分かったら**: MAP-E でもポート数の多い VNE があります(OCN バーチャルコネクトは 1008)。
ただし **VNE は選べないことが多い**ので、実際は固定 IP か PPPoE 併用の検討になります。

**教科書**: 24.4「MAP-E、MAP-T、4rd」(p.425) / 24.3「A+P」(p.423)

### 3-4. 「ポート開放できますか?」— これで即答できます

**今日いちばん実務で効くページです。**

> **そもそもポート開放とは**
> **「外から来た通信を、社内のこの機械に通してください」というルータへの指示**です。
> カメラの遠隔閲覧、拠点間 VPN、リモートデスクトップが典型例です。

2-3 で言った「**使える伝票番号**」「**伝票が見えない**」の話が、ここに出てきます。

| 方式 | 答え方 |
|---|---|
| **PPPoE(従来)** | **できます。**今までどおりです |
| **MAP-E** | **割り当てられたポートなら できます。**ただし「80 番を開けて」は**たいてい無理**です |
| **DS-Lite** | **できません。**利用者側に手段がありません。固定 IP のオプション契約が必要です |

**なぜ MAP-E で「80 番」が無理なのか。**
使えるポートが計算で決まってしまうからです。**さっきの例だと 4176〜4191 のような番号しか使えません。**
**80 番や 443 番のような若い番号は、仕組みの上でそもそも配られません。**だから無理です。

> **「カメラの 80 番はどうするの?」と聞かれたら**
> MAP-E では**外側の番号は割り当てられたポートから選び、社内側の 80 番へはルータが読み替えます。**
> つまり「外から `4176` 番で来てもらって、社内のカメラの 80 番に渡す」という形にはできます。
> **外側で 80 番を名乗ることはできない**、というのが制約です。

**先に聞いておくべきこと(切替前のヒアリング):**

- 外から入ってくる通信はありますか(**VPN、拠点間、監視、カメラ、リモートデスクトップ**)
- ある場合、**そのポート番号は何番ですか**
- **1 つでもあれば、DS-Lite と MAP-E は要注意です。**固定 IP か PPPoE 併用を検討します

> **これを切替後に発覚させると事故になります。**「速くなりました」の翌日に
> 「拠点間 VPN が張れません」と言われるのが最悪のパターンです。

### 3-5. 拠点間 VPN はどうなるのか(法人案件で一番聞かれます)

**結論: 少なくとも片端に固定 IP が要ります。**

VPN は「**外から入ってくる通信**」の代表です。「ポート開放」のページがそのまま効きます。

| | こちらから張りに行く(発信側) | 相手から張られる(応答側・待ち受け) |
|---|---|---|
| **PPPoE** | ○ | ○ |
| **MAP-E** | **張れます**(条件は下記) | **不可**。決まった番号(500)で待てません |
| **DS-Lite** | **張れます**(条件は下記) | **不可**。そもそも手段がありません |
| **固定 IP オプション** | ○ | ○ |

> **「張れます」の条件**: **両端が NAT 越え(NAT-T)に対応していること**です。
> MAP-E も DS-Lite も途中でアドレスとポートを書き換えるので、
> **NAT-T を使わない設定(ESP をそのまま流す)だと張れません。**
> 古い機器や、対向が NAT-T を切っている場合は要注意です。**お客様には「たいてい」と言わないこと。**

**そもそも `UDP 500` / `4500` とは。**
VPN が**最初の握手に使うと決まっている番号**です。電話でいう代表番号のようなもので、
**この番号で待っていないと相手からの呼び出しを受けられません。**

**なぜ待ち受けができないのか。**
**`500` はウェルノウンポート(0〜1023)なので、MAP-E では誰にも配られません。**
自分が使えるポートは計算で決まるので、**そこに 500 は入りません。**
DS-Lite は外から見えるアドレス自体がありません。**「80 番が使えない」のと同じ理由**です。

> **`4500` の扱いはサービスによります。**除外されるのは「先頭のブロック」で、
> その広さがサービスごとに違うためです(v6プラスは 0〜4095 なので 4500 も配られ得ますが、
> **どのポートが自分に割り当たるかは選べない**ので、結論は同じです)。
> **待ち受け不可の根拠は `500` だけで足ります。**

### だからこう提案します

- **拠点 ↔ データセンタ / クラウド** の形なら、**センタ側を固定 IP** にして、
  **拠点からは発信のみ**にすれば成立します。これが一番よくある形です
- **拠点 ↔ 拠点** を直接張るなら、**どちらか片方は固定 IP**が要ります
- **両端とも MAP-E / DS-Lite** にすると、**どちらも待ち受けできないので張れません**

> **ここは机上の整理です。**うちの検証環境ではまだ VPN を張って測っていません。
> **案件で使う前に必ず実機で確かめてください。**(検証項目として積んであります)

**ヒアリングで必ず聞くこと**: 「**VPN はどちらから張っていますか**」。
「どちらからでもいい」と言われたら、**発信の向きを固定できるかどうか**を確認してください。

### 3-6. MTU 1460 — 「Web は見えるのにファイルが落ちない」の正体

**箱に詰めると、その分だけ中身が小さくなります。**

- ふつうの Ethernet は **1500 バイト**まで運べます
- IPv6 の箱に詰めると **ヘッダ 40 バイト**を使うので、**中身は 1460 バイト**まで
- だから MAP-E も DS-Lite も **MTU は 1460** になります

**厄介なのは症状の出方です。**

| パケットの大きさ | 結果 | 見え方 |
|---|---|---|
| **小さい**(Web の表示、ping、DNS) | 通る | **「つながってる」と見える** |
| **大きい**(ファイル送信、メール添付) | 落ちる | **「たまに固まる」「大きい添付だけ失敗」** |

**だから「ping が通るから大丈夫」は通用しません。**

**直し方**は決まっています(**TCP の話です**)。**ルータに 1 行入れるだけ**です。
「1 回に運ぶ荷物をこれ以上大きくするな」と、あらかじめ上限を教えてやります。

- **なぜ 1420 なのか**: 箱に入る大きさ 1460 から、TCP と IP のヘッダ 40 を引いた数字です
  - **タイトルの 1460 とコマンドの 1420 は別物**なので、打ち間違えないでください
  - **40 を 2 回引きますが、中身は別物です。**偶然同じ数字なので混乱しないでください

| 引き算 | 引くもの | 結果 |
|---|---|---|
| 1500 − 40 | **IPv6 のヘッダ**(箱の厚み) | **MTU 1460** = 箱に入る大きさ |
| 1460 − 40 | **TCP のヘッダ 20 + IP のヘッダ 20** | **MSS 1420** = 中身のデータの上限 |
- Cisco なら `ip tcp adjust-mss 1420` の 1 行
- OpenWrt ならファイアウォールの `mtu_fix`

**うちの実機検証では、この 1 行が無いと 5MB のファイルが落ちてきませんでした。**

> **第4部でまた出てきます。**「あの 1 行」と言ったらこれのことです。

**教科書**: 第10章「Path MTU Discovery」(p.215) / 第9章「IP フラグメンテーション」(p.205)

### 4-2. 何を再現しているのか

```
 [お客様のルータ] ── [NTT の網の代わり] ── [受け口] ── [模擬インターネット]
   OpenWrt            住所を配る役          荷物を降ろす    Web と DNS
   または実機 892FJ    (RA と DHCPv6)      (MAP-E/DS-Lite)
        │
  [PPPoE の受け口] ← 切替前の状態も再現できる
```

| 役 | 中身 | 何をしているか |
|---|---|---|
| **NGN-SIM** | Linux | **NTT の網の代わり。**住所を配る役 |
| **VNE** | Linux + トンネル | **MAP-E と DS-Lite の受け口**。トラックの荷物を降ろす側 |
| **INET-SIM** | Linux | **模擬インターネット。アクセス元のアドレスを表示してくれる** |
| **BRAS** | Linux | **PPPoE の受け口。切替前の状態**を作れる |
| **CPE** | OpenWrt または実機 | お客様のルータ役 |

アドレスは全部**ドキュメント用に予約された範囲**を使っています
(`2001:db8::/32`、`198.51.100.0/24`、`203.0.113.0/24`)。**本物の誰かに迷惑をかけません。**

### 4-3. これで何ができるのか

**教科書を読んでも分からない「実際の挙動」を、壊しながら見られます。**

| できること | 具体的に |
|---|---|
| **切替の練習** | PPPoE から IPoE に切り替える手順を、本番と同じ順番で通せる |
| **方式の切り替え** | MAP-E と DS-Lite を行き来できる。RA 方式と PD 方式(ひかり電話ありの「まとめ借り」)も切り替えられる |
| **パケットを見る** | RA、DHCPv6 のやり取り、トンネルの中身をキャプチャできる |
| **わざと壊す** | ポート枯渇、MTU の問題、DNS の遅延などを**再現できる** |
| **実機を繋げる** | 物理の Cisco 892FJ を繋ぎ込んで、本物の設定を投入できる |

**MAP-E の計算が合っているかも、ここで確かめました。**
手計算した共有 IPv4 `198.51.100.10` と 先頭ポート `4176〜4191`、MTU 1460 が、
CPE が自動計算した値と**完全に一致**しました。理屈どおりに出ます。

**わざと壊せるのが一番大きいです。**
本番で起きたら大事故になる現象を、**先に見て、直し方を手で覚えられます。**

### 4-4. 実機の Cisco 892FJ で DS-Lite を通した結果

**教科書の理屈が、実機と実際の Windows PC で、そのとおりになりました。**

物理の 892FJ を検証環境に繋ぎ、その配下に Windows PC を直結して測った値です。

| 確認したこと | 実測値 | 何を示しているか |
|---|---|---|
| **アクセス元のアドレス** | **`203.0.113.1`** | **網側で NAT された = DS-Lite が成立している** |
| ping | 0% 損失 / **TTL=62** | 相手の Linux は 64 で返す。手元に 62 で届いた = **ルータを 2 つ越えた** |
| MTU 1460 で送る | **通る** | トンネル分を引いた大きさが確保できている |
| MTU 1500 で送る | **CPE が「分割が必要」と返す** | **経路 MTU の通知が正常に動いている** |
| 5MB ダウンロード | **1.15 秒で完走** | **MTU のページで入れた「あの 1 行」が効いている** |

> **一番大事なのは 1 行目です。**
> ping が通っただけでは「たまたま届いた」かもしれません。
> **「どのアドレスで外に出たか」を見て初めて、意図した経路を通ったと言えます。**

### 4-5. やってみて分かった「効かない直感」3 つ

**この 3 つは、教科書を読んだだけでは絶対に気づけませんでした。**

**① 「疎通した」は「正しい経路を通った」ではない**

検証スクリプトが**全項目 PASS したのに、網側の変換が効いていなかった**ことがありました。
構成を誤った DS-Lite で `PASS=10` が出たのに、**出口を見たらクライアントの私設アドレスのまま**
外に出ていました。**トンネル自体は設計どおり通っていた**のに、その先で NAT が当たっていなかったのです。
`ping` も `curl` も成功するので、**見た目では絶対に分かりません。**

→ **必ず「出口のアドレス」を確認してください。**これだけが唯一の証拠です。

**② 設定が入ることと、動くことは別物**

Cisco の仮想ルータで MAP-E を試したとき、**設定は通り、確認コマンドも正しい値を返しました。**
それなのに**パケットが 1 つも流れませんでした。**転送エンジンが落ちていたのです。

→ **確認コマンドで終わらせず、パケットを流して測るところまでやってください。**

> **これは仮想ルータでの話です。**実機の Cisco で同じことが起きるかは確かめていません。

**③ 症状が 1 つでも、原因は 1 つとは限らない**

「ping は通るのに名前解決だけ死ぬ」という症状を追ったら、**独立した原因が 3 つ重なっていました。**
1 つ直しても直らないので、**「直したのに変わらない = 見当違い」と判断すると迷子になります。**

→ **1 つ直したら 1 つ確かめる。**まとめて直さないでください。

### 5-1. 3 行まとめと、明日から使うチェックリスト

**今日の話を 3 行にすると:**

1. **PPPoE が遅いから IPoE に変える。**アドレス枯渇の話ではありません
2. **社内は IPv4 のまま。**だから IPv4 を IPv6 に載せて運ぶ。それが MAP-E と DS-Lite です
3. **どちらになるかは選べません。**VNE が決めています

**案件で最初に確認する 5 つ:**

- [ ] **ひかり電話はありますか** → `/64` か `/56` かが決まる
- [ ] **VNE はどこですか** → 方式が決まる(ISP 名だけでは分かりません)
- [ ] **外から入ってくる通信はありますか** → VPN / 拠点間 / 監視 / カメラ
- [ ] **ある場合、ポート番号は何番ですか** → MAP-E でも開けられるかが決まる
- [ ] **同時接続数はどれくらいですか** → MAP-E のポート数(240 など)で足りるか

**切替後に必ず確認する 1 つ:**

- [ ] **どのアドレスで外に出たか。**疎通確認だけでは、経路が正しいことを示せません

## 想定問答(配布資料にだけ載せます。投影はしません)

**質疑 5 分で出そうなものです。ここだけ先に読んでおいてください。**

**Q1. 「IPv6 にすれば NAT が無くなって、ポート開放も要らなくなるのでは?」**

なりません。**社内は IPv4 のままだから**です。社内から見た世界は今日と何も変わらず、
外に出るところで IPv6 に載せ替えているだけです。社内も IPv6 にすれば話は変わりますが、
それはアドレス設計のやり直しになるので、今回の案件ではやりません(0-4)。

**Q2. 「PPPoE を併用すれば全部解決では? なぜみんなそうしないのか」**

解決はします。実際よくやります。ただし **PPPoE を使う通信は結局遅いまま**です。
「速くしたい」が動機なのに、外から入る通信だけ遅い経路に残すことになります。
運用も二重になります。**やるなら「何を PPPoE に残すか」を決めてから**にしてください。

**Q3. 「固定 IP のオプションって、具体的に何をどこに申し込むのか」**

契約している **ISP に申し込みます**(VNE に直接ではありません)。
サービス名も料金も ISP ごとに違うので、**その場で答えず持ち帰ってください。**
「固定 IP のオプションがあるかどうかを確認します」で十分です。

**Q4. 「家庭では 240 個で困らないのに、なぜ会社だと困るのか」**

同時に使う数が違うからです。家庭は数台ですが、拠点だと PC が数十台あり、
そこに監視やカメラが加わります。**240 個は使い回しているので、
一度に張る接続の数が多いと足りなくなります**。

**Q5. 「MAP-E か DS-Lite か、開通前に机上で確定できないのか」**

**VNE が分かれば方式は決まります**(2-4 の表)。ただし
**同じ ISP 名でもプランで VNE が違うことがある**ので、
最後は開通後に実測で確かめてください。確かめ方は「どのアドレスで外に出たか」です(4-4)。

**Q6. 「うちのルータは対応していますか」**

機種によります。**Cisco 892FJ は古い IOS なので MAP-E に対応していません**(DS-Lite は可)。
市販ルータは対応表が各社から出ています。**方式が分かってから機種を確認する**順番でお願いします。

**Q7. 「NAT が無くなると、外から丸見えになって危なくないですか」**

**いい質問ですが、前提が 2 つずれています。**

まず **NAT はセキュリティ機能ではありません。**「たまたま外から入れない」状態を副作用として
作っていただけで、守っているのは**ファイアウォール**です。

そのうえで今回の案件では、**社内は IPv4 のままで NAT も残ります。**
IPv6 を末端まで通す構成にすると「外から直接届く」形にはなりますが、
その場合も**ファイアウォールで止めるのが本来のやり方**です。
**「NAT があるから安全」だったのではなく、「NAT があるので気づかずに済んでいた」だけ**です。

**Q8. 「DS-Lite なら同時接続数は無制限ですか」**

**無制限ではありません。**MAP-E は「240 個」のように数がはっきり見えるのに対し、
DS-Lite は**網側の装置(AFTR)の上限**なので**利用者側から見えないだけ**です。
**同時接続の多い拠点(監視系・多数の端末)では、DS-Lite でも事前に事業者へ確認してください。**
「MAP-E は制限あり、DS-Lite は無制限」と提案書に書かないこと。
